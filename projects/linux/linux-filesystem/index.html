Linux Filesystem and Directory Structure

• local lab
Summary

This topic explores how Linux organizes files using a hierarchical filesystem structure starting from the root directory. It explains the purpose of major system directories, different Linux file types, the difference between hard and symbolic links, and how filesystems are mounted to storage devices. It also introduces inode structures that store file metadata. Understanding these concepts helps administrators and DevOps engineers manage storage, configuration files, and system resources effectively.

Filesystem and Directory Structure

Goal: Understand the Linux Filesystem Hierarchy Standard (FHS), why it exists, and how Linux organizes system files and directories across the operating system.

  1. What is a Filesystem?
    A filesystem is the logical structure used by an operating system to store, organize, manage, and retrieve data on storage devices such as hard drives, SSDs, USB drives, and network storage. The filesystem acts as the interface between the operating system and physical storage hardware. It defines how files are stored on disk, how directories are organized, and how metadata about files is managed.
    A filesystem controls several key aspects:
    • File Naming – defines rules for naming files and directories.
    • Directory Organization – structures files in hierarchical folders.
    • Permissions and Ownership – controls who can read, write, or execute files.
    • Space Allocation – determines how disk blocks are assigned to files.
    • Metadata Management – stores file attributes such as timestamps and ownership.
    Linux supports multiple filesystem types, including:
    • ext4 – the most common Linux filesystem
    • xfs – used in enterprise systems
    • btrfs – advanced filesystem with snapshots
    • fat32 / ntfs – used for compatibility with Windows
    Unlike Windows, which separates disks using drive letters like C:\ and D:\, Linux uses a single unified filesystem tree starting from the root directory /.
  2. The Root Directory (/)
    The root directory (/) is the top-level directory in the Linux filesystem hierarchy. Every file and directory on the system exists somewhere beneath this root.
    Example structure:
                      /
                  ├── bin
                  ├── boot
                  ├── dev
                  ├── etc
                  ├── home
                  ├── lib
                  ├── media
                  ├── mnt
                  ├── opt
                  ├── proc
                  ├── root
                  ├── run
                  ├── sbin
                  ├── tmp
                  ├── usr
                  └── var
    Important characteristics of the root directory:
    • It is the starting point of the entire filesystem hierarchy.
    • All mounted devices are attached somewhere under this directory.
    • System-critical directories are located directly under root.
    For example:
    • The operating system configuration lives in /etc
    • User files are stored in /home
    • System logs are stored in /var/log
    Because everything in Linux starts from the root directory, administrators must carefully manage access and permissions.
  3. Filesystem Hierarchy Standard (FHS)
    The Filesystem Hierarchy Standard (FHS) is a specification that defines how directories and files should be organized in Linux systems. It was created to ensure consistency across different Linux distributions such as Ubuntu, Debian, Fedora, and Red Hat.
    The main goals of FHS are:
    • Provide a consistent directory structure
    • Make software installation predictable
    • Allow administrators to easily locate system files
    • Ensure compatibility between distributions
    For example, because of FHS:
    • System configuration files are always located in /etc
    • System logs are always located in /var/log
    • User home directories are stored in /home
    This standard makes it easier to manage Linux servers, especially in large infrastructure environments.
  4. 📁 /bin – Essential User Binaries
    The /bin directory contains essential command line programs required for basic system operation.
    Examples include:
    • ls
    • cp
    • mv
    • cat
    • mkdir
    These commands must be available even when the system is running in minimal or recovery mode.
  5. 📁 /boot – Boot Files
    The /boot directory contains the files required for starting the Linux operating system. These files are used by the bootloader during system startup.
    • Stores the Linux kernel image.
    • Contains bootloader configuration files.
    • Includes initial RAM filesystem (initramfs).
    Example files:
                  /boot/vmlinuz
              /boot/initramfs
              /boot/grub/grub.cfg
    The bootloader (usually GRUB) reads these files to load the kernel and start the operating system.
  6. 📁 /dev – Device Files
    The /dev directory contains files representing hardware devices.
    Examples: 
                          /dev/sda
                      /dev/sda1
                      /dev/null
                      /dev/random
    Linux treats hardware devices as files that can be accessed by applications and system utilities.
  7. 📁 /etc – System Configuration
    The /etc directory contains configuration files for the entire system.
    Examples include: 
                          /etc/passwd
                      /etc/group
                      /etc/fstab
                      /etc/ssh/sshd_config
    These files define system behavior, service settings, authentication data, and networking configuration.
  8. 📁 /home – User Home Directories
    The /home directory stores personal directories for each user. Example: 
                      /home/santhosh
                  /home/devops
                  /home/user1
    Each user directory stores personal files, documents, scripts, and configuration settings.
  9. 📁 /lib
    The /lib directory contains essential shared libraries needed by programs in /bin and /sbin.
    • Stores shared libraries required by core system binaries.
    • Contains kernel modules.
    • Required for basic system functionality.
    Example paths:
                  /lib/x86_64-linux-gnu/
              /lib/modules/
    Shared libraries allow multiple programs to use the same code, reducing duplication and saving system resources.
  10. 📁 /mnt and 📁 /media – Mount Points
    These directories are used to attach external storage devices. /mnt is commonly used for temporary mounts. /media is used for removable devices such as USB drives or DVDs.
  11. 📁 /opt – Optional Software
    The /opt directory is used for installing third-party applications that are not part of the default operating system packages.
    Example: 
                          /opt/google
                      /opt/custom-app
  12. 📁 /proc – Process Information
    The /proc directory is a virtual filesystem that provides information about system processes and kernel data.
    Examples: 
                          /proc/cpuinfo
                      /proc/meminfo
                      /proc/uptime
    Each running process also has a directory inside /proc.
  13. 📁 /root
    The /root directory is the home directory of the root user (system administrator).
    • Used for administrative tasks.
    • Contains root user's configuration files.
    • Separate from normal user directories.
    Example files:
                          /root/.bashrc
                      /root/scripts
    This directory is not the same as the system root directory /. It specifically belongs to the root user.
  14. 📁 /run
    The /run directory stores runtime system information that is created during system boot.
    • Stores temporary system process information.
    • Contains PID files and runtime data.
    • Data is cleared when the system restarts.
    Example:
                  /run/systemd/
              /run/nginx.pid
              /run/docker.pid
    This directory is usually stored in memory (tmpfs) and exists only while the system is running.
  15. 📁 /sbin – System Administration Commands
    The /sbin directory contains system management commands typically used by the system administrator.
    Examples:
    • mount
    • reboot
    • shutdown
    • fsck
    These tools are used for system maintenance and recovery.
  16. 📁 /tmp – Temporary Files
    The /tmp directory stores temporary files created by programs and users.
    Characteristics:
    • Temporary storage location
    • Accessible by all users
    • Often cleared during system reboot
  17. 📁 /usr – User Applications
    The /usr directory contains applications, libraries, and shared resources used by most programs.
    Important subdirectories include:
    • /usr/bin – user commands
    • /usr/lib – program libraries
    • /usr/share – shared data
    Most software installed by package managers is stored here.
  18. 📁 /var – Variable Data
    The /var directory stores data that frequently changes during system operation.
    Examples include:
    • system logs
    • mail queues
    • database files
    • package manager cache
    Example log location: 
                          /var/log/syslog
                      /var/log/nginx
  19. Why FHS is Important
    The Filesystem Hierarchy Standard ensures consistency across Linux systems. This allows administrators and applications to easily find files regardless of the distribution.
    FHS is especially important in:
    • System administration
    • DevOps automation
    • Container environments
    • Cloud infrastructure
Completion check: You should now understand the purpose of the Linux Filesystem Hierarchy Standard and be able to identify the role of important directories such as /bin, /etc, /usr, /var, /home, and /boot.

Goal: Understand the different types of files in Linux, how the system represents them internally, and how administrators can identify and work with these file types using command-line tools.

  1. Introduction to File Types in Linux
    In Linux, everything is treated as a file. This includes normal files, directories, hardware devices, and even communication channels between processes. Linux uses different file types to represent different kinds of resources inside the operating system. These file types allow Linux to maintain a unified filesystem interface where applications interact with resources using file operations. The main Linux file types include:
    • Regular files
    • Directories
    • Symbolic links
    • Character device files
    • Block device files
    • Named pipes (FIFOs)
    • Sockets
  2. Identifying File Types Using ls Command
    Linux displays file types when listing files using: 
                  ls -l
                
    Example output:
    
                
    drwxr-xr-x 2 user user 4096 Mar 10 documents
    -rw-r--r-- 1 user user  234 Mar 10 notes.txt
    lrwxrwxrwx 1 user user   10 Mar 10 link -> notes.txt
    The first character of each line represents the file type.
    SymbolFile Type
    -Regular file
    dDirectory
    lSymbolic link
    cCharacter device
    bBlock device
    pNamed pipe
    sSocket
    Understanding this output helps administrators quickly identify the nature of files on a system.
  3. Regular Files
    Regular files are the most common file type in Linux. These files store user data, program code, scripts, or application binaries.
    Example include:
    • Text files
    • Configuration files
    • Shell scripts
    • Compiled programs
    Example:
                      touch file.txt
                  nano script.sh
    Regular files are represented by the symbol: 
    -
    in the output of ls -l.
  4. Directories
    Directories are special files that contain references to other files and directories. They provide the hierarchical structure of the Linux filesystem.
    Example directory creation:
    mkdir projects
    Example listing:
    drwxr-xr-x 2 user user 4096 projects
    The letter d at the beginning indicates that the file is a directory. Directories allow the operating system to organize files efficiently.
  5. Symbolic Links (Soft Links)
    A symbolic link is a file that points to another file or directory. It acts similar to a shortcut.
    Example creation:
    ln -s original.txt shortcut.txt
    Example output:
    lrwxrwxrwx 1 user user shortcut.txt -> original.txt
    Characteristics:
    • Stores path to the target file
    • Can link across filesystems
    • Breaks if the original file is deleted
    Symbolic links are represented with the symbol:
    l
  6. Character Device Files
    Character devices transfer data one character at a time. These devices are typically used for input/output hardware devices.
    Example:
                  /dev/tty
              /dev/random
              /dev/null
    They are represented by:
    c
    Character devices are commonly used by:
    • terminal interfaces
    • keyboard devices
    • random number generators
  7. Block Device Files
    Block devices store data in fixed-size blocks. These devices allow the system to read and write data in chunks instead of individual characters.
    Example:
                    /dev/sda
                /dev/sda1
    These represent hard disks and disk partitions. Block devices are represented with:
    b
    Block devices are critical for storage systems and filesystems.
  8. Named Pipes (FIFO)
    Named pipes allow processes to communicate with each other.
    Example creation:
    mkfifo mypipe
    Processes can write data to the pipe and another process can read it.
    Named pipes are represented with:
    p
    They are commonly used in scripting and interprocess communication.
  9. Sockets
    Sockets are files used for communication between processes, especially for networking services.
    Examples:
    /var/run/docker.sock
    Applications such as web servers and databases sockets for communication.
    Sockets are represented with:
    s
  10. Advanced Concepts: Everything is a File
    One of the core Linux design principles is that everything is treated as a file.
    Example include:
    • Hardware devices in /dev
    • Kernel information in /proc
    • System runtime data in /run
    This design allows applications to interact with hardware, processes, and services using the same file-based interface.
  11. Why Understanding File Types Matters
    File types are important for system administration and DevOps workflows.
    They help with:
    • debugging system issues
    • managing hardware devices
    • understanding Linux storage systems
    • working with containers and virtualization
    For Example:
                      docker.sock -> socket file
                  /dev/sda -> block device
                  /tmp/mypipe -> named pipe
    Understanding these file types helps engineers troubleshoot systems and manage Linux infrastructure more effectively.
Completion check: You should now be able to identify Linux file types using the ls -l command and understand how different file types are used within the Linux operating system.

Goal: Understand how Linux links work, how files reference inodes, and the difference between Hard Links and Symbolic Links.

  1. Introduction to Links in Linux
    In Linux, a file name is simply a reference to an inode. Links allow multiple references to the same file data.
    There are two main types of links:
    • Hard Links
    • Symbolic Links (Soft Links)
    Links help users:
    • Create shortcuts
    • Share files across locations
    • Organize filesystems efficiently
  2. Understanding File References and Inodes
    Each file in Linux is associated with an inode number.
    The inode stores:
    • file size
    • file permissions
    • owner information
    • disk block locations
    • timestamps
    Directories store filenames and map them to inode numbers.
    ls -i
    Example output:
    12345 file.txt
    12346 notes.txt
    This means the file file.txt is associated with inode 12345.
  3. What is a Hard Link
    A hard link is another filename that points directly to the same inode.
    This means:
    • Both filenames reference the same file data
    • Deleting one filename does not delete the file
    • The file exists until all hard links are removed
  4. Creating a Hard Link
    ln original.txt hardlink.txt
    This creates another reference to the same inode.
    ls -li
    Example output:
    12345 -rw-r--r-- 2 user user 120 Mar 12 original.txt
    12345 -rw-r--r-- 2 user user 120 Mar 12 hardlink.txt
    Notice:
    • Both files share the same inode number
    • The link count increased from 1 to 2
  5. Deleting a Hard Link
    one link is removed, the data remains available.
    rm original.txt
    ls -li
    Example output:
    12345 -rw-r--r-- 1 user user 120 Mar 12 hardlink.txt
    The file still exists because the inode still has one reference.
  6. Limitations of Hard Links
    Hard links have several limitations:
    • Cannot link directories
    • Cannot link across filesystems
    • Only reference the same inode
    Because of these limitations, Linux also provides symbolic links.
  7. What is a Symbolic Link
    A symbolic link (soft link) is a file that contains the path to another file. It acts like a shortcut. Instead of referencing an inode directly, it references a file path.
  8. Creating a Symbolic Link
    ln -s original.txt symlink.txt
    ls -l
    Example output:
    lrwxrwxrwx 1 user user 12 Mar 12 symlink.txt -> original.txt
    Here:
    • l indicates a symbolic link
    • The arrow shows the target file
  9. Behavior of Symbolic Links
    If the original file is deleted, the symbolic link becomes broken.
    rm original.txt
    ls -l
    Example output:
    lrwxrwxrwx 1 user user 12 Mar 12 symlink.txt -> original.txt
    The link still exists but points to a non-existing file.
  10. Checking Link Information
    To inspect link relationships:
    stat file.txt
    Example output:
    File: file.txt
    Size: 120
    Links: 2
    Inode: 12345
    Permissions: -rw-r--r--
    This command shows the inode and link count.
  11. Difference Between Hard Links and Symbolic Links

    Feature Hard Link Symbolic Link
    Reference Points to inode Points to file path
    Cross filesystem No Yes
    Link directories No Yes
    Break if target removed No Yes
  12. Real World Usage
    Symbolic links are widely used in Linux systems. Examples include:
    • Shared libraries
    • System command shortcuts
    • Application configuration references
    Example:
    ls -l /usr/bin/python
    Example output:
    lrwxrwxrwx 1 root root python -> python3
    Here the command python is linked to python3.
  13. Why Links are Important
    Understanding links is critical for:
    • filesystem design
    • system administration
    • software package management
    • DevOps automation
    Linux uses links extensively in system libraries, container images, and package installations.
Completion check: You should now understand how Linux links work, how hard links reference inodes, and how symbolic links reference file paths.

Goal: Understand how Linux attaches storage devices to the filesystem tree using mounting and how to safely detach them using unmounting.

  1. What is Mounting
    Linux organizes storage devices within a single directory structure.Mounting is the process of attaching a storage device to a directory.
    Example:
    mount /dev/sdb1 /mnt/data
    This connects the device /dev/sdb1 to the directory
    /mnt/data.
  2. Viewing Mounted Filesystems
    To see all mounted filesystems:
    mount
    Example output:
    dev/sda1 on / type ext4
    /dev/sdb1 on /mnt/data type ext4
    This shows which devices are attached to which directories.
  3. Mounting a Filesystem
    First create a mount point:
    mkdir /mnt/storage
    Mount the device:
    mount /dev/sdb1 /mnt/storage
    Now files stored on the disk appear inside the mount directory.
  4. Unmounting a Filesystem
    To detach a mounted filesystem:
    umount /mnt/storage
    After unmounting, the device is safely disconnected from the system.
  5. Checking Disk Usage
    To check mounted disk usage:
    df -h
    Example output:
    Filesystem Size Used Avail Mounted on
    /dev/sda1  40G  15G  23G /
    /dev/sdb1 100G  10G  90G /mnt/storage
  6. Automatic Mounting Using fstab
    Linux automatically mounts disks during boot using: /etc/fstab
    Example entry:
    /dev/sdb1  /mnt/storage  ext4  defaults  0 0
    This ensures the disk mounts automatically every time the system starts.
  7. Advanced Mount Options
    Mount commands support options.
    Example:
    mount -o ro /dev/sdb1 /mnt/storage
    Meaning:
    • ro → read-only mode
    Other options:
    • rw → read-write
    • noexec → disable executable files
    • nosuid → disable SUID programs
Completion check: You should now understand how to mount and unmount filesystems and how Linux integrates storage devices into the directory tree.

Goal: Understand how storage disks are divided into partitions and how different filesystems manage data on disk.

  1. What is a Disk Partition
    A partition is a logical division of a physical disk.
    Example disk layout:
    /dev/sda1 → /boot
    /dev/sda2 → /
    /dev/sda3 → /home
    Each partition can contain a separate filesystem.
  2. Viewing Disk Partitions
    To view partitions:
    lsblk
    Example output:
          NAME   SIZE TYPE MOUNTPOINT
      sda    100G disk
      ├─sda1   1G part /boot
      ├─sda2  30G part /
      └─sda3  69G part /home
  3. Partitioning a Disk
    Use the fdisk tool:
    fdisk /dev/sdb
    Inside fdisk you can:
    • create partitions
    • delete partitions
    • view partition tables
  4. Filesystem Types
    Common Linux filesystems include:
    • ext4 – default Linux filesystem
    • xfs – enterprise filesystem
    • btrfs – advanced filesystem with snapshots
    • fat32 – compatibility with Windows
    • ntfs – Windows filesystem
  5. Creating a Filesystem
    To create a filesystem:
    mkfs.ext4 /dev/sdb1
    This formats the partition with the ext4 filesystem.
  6. Checking Filesystem Information
    blkid
    Example output:
    /dev/sda1: UUID="1234-abcd" TYPE="ext4"
    /dev/sdb1: UUID="5678-efgh" TYPE="xfs"
    This shows filesystem types and UUID identifiers.
Completion check: You should now understand how disks are partitioned and how Linux filesystems store and manage data.

Goal: Understand how Linux stores file metadata using inodes and how the filesystem tracks file information.

  1. What is an Inode
    An inode is a data structure used by Linux filesystems to store information about a file. Each file has a unique inode number.
  2. Information Stored in an Inode
    An inode stores:
    • file permissions
    • file owner
    • file size
    • timestamps
    • disk block locations
    Important: The inode does NOT store the filename.
  3. Viewing Inode Numbers
    ls -i
    Example output:
    12345 notes.txt
    12346 script.sh
  4. Checking File Metadata
    stat notes.txt
    Example output:
          File: notes.txt
      Size: 200
      Inode: 12345
      Links: 1
      Permissions: -rw-r--r--
  5. How Files Are Stored
    File storage process: 
    Directory → Filename → Inode → Data Blocks
    Meaning:
    • directory stores filename
    • filename points to inode
    • inode points to disk blocks
  6. Checking Inode Usage
    df -i
    Example output:
    Filesystem Inodes IUsed IFree IUse%
    /dev/sda1 655360 20000 635360 3%
  7. Why Inodes Matter
    Inodes are important for:
    • file management
    • filesystem performance
    • hard links
    • system troubleshooting
    DevOps engineers frequently inspect inode usage when diagnosing storage issues.
Completion check: You should now understand how Linux stores file metadata using inodes and how filenames reference inode numbers.

Goal: Understand Linux virtual filesystems, how the kernel exposes system information through files, and how administrators interact with kernel components using directories like /proc, /sys, /dev, and /run.

  1. What are Virtual Filesystems
    Virtual filesystems are special filesystems created by the Linux kernel to expose system and hardware information.
    Unlike normal filesystems:
    • They do not store data on disk
    • They exist only in memory
    • They provide real-time system information
    These filesystems allow programs and administrators to interact with the kernel using standard file operations.
    Common Linux virtual filesystems include:
    • /proc
    • /sys
    • /dev
    • /run
  2. The /proc Filesystem
    The /proc directory is a virtual filesystem that provides information about system processes and kernel parameters. It is generated dynamically by the kernel.
    To view the contents:
    ls /proc
    Example output:
    1
    245
    1300
    cpuinfo
    meminfo
    uptime
    Numeric directories represent running process IDs.
    Example:
    ls /proc/1
    Example output:
    cmdline
    status
    fd
    maps
    Each directory contains information about a specific process.
  3. Viewing System Information Using /proc
    The /proc filesystem contains useful system information.
    CPU information:
    cat /proc/cpuinfo
    Example output:
    processor : 0
    vendor_id : GenuineIntel
    cpu cores : 4
    Memory information:
    cat /proc/meminfo
    Example output:
    MemTotal: 16384256 kB
    MemFree: 1234567 kB
    System uptime:
    cat /proc/uptime
  4. The /sys Filesystem
    The /sys directory exposes information about hardware devices and kernel subsystems. It is known as the sysfs filesystem.
    To view devices:
    ls /sys/class
    Example output:
    block
    net
    power_supply
    tty
    Each directory represents a hardware class.
    Example network devices:
    ls /sys/class/net
    Example output:
    eth0
    lo
    These directories provide real-time hardware information.
  5. The /dev Filesystem
    The /dev directory contains device files representing hardware devices. Linux treats hardware devices as files.
    Examples:
    ls /dev
    Example output:
    sda
    sda1
    tty
    null
    random
    Device types include:
    • Block devices (disks)
    • Character devices (terminals)
    Example block device:
    ls -l /dev/sda
    Example output:
    brw-rw---- 1 root disk 8, 0 /dev/sda
  6. Understanding Device Management (udev)
    Modern Linux systems dynamically manage devices using the udev device manager.
    When hardware is connected:
    • The kernel detects the device
    • udev creates device files inside /dev
    • Applications can interact with the device
    Example:
    Plugging a USB drive creates a device such as: 
    /dev/sdb
  7. The /run Filesystem
    The /run directory stores runtime system information. It is stored in memory and cleared when the system reboots.
    Examples include:
    • process ID files
    • system service sockets
    • runtime service data
    Example:
    ls /run
    Example output:
    systemd
    user
    docker.sock
    Applications store temporary runtime data here.
  8. Comparing Virtual Filesystems
    Directory Purpose
    /proc Process and kernel information
    /sys Hardware and kernel device information
    /dev Device files representing hardware
    /run Runtime system data
  9. How Virtual Filesystems Connect to the Kernel
    Linux architecture:
          User Applications
            ↓
      System Calls
            ↓
      Linux Kernel
            ↓
      Virtual Filesystems (/proc /sys /dev /run)
            ↓
      Hardware Devices
    These virtual filesystems act as an interface between user-space programs and the Linux kernel.
  10. Why Virtual Filesystems are Important for DevOps
    DevOps engineers interact with these filesystems frequently.
    Examples:
    • Container runtimes use /proc and /sys
    • Docker communicates using /var/run/docker.sock
    • Hardware monitoring uses /sys
    • System metrics tools read /proc
    Monitoring tools such as:
    • top
    • htop
    • free
    • vmstat
    all read data from virtual filesystems.
Completion check: You should now understand how Linux exposes system information through virtual filesystems and how directories like /proc, /sys, /dev, and /run connect user programs to the kernel.

Goal: Understand how the Linux kernel manages files internally using the Virtual File System (VFS) layer and how applications interact with different filesystems like ext4, xfs, and btrfs through a unified interface.

  1. What is the Virtual File System (VFS)
    The Virtual File System (VFS) is a kernel subsystem that provides a unified interface for accessing different filesystem types. Instead of applications communicating directly with each filesystem, they communicate with the VFS layer. The VFS layer then forwards requests to the correct filesystem driver.
    Benefits of VFS:
    • Supports multiple filesystems
    • Provides a unified API
    • Improves portability
    • Simplifies filesystem management
  2. Linux File Access Architecture
    When an application reads or writes a file, the request passes through multiple layers inside the operating system.
    System architecture:
          Application
          ↓
      System Call
          ↓
      VFS Layer
          ↓
      Filesystem Driver
          ↓
      Block Layer
          ↓
      Storage Device
    Each layer performs specific responsibilities.
  3. Application Layer
    Applications interact with files using system libraries.
    Example programs:
    • text editors
    • web servers
    • databases
    • shell commands
    Example file operation:
    cat file.txt
    The application does not know which filesystem stores the file. The operating system handles this automatically.
  4. System Calls
    Applications access files using system calls. Common file system calls include:
    • open()
    • read()
    • write()
    • close()
    • stat()
    Example using strace:
    strace cat file.txt
    Example output:
    open("file.txt", O_RDONLY)
    read(3, "Hello World", 1024)
    close(3)
    These system calls are passed to the VFS layer.
  5. The VFS Layer
    The Virtual File System acts as an abstraction layer. It provides generic operations for all filesystems.
    Responsibilities include:
    • path resolution
    • file lookup
    • permission checking
    • inode management
    • filesystem routing
    Example:
    A request to open a file:
    open("/home/user/file.txt")
    VFS determines:
    • which filesystem contains the file
    • which inode represents the file
    • which filesystem driver handles the request
  6. Filesystem Drivers
    After the VFS identifies the correct filesystem, it forwards the request to the filesystem driver.
    Common Linux filesystems:
    • ext4
    • xfs
    • btrfs
    • fat32
    • ntfs
    Each filesystem has its own driver.
    Example checking filesystem type:
    df -T
    Example output:
    Filesystem Type Size Used Avail Mounted on
    /dev/sda1 ext4 40G 15G 23G /
  7. Block Layer
    The block layer manages how data is written to storage devices.
    Responsibilities include:
    • block allocation
    • disk scheduling
    • I/O optimization
    Filesystems store data in fixed-size blocks.
    Example:
    Block size: 4096 bytes
    The filesystem maps file data to these blocks.
  8. Storage Device Layer
    This is the physical storage device.
    Examples include:
    • hard drives
    • SSDs
    • NVMe drives
    • network storage
    Devices appear in Linux as block devices.
    Example:
    ls /dev/sd*
    Example output:
    /dev/sda
    /dev/sda1
    /dev/sda2
  9. VFS Data Structures
    The VFS uses several internal structures:
    • Superblock
    • Inode
    • Dentry
    • File object
    Explanation:
    • Superblock → filesystem metadata
    • Inode → file metadata
    • Dentry → directory entries
    • File object → open file instance
    These structures allow the kernel to manage files efficiently.
  10. Example of File Access Flow
    When reading a file: 
    cat notes.txt
    Flow inside the system:
          Application (cat)
            ↓
      open() system call
            ↓
      VFS lookup
            ↓
      Filesystem driver
            ↓
      Block device
            ↓
      Disk
    The result is returned to the application.
  11. Why VFS is Important for DevOps
    DevOps engineers work with many storage technologies.
    Examples:
    • Docker container filesystems
    • Kubernetes volumes
    • Network storage
    • Overlay filesystems
    All these systems rely on the VFS layer.
    Container filesystems like:
    • overlayfs
    • aufs
    integrate through the VFS.
  12. Real Example in Containers
    Check container filesystem driver:
    docker info | grep Storage
    Example output:
    Storage Driver: overlay2
    OverlayFS works through the VFS layer to combine multiple filesystems.
  13. Summary of the Linux File System Stack
    Complete Linux file handling stack:
          User Application
            ↓
      System Call Interface
            ↓
      Virtual File System (VFS)
            ↓
      Filesystem Driver (ext4/xfs/btrfs)
            ↓
      Block Layer
            ↓
      Disk / Storage Device
    The VFS ensures that applications can access files consistently regardless of the underlying filesystem.
