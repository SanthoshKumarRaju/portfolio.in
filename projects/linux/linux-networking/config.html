Linux Networking - Interfaces

Goal: Master Netplan to configure networking in Ubuntu systems, including static IP, DHCP, advanced networking, and real-world troubleshooting.

  1. What is Netplan
    Netplan is a YAML-based network configuration tool used in Ubuntu.
    • Introduced in Ubuntu 17.10+
    • Replaces /etc/network/interfaces
    • Acts as a configuration abstraction layer
  2. Why Netplan is Important
    • Simplifies network configuration
    • Supports modern networking
    • Used in servers, cloud, and containers
  3. Netplan Architecture
    Netplan does not configure networking directly.
    • Frontend → Netplan YAML
    • Backend → systemd-networkd / NetworkManager
  4. Configuration File Location
    /etc/netplan/*.yaml
  5. Basic YAML Structure
    network:
  version: 2
  renderer: networkd
  6. Identify Network Interfaces
    ip a
  7. DHCP Configuration
    network:
  version: 2
  ethernets:
    eth0:
      dhcp4: true
  8. Static IP Configuration
    network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 192.168.1.100/24
      gateway4: 192.168.1.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 8.8.4.4
  9. Apply Configuration
    netplan apply
  10. Safe Testing
    netplan try
    Automatically rolls back if misconfigured.
  11. Check Generated Config
    netplan generate
  12. Multiple Interfaces
    ethernets:
  eth0:
    dhcp4: true
  eth1:
    addresses: [10.0.0.10/24]
  13. Set Hostname
    hostnamectl set-hostname my-server
  14. DNS Configuration
    Managed via: 
    nameservers:
  addresses: [8.8.8.8]
  15. Routing Configuration
    routes:
  - to: 0.0.0.0/0
    via: 192.168.1.1
  16. Advanced: VLAN Configuration
    vlans:
  vlan100:
    id: 100
    link: eth0
    addresses: [192.168.100.10/24]
  17. Advanced: Bridge Configuration
    bridges:
  br0:
    interfaces: [eth0]
    dhcp4: true
  18. Advanced: Bonding (NIC Teaming)
    bonds:
  bond0:
    interfaces: [eth0, eth1]
    parameters:
      mode: active-backup
  19. Renderer Types
    • networkd → servers
    • NetworkManager → desktops
  20. Common Errors
    • YAML indentation errors
    • Wrong interface name
    • Invalid IP/gateway
  21. Debug Netplan
    netplan --debug apply
  22. Check Connectivity
    ping 8.8.8.8
ping google.com
  23. Netplan in Cloud
    • Used in AWS, Azure Ubuntu images
    • Configured via cloud-init
  24. Netplan in DevOps
    • Automate server provisioning
    • Used in CI/CD environments
  25. Netplan in Containers
    • Rarely used directly
    • Used in host networking
  26. Troubleshooting Workflow
    Check config file
netplan try
ip a
ip route
ping gateway
  27. Best Practices
    • Always test with netplan try
    • Use correct indentation (YAML sensitive)
    • Backup configs before changes
  28. Real-World Example
    • Server setup → static IP via Netplan
    • Cloud VM → DHCP auto config
    • Production → VLAN + bonding setup
  29. Summary
    Netplan is the modern standard for configuring networking in Ubuntu, providing a flexible, declarative, and scalable way to manage network interfaces.
Completion check: You should now be able to configure and troubleshoot networking using Netplan from basic to advanced scenarios.

Goal: Master NetworkManager for managing network connections dynamically using GUI and CLI tools, including advanced configurations and troubleshooting.

  1. What is NetworkManager
    NetworkManager is a service that manages network connections dynamically in Linux systems.
    • Simplifies network configuration
    • Supports GUI and CLI tools
    • Used in desktops and modern servers
  2. Why NetworkManager is Important
    • Automatic network detection
    • Easy switching between networks
    • Supports Wi-Fi, Ethernet, VPN
  3. Architecture
    • NetworkManager daemon (service)
    • CLI tools → nmcli
    • UI tools → nmtui / GUI
  4. Check NetworkManager Status
    systemctl status NetworkManager
  5. Start / Stop Service
    systemctl start NetworkManager
systemctl stop NetworkManager
  6. List Network Devices
    nmcli device status
  7. List Connections
    nmcli connection show
  8. Bring Up a Connection
    nmcli connection up eth0
  9. Bring Down a Connection
    nmcli connection down eth0
  10. Create DHCP Connection
    nmcli connection add type ethernet ifname eth0 con-name my-dhcp
  11. Configure Static IP
    nmcli connection modify eth0 ipv4.addresses 192.168.1.100/24
nmcli connection modify eth0 ipv4.gateway 192.168.1.1
nmcli connection modify eth0 ipv4.dns "8.8.8.8"
nmcli connection modify eth0 ipv4.method manual
nmcli connection up eth0
  12. Delete Connection
    nmcli connection delete eth0
  13. Modify DNS
    nmcli connection modify eth0 ipv4.dns "8.8.8.8 8.8.4.4"
  14. nmtui (Text UI Tool)
    nmtui
    Provides interactive configuration.
  15. GUI Usage
    • Used in desktop environments
    • Easy Wi-Fi and VPN management
  16. Connection Profiles
    Stored in: 
    /etc/NetworkManager/system-connections/
  17. Advanced: Multiple Interfaces
    Manage multiple NICs with separate configs.
  18. Advanced: VLAN Configuration
    nmcli connection add type vlan dev eth0 id 100
  19. Advanced: Bridge Configuration
    nmcli connection add type bridge ifname br0
  20. Advanced: Bonding
    nmcli connection add type bond ifname bond0 mode active-backup
  21. Wi-Fi Management
    nmcli device wifi list
nmcli device wifi connect "SSID" password "password"
  22. VPN Configuration
    • Supports OpenVPN, IPSec
    • Configured via GUI or nmcli
  23. NetworkManager vs Netplan
    Feature NetworkManager Netplan
    Type Dynamic Declarative
    Use Case Desktop Server
  24. Use in DevOps
    • Dynamic network changes
    • Automation using nmcli scripts
  25. Use in Cloud
    • Manage multiple interfaces
    • Handle dynamic IP assignment
  26. Use in Containers
    • Mostly used on host systems
    • Controls bridge networks
  27. Common Issues
    • Connection not activating
    • Wrong DNS
    • Interface unmanaged
  28. Debug NetworkManager
    journalctl -u NetworkManager
  29. Troubleshooting Workflow
    nmcli device status
nmcli connection show
ip a
ping gateway
  30. Best Practices
    • Use nmcli for automation
    • Keep configs consistent
    • Monitor connection states
  31. Real-World Example
    • Laptop → Wi-Fi switching
    • Server → dynamic IP updates
    • Production → VLAN + bonding via nmcli
  32. Summary
    NetworkManager provides a powerful and flexible way to manage networking dynamically using both CLI and GUI tools, making it essential for modern Linux environments.
Completion check: You should now be able to configure and manage networking dynamically using NetworkManager and nmcli.

Goal: Master nmcli and nmtui to configure, automate, and troubleshoot networking using command-line tools in Linux systems.

  1. What are nmcli & nmtui
    • nmcli → Command-line interface for NetworkManager
    • nmtui → Text-based UI tool
  2. Why These Tools are Important
    • Used in servers (no GUI)
    • Automation-friendly
    • Full control over networking
  3. nmcli Command Structure
    nmcli [OPTIONS] OBJECT { COMMAND }
  4. Main nmcli Objects
    • device → network interfaces
    • connection → saved configs
    • general → overall status
  5. Check Network Status
    nmcli general status
  6. List Devices
    nmcli device status
  7. List Connections
    nmcli connection show
  8. Show Detailed Info
    nmcli device show
  9. Bring Interface Up
    nmcli device connect eth0
  10. Bring Interface Down
    nmcli device disconnect eth0
  11. Create New Connection
    nmcli connection add type ethernet ifname eth0 con-name my-conn
  12. Set Static IP
    nmcli connection modify my-conn ipv4.addresses 192.168.1.100/24
nmcli connection modify my-conn ipv4.gateway 192.168.1.1
nmcli connection modify my-conn ipv4.dns "8.8.8.8"
nmcli connection modify my-conn ipv4.method manual
nmcli connection up my-conn
  13. Set DHCP
    nmcli connection modify my-conn ipv4.method auto
  14. Modify Existing Connection
    nmcli connection modify eth0 ipv4.dns "1.1.1.1"
  15. Delete Connection
    nmcli connection delete my-conn
  16. Wi-Fi Scanning
    nmcli device wifi list
  17. Connect to Wi-Fi
    nmcli device wifi connect "SSID" password "password"
  18. nmtui Overview
    nmtui
    Menu options:
    • Edit connection
    • Activate connection
    • Set hostname
  19. When to Use nmtui
    • Quick setup
    • Beginner-friendly
    • No need to remember commands
  20. nmcli vs nmtui
    Feature nmcli nmtui
    Interface CLI Text UI
    Automation Yes No
  21. Advanced: VLAN
    nmcli connection add type vlan dev eth0 id 100
  22. Advanced: Bridge
    nmcli connection add type bridge ifname br0
  23. Advanced: Bonding
    nmcli connection add type bond ifname bond0 mode active-backup
  24. Automation with nmcli
    #!/bin/bash
nmcli connection add type ethernet ifname eth0 con-name auto-ip
nmcli connection up auto-ip
  25. Use in DevOps
    • Automate server networking
    • CI/CD environment setup
    • Infrastructure as Code scripts
  26. Use in Cloud
    • Dynamic IP changes
    • Multiple network interfaces
  27. Common Issues
    • Connection not activating
    • Interface unmanaged
    • Wrong DNS or gateway
  28. Debugging
    nmcli general status
nmcli device status
journalctl -u NetworkManager
  29. Troubleshooting Workflow
    Check device → nmcli device status
Check connection → nmcli connection show
Restart → systemctl restart NetworkManager
Test → ping 8.8.8.8
  30. Best Practices
    • Use nmcli for automation
    • Use nmtui for quick setup
    • Keep consistent naming
  31. Real-World Example
    • Server provisioning → nmcli scripts
    • Quick fix → nmtui
    • Production → VLAN + bonding via nmcli
  32. Summary
    nmcli and nmtui provide powerful command-line tools to manage networking efficiently, enabling automation, troubleshooting, and advanced configurations in Linux environments.
Completion check: You should now be able to configure, automate, and troubleshoot networking using nmcli and nmtui.

Goal: Master ifcfg-based network configuration in RHEL systems, including static IP setup, advanced networking, and enterprise troubleshooting.

  1. What are ifcfg Files
    ifcfg files are configuration files used in RHEL-based systems to define network interface settings.
    • Used in RHEL, CentOS, Rocky Linux
    • Stored as key-value pairs
  2. Why ifcfg is Important
    • Widely used in enterprise environments
    • Simple and readable format
    • Compatible with automation tools
  3. File Location
    /etc/sysconfig/network-scripts/
  4. File Naming Convention
    ifcfg-eth0
ifcfg-ens33
  5. Basic File Structure
    DEVICE=eth0
BOOTPROTO=dhcp
ONBOOT=yes
  6. DHCP Configuration
    DEVICE=eth0
BOOTPROTO=dhcp
ONBOOT=yes
TYPE=Ethernet
  7. Static IP Configuration
    DEVICE=eth0
BOOTPROTO=none
ONBOOT=yes
IPADDR=192.168.1.100
NETMASK=255.255.255.0
GATEWAY=192.168.1.1
DNS1=8.8.8.8
  8. Important Parameters
    • DEVICE → Interface name
    • BOOTPROTO → dhcp / none
    • ONBOOT → Start at boot
    • IPADDR → IP address
    • NETMASK → Subnet mask
    • GATEWAY → Default gateway
  9. Restart Network Service
    systemctl restart network
  10. Check Interface Status
    ip a
  11. DNS Configuration
    /etc/resolv.conf
  12. Multiple Interfaces
    Each interface has its own file: 
    ifcfg-eth0
ifcfg-eth1
  13. Advanced: Multiple IPs
    IPADDR0=192.168.1.100
IPADDR1=192.168.1.101
  14. Advanced: VLAN
    DEVICE=eth0.100
VLAN=yes
IPADDR=192.168.100.10
  15. Advanced: Bridge
    DEVICE=br0
TYPE=Bridge
BOOTPROTO=dhcp
  16. Advanced: Bonding
    DEVICE=bond0
BONDING_OPTS="mode=active-backup"
  17. Advanced: MTU Configuration
    MTU=9000
  18. Network Scripts
    Managed by: 
    /etc/init.d/network
  19. ifcfg vs NetworkManager
    Feature ifcfg NetworkManager
    Type Static Dynamic
    Usage Servers Modern systems
  20. Use in DevOps
    • Automate server configuration
    • Infrastructure provisioning
    • Used with Ansible
  21. Use in Cloud
    • Configure static IPs
    • Multi-NIC setups
  22. Use in Enterprise
    • Data center networking
    • High availability setups
  23. Common Issues
    • Wrong IP or gateway
    • Interface not starting
    • DNS not resolving
  24. Debugging
    ip a
ip route
ping gateway
systemctl status network
  25. Troubleshooting Workflow
    Check config file
Restart network
Verify IP (ip a)
Check route (ip route)
Test connectivity
  26. Best Practices
    • Use consistent naming
    • Backup configs before changes
    • Validate after restart
  27. Real-World Example
    • Enterprise server → static IP via ifcfg
    • Data center → bonded interfaces
    • Cloud VM → multiple NIC config
  28. Summary
    ifcfg files provide a simple and reliable way to configure networking in RHEL systems, especially in enterprise and production environments.
Completion check: You should now be able to configure and troubleshoot networking using ifcfg files in RHEL-based systems.
