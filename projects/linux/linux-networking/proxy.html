  1. What is Reverse Proxy
    Reverse proxy sits between client and backend servers.
  2. Why Reverse Proxy

    • Improve security
    • Enable load balancing
  3. Basic Flow
    Client → Reverse Proxy → Backend → Response → Client
  4. Reverse vs Forward Proxy
    • Forward proxy → client side
    • Reverse proxy → server side
  5. Request Routing
    /api → service-A
/auth → service-B
  6. Load Balancing
    • Round Robin
    • Least Connections
    • IP Hash
  7. Traffic Distribution
    Client → Proxy → [Server1, Server2, Server3]
  8. SSL Termination
    Client (HTTPS) → Proxy → Backend (HTTP)
  9. Security Layer
    • Hide internal IP
    • Block malicious traffic
    • Rate limiting
  10. Caching
    Proxy (cache hit) → Response (no backend call)
  11. Header Management
    • X-Forwarded-For
    • X-Real-IP
  12. Reverse Proxy with Docker
    Client → Traefik/Nginx → Containers
  13. Microservices Routing
    • Single entry point
    • Routes to multiple services
  14. High Availability
    If Server1 fails → route to Server2
  15. Health Checks

  16. Logging & Monitoring

    • Traffic tracking
  17. Performance Optimization

    • Connection reuse

Goal: Understand how load balancing distributes traffic across multiple servers to ensure scalability, reliability, and high availability.

  1. What is Load Balancing
    Distributes incoming traffic across multiple backend servers.
  2. Why Load Balancing
    • Prevent server overload
    • Ensure high availability
    • Improve performance
  3. Basic Flow
    Client → Load Balancer → Multiple Servers → Response
  4. Single Server Problem
    Client → Server (Overload / Failure)
  5. With Load Balancer
    Client → LB → [Server1, Server2, Server3]
  6. Types of Load Balancing
    • Layer 4 (Transport level)
    • Layer 7 (Application level)
  7. Layer 4 Load Balancing
    • Works on IP + Port
    • Fast and efficient
  8. Layer 7 Load Balancing
    • Works on HTTP/HTTPS
    • Routes based on URL, headers
  9. Load Balancing Algorithms
    • Round Robin
    • Least Connections
    • IP Hash
    • Weighted Round Robin
  10. Round Robin
    Req1 → Server1
Req2 → Server2
Req3 → Server3
  11. Least Connections
    Routes traffic to server with fewer active connections.
  12. IP Hash
    Same client always goes to same server.
  13. Weighted Distribution
    Server1 (weight 3) → More traffic
Server2 (weight 1) → Less traffic
  14. Health Checks
    Check /health → If fail → remove server
  15. Failover Mechanism
    If Server1 down → redirect to Server2
  16. Session Persistence (Sticky Sessions)
    • User sticks to same server
  17. Active vs Passive LB
    • Active → distributes traffic
    • Passive → standby backup
  18. DNS Load Balancing
    Domain → multiple IPs
  19. Hardware vs Software LB
    • Hardware → expensive, high performance
    • Software → flexible (Nginx, HAProxy)
  20. Cloud Load Balancing
    • AWS ELB
    • GCP Load Balancer
  21. Load Balancer + Reverse Proxy
    Often combined in same tool (Nginx, Traefik).
  22. Docker / Swarm Integration
    Client → LB → Swarm Service → Containers
  23. Ingress Load Balancing (Swarm)
    • Routing mesh
    • Requests hit any node
  24. Traffic Flow in Swarm
    Client → Any Node → Routing Mesh → Container
  25. Performance Benefits
    • Reduced latency
    • Better throughput
  26. Security Benefits
    • Hides backend servers
    • DDoS mitigation
  27. Common Ports
    • 80 → HTTP
    • 443 → HTTPS
  28. Nginx Load Balancing Example
    upstream backend {
  server app1:3000;
  server app2:3000;
}

server {
  location / {
    proxy_pass http://backend;
  }
}
  29. Debug Commands
    curl -v http://lb
docker service ps
docker logs
  30. Common Issues
    • Uneven traffic distribution
    • Health check failure
    • Session issues
  31. Troubleshooting Flow
    Check LB config
Check backend health
Check logs
Check network
  32. Real-World Use Cases
    • High traffic websites
    • Microservices
    • Cloud applications
  33. Summary
    Load balancing distributes traffic across servers to ensure reliability, scalability, and high performance.
Completion check: You should now understand how load balancing distributes traffic and ensures high availability.

Goal: Understand how SSL termination works at the proxy level to handle HTTPS encryption, improve performance, and simplify backend communication.

  1. What is SSL Termination
    SSL termination is the process where HTTPS encryption is handled at the proxy instead of backend servers.
  2. Why SSL Termination
    • Reduce backend load
    • Centralized certificate management
    • Improve performance
  3. Basic Flow
    Client (HTTPS) → Proxy (Decrypt) → Backend (HTTP) → Response → Proxy (Encrypt) → Client
  4. Without SSL Termination
    Client → HTTPS → Backend (Handles SSL)
  5. With SSL Termination
    Client → HTTPS → Proxy → HTTP → Backend
  6. SSL/TLS Overview
    • Encrypts data in transit
    • Ensures confidentiality & integrity
  7. Handshake Process
    Client Hello → Server Certificate → Key Exchange → Secure Connection
  8. Certificates
    • Public key certificates
    • Issued by Certificate Authority (CA)
  9. Private Key
    Stored securely in proxy to decrypt traffic.
  10. SSL Offloading
    Another term for SSL termination (proxy handles encryption work).
  11. Benefits
    • Faster backend processing
    • Reduced CPU usage on servers
    • Simplified architecture
  12. Security Consideration
    • Backend traffic becomes HTTP (not encrypted)
    • Use internal secure networks
  13. Re-Encryption (Optional)
    Client → HTTPS → Proxy → HTTPS → Backend
  14. Edge Termination
    SSL ends at proxy (most common setup).
  15. End-to-End Encryption
    SSL continues till backend.
  16. Tools Supporting SSL Termination
    • Nginx
    • Traefik
    • HAProxy
  17. Common Ports
    • 443 → HTTPS
    • 80 → HTTP
  18. Nginx SSL Example
    server {
  listen 443 ssl;

  ssl_certificate /etc/ssl/cert.pem;
  ssl_certificate_key /etc/ssl/key.pem;

  location / {
    proxy_pass http://backend:3000;
  }
}
  19. Traefik SSL Example
    labels:
  - "traefik.http.routers.app.tls=true"
  20. Let's Encrypt Integration
    • Auto-generate SSL certificates
    • Auto-renewal
  21. Performance Optimization
    • Session reuse
    • TLS offloading
  22. Header Handling
    • X-Forwarded-Proto: https
  23. Debug Commands
    curl -v https://example.com
openssl s_client -connect example.com:443
  24. Common Issues
    • Certificate expired
    • Wrong certificate path
    • Mixed content issues
  25. Troubleshooting Flow
    Check certificate
Check proxy config
Check ports
Check logs
  26. Docker / Swarm Integration
    Client → HTTPS → Traefik → Service → Containers
  27. Security Best Practices
    • Use strong TLS versions
    • Disable weak ciphers
    • Enable HSTS
  28. Real-World Use Cases
    • Web applications
    • Microservices
    • Cloud deployments
  29. Summary
    SSL termination offloads encryption to proxy, improving performance and simplifying secure communication management.
Completion check: You should now understand how SSL termination works and how it secures and optimizes modern architectures.

  2. Why Traefik
    • Dynamic configuration
    • Automatic service discovery
    • Built-in SSL support
  3. Basic Flow
    Client → Traefik → Service → Container
  4. Static vs Dynamic Config
    • Static → startup config
    • Dynamic → runtime routing rules
  5. Core Components
    • EntryPoints
    • Routers
    • Services
    • Middlewares
  6. EntryPoints
    :web → port 80
:websecure → port 443
  7. Routers
    Defines how requests are matched. 
    Host(`example.com`)
Path(`/api`)
  8. Services
    Backend services where traffic is forwarded.
  9. Middlewares
    • Authentication
    • Rate limiting
    • Redirects
  10. Dynamic Service Discovery
    Traefik automatically detects containers using Docker API.
  11. Docker Integration
    --providers.docker=true
  12. Docker Labels
    Used to define routing rules.

  - "traefik.http.routers.app.rule=Host(`example.com`)"
  13. Swarm Mode Integration
    --providers.docker.swarmMode=true
  14. Overlay Network Usage
    Traefik communicates with services via overlay network.
  15. Load Balancing in Traefik
    Multiple containers → traffic distributed automatically
  16. SSL / HTTPS Support

    • Let's Encrypt integration
  17. Let's Encrypt Example

  18. HTTP to HTTPS Redirect

  19. Traefik Dashboard

  20. EntryPoints Example

  21. Security Features

  22. Middleware Example

  23. Request Flow in Traefik

  24. High Availability

  25. Logging & Monitoring

Goal: Understand how Nginx works as a reverse proxy and load balancer to efficiently route traffic and manage backend services.

  2. Why Nginx
    • High performance
    • Handles thousands of connections
    • Lightweight and scalable
  3. Basic Flow
    Client → Nginx → Backend Server → Response → Client
  4. Nginx Architecture
    • Master process
    • Worker processes
    • Event-driven model
  5. Event-Driven Model
    Handles multiple requests asynchronously using non-blocking I/O.
  6. Reverse Proxy Role
    Client → Nginx → Backend (hidden)
  7. Load Balancer Role
    Client → Nginx → [Server1, Server2, Server3]
  8. Static Content Serving
    Nginx serves static files faster than backend servers.
  9. Load Balancing Algorithms
    • Round Robin (default)
    • Least Connections
    • IP Hash
  10. Upstream Block

  server app2:3000;
}
  11. Proxy Configuration

  12. SSL Termination

  13. Compression

  14. Caching
    • Reduces backend load
  15. Connection Handling
    • Keep-alive connections
  16. Header Forwarding

  17. Health Checks

  18. Failover Handling

  19. Rate Limiting
    • Prevent abuse
  20. Security Features

  21. Common Ports

Goal: Understand how HAProxy provides high-performance load balancing, traffic routing, and high availability for modern applications.

  1. What is HAProxy
    HAProxy is a fast, reliable load balancer and reverse proxy designed for high-traffic systems.
  2. Why HAProxy
    • Handles millions of requests
    • Low latency
    • Highly reliable
  3. Basic Flow
    Client → HAProxy → Backend Servers → Response → Client
  4. Core Components
    • Frontend
    • Backend
    • Listen
  5. Frontend
    Handles incoming client requests. 
    frontend http_front
  bind *:80
  6. Backend
    Defines server pool. 
    backend app_servers
  server app1 10.0.0.1:3000
  server app2 10.0.0.2:3000
  7. Listen Block
    Combines frontend + backend.
  8. Load Balancing Algorithms
    • Round Robin
    • Least Connections
    • Source (IP Hash)
  9. Traffic Distribution
    Client → HAProxy → [Server1, Server2, Server3]
  10. Layer 4 vs Layer 7
    • L4 → TCP level
    • L7 → HTTP level (content-based routing)
  11. Health Checks
    option httpchk GET /health
  12. Failover Mechanism
    If server fails → traffic redirected
  13. Session Persistence
    • Sticky sessions
  14. SSL Termination
    bind *:443 ssl crt /etc/ssl/cert.pem
  15. Access Control
    • ACL (Access Control Lists)
    acl is_api path_beg /api
  16. Routing Rules
    use_backend api_servers if is_api
  17. Rate Limiting
    Protects against abuse.
  18. Logging
    • Detailed request logs
  19. Monitoring Dashboard
    stats enable
stats uri /stats
  20. High Availability Setup
    Multiple HAProxy instances + failover
  21. Performance Features
    • Connection reuse
    • Efficient memory usage
  22. Security Features
    • SSL support
    • Request filtering
  23. Common Ports
    • 80 → HTTP
    • 443 → HTTPS
  24. Docker Integration
    Client → HAProxy → Containers
  25. Swarm Integration
    Client → HAProxy → Swarm Services → Containers
  26. Example Full Config
    frontend http_front
  bind *:80
  default_backend app_servers

backend app_servers
  balance roundrobin
  server app1 10.0.0.1:3000 check
  server app2 10.0.0.2:3000 check
  27. Debug Commands
    haproxy -c -f /etc/haproxy/haproxy.cfg
systemctl status haproxy
  28. Common Issues
    • Backend unreachable
    • Health check failure
    • Wrong ACL rules
  29. Troubleshooting Flow
    Check config
Check backend
Check logs
Check network
  30. Real-World Use Cases
    • High-traffic websites
    • Banking systems
    • Cloud platforms
  31. Summary
    HAProxy is a powerful, high-performance load balancer used to distribute traffic, ensure reliability, and handle large-scale applications efficiently.
Completion check: You should now understand how HAProxy manages high-performance load balancing and traffic routing.
