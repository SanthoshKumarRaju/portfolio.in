Goal: Understand how journalctl is used to query, filter, and analyze system logs in modern Linux systems powered by systemd.

  1. What is journalctl
    journalctl is a command-line tool used to view and query logs collected by systemd-journald.
  2. Why journalctl
    • Centralized logging
    • Powerful filtering
    • Structured logs
  3. Logging System
    systemd-journald → stores logs → journalctl queries them
  4. Basic Command
    journalctl
    Shows all logs.
  5. Real-Time Logs
    journalctl -f
    Similar to tail -f.
  6. Filter by Service
    journalctl -u nginx
  7. Filter by Time
    journalctl --since "1 hour ago"
journalctl --since "2024-01-01"
  8. Filter by Boot
    journalctl -b
  9. Previous Boot Logs
    journalctl -b -1
  10. Filter by Priority
    journalctl -p err
  11. Log Levels
    • 0 → Emergency
    • 3 → Error
    • 6 → Info
  12. Show Last N Lines
    journalctl -n 50
  13. Combine Filters
    journalctl -u nginx -p err --since "1 hour ago"
  14. Search Logs
    journalctl | grep "error"
  15. Kernel Logs
    journalctl -k
  16. JSON Output
    journalctl -o json
  17. Disk Usage
    journalctl --disk-usage
  18. Clear Logs
    journalctl --vacuum-time=7d
  19. Persistent Logs
    /var/log/journal
  20. Enable Persistent Logging
    mkdir -p /var/log/journal
systemctl restart systemd-journald
  21. Log Structure
    Timestamp → Unit → Message
  22. Debugging Workflow
    Check logs → Filter → Identify issue → Fix
  23. Docker Integration
    • Uses journald logging driver
  24. Kubernetes Integration
    • Node logs via journalctl
  25. Security Logs
    journalctl -u ssh
  26. Performance Consideration
    • Large logs consume disk space
  27. Common Issues
    • Logs missing
    • Permission denied
    • Logs not persistent
  28. Troubleshooting Flow
    Check service logs
Filter errors
Check system logs
Analyze timestamps
  29. Best Practices
    • Enable persistent logs
    • Use filters effectively
    • Rotate logs regularly
  30. Real-World Example
    Debugging failed service using journalctl -u service_name
  31. Summary
    journalctl is a powerful tool for querying and analyzing system logs, providing deep insights into system behavior and issues.
Completion check: You should now understand how to use journalctl for efficient log analysis and troubleshooting.

Goal: Understand how service logs help debug networking issues in applications, including request flow, errors, and performance bottlenecks.

  1. What are Service Logs
    Service logs are logs generated by applications and services that record runtime events, requests, and errors.
  2. Why Service Logs
    • Debug application issues
    • Trace network requests
    • Monitor performance
  3. Basic Concept
    Client Request → Service → Log Entry → Analysis
  4. Types of Service Logs
    • Access logs
    • Error logs
    • Debug logs
  5. Access Logs
    Request → Response → Status code logged
  6. Error Logs
    Failures → Exceptions → Error details
  7. Debug Logs
    • Detailed internal processing logs
  8. Common Log Format
    Timestamp → Request → Status → IP → Message
  9. HTTP Status Codes
    • 200 → Success
    • 404 → Not found
    • 500 → Server error
  10. Nginx Logs
    /var/log/nginx/access.log
/var/log/nginx/error.log
  11. HAProxy Logs
    • Connection metrics
  12. Application Logs
    • Spring Boot, Node.js, etc.
  13. Docker Logs
    docker logs container_id
  14. Kubernetes Logs
    kubectl logs pod_name
  15. Tracing Requests
    Request ID → Track across services
  16. Correlation ID
    Helps trace requests in microservices.
  17. Network Issues in Logs
    • Timeouts
    • Connection refused
    • DNS errors
  18. Latency Analysis
    Request time → Response time
  19. Log Levels
    • INFO
    • WARN
    • ERROR
  20. Filtering Logs
    grep "error" logfile
  21. Real-Time Monitoring
    tail -f access.log
  22. Centralized Logging
    • ELK Stack
    • Fluentd
  23. Metrics vs Logs
    • Logs → detailed events
    • Metrics → aggregated data
  24. Alerting
    • Trigger alerts on errors
  25. Common Issues
    • Logs missing
    • Too verbose logs
    • No structured logs
  26. Troubleshooting Flow
    Check logs
Filter errors
Trace request
Identify root cause
  27. Performance Consideration
    • Logging overhead
  28. Best Practices
    • Use structured logs (JSON)
    • Include request IDs
    • Centralize logs
  29. Advanced Tools
    • ELK Stack
    • Grafana Loki
  30. Real-World Example
    Debugging API timeout using Nginx access logs and backend logs
  31. Summary
    Service logs provide deep visibility into application behavior and are essential for debugging networking issues and performance bottlenecks.
