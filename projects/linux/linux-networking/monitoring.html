Goal: Master tcpdump to capture, analyze, and debug network traffic at packet level in real-world systems.

  1. What is tcpdump
    tcpdump is a command-line tool used to capture and analyze network packets.
    • Works at packet level
    • Used for deep debugging
  2. Why tcpdump is Important
    • Shows real network traffic
    • Helps identify root cause
    • Used by DevOps, SRE, network engineers
  3. Install tcpdump
    sudo apt install tcpdump
  4. Basic Command
    tcpdump
  5. Capture on Interface
    tcpdump -i eth0
  6. List Interfaces
    tcpdump -D
  7. Capture Limited Packets
    tcpdump -c 10
  8. Filter by IP
    tcpdump host 192.168.1.10
  9. Filter by Port
    tcpdump port 80
  10. Filter by Protocol
    tcpdump tcp
tcpdump udp
  11. Combine Filters
    tcpdump tcp port 80 and host 192.168.1.10
  12. Capture HTTP Traffic
    tcpdump -i eth0 port 80
  13. Capture DNS Traffic
    tcpdump port 53
  14. Verbose Output
    tcpdump -v
tcpdump -vv
tcpdump -vvv
  15. Show Packet Data
    tcpdump -X
  16. Save Capture to File
    tcpdump -w capture.pcap
  17. Read Capture File
    tcpdump -r capture.pcap
  18. Use with Wireshark
    Analyze .pcap files in GUI.
  19. Packet Flow Understanding
    Client → SYN → Server
Server → SYN-ACK → Client
Client → ACK → Connection established
  20. Debug HTTP Issues
    tcpdump -i eth0 port 80
  21. Debug DNS Issues
    tcpdump port 53
  22. Debug SSH Issues
    tcpdump port 22
  23. Detect Packet Drops
    • No response → firewall or routing issue
  24. Advanced: Capture Only Incoming
    tcpdump -i eth0 dst host 192.168.1.10
  25. Advanced: Capture Only Outgoing
    tcpdump -i eth0 src host 192.168.1.10
  26. Advanced: Time Stamps
    tcpdump -tttt
  27. DevOps Use Cases
    • Debug API failures
    • Analyze microservice communication
  28. Cloud Troubleshooting
    • Check incoming/outgoing traffic
    • Debug security group issues
  29. Container Debugging
    • Capture traffic on docker0
    • Analyze pod communication
  30. Kubernetes Debugging
    • Check service traffic
    • Debug network policies
  31. Common Issues
    • No packets captured → wrong interface
    • Too much data → no filter
  32. Troubleshooting Workflow
    Run tcpdump
Apply filters
Observe packets
Identify issue
  33. Golden Debug Rule
    If packet is not seen → network issue
If packet seen but no response → server/firewall issue
  34. Best Practices
    • Always use filters
    • Capture minimal data
    • Save logs for analysis
  35. Real-World Example
    • API failing → no response packet
    • DNS issue → no DNS reply
    • Firewall issue → packet dropped
  36. Summary
    tcpdump is a powerful tool for capturing and analyzing network packets, enabling deep troubleshooting and precise diagnosis of network issues.
Completion check: You should now be able to capture and analyze network packets using tcpdump for real-world debugging.

Goal: Master Wireshark for visual packet inspection, protocol analysis, and advanced network debugging in real-world environments.

  1. What is Wireshark
    Wireshark is a graphical network protocol analyzer used to capture and inspect packets in detail.
    • GUI-based tool
    • Deep protocol inspection
  2. Why Wireshark is Important
    • Visual packet analysis
    • Understand protocols deeply
    • Used in debugging, security, forensics
  3. Install Wireshark
    sudo apt install wireshark
  4. Start Wireshark
    wireshark
  5. Interface Selection
    Choose network interface (eth0, wlan0).
  6. Start Packet Capture
    Click "Start Capture".
  7. Packet List Pane
    Shows all captured packets.
  8. Packet Details Pane
    Shows protocol layers:
    • Ethernet
    • IP
    • TCP/UDP
    • Application (HTTP, DNS)
  9. Packet Bytes Pane
    Raw packet data in hex format.
  10. Capture Filters
    Applied before capture: 
    port 80
host 192.168.1.10
  11. Display Filters
    Applied after capture: 
    http
ip.addr == 192.168.1.10
tcp.port == 443
  12. Follow TCP Stream
    View full conversation between client and server.
  13. Analyze HTTP Traffic
    • Request headers
    • Response codes
  14. Analyze DNS Queries
    • Domain lookup
    • Response IP
  15. Analyze TCP Handshake
    SYN → SYN-ACK → ACK
  16. Identify Retransmissions
    Detect packet loss or network issues.
  17. Color Coding
    Different protocols highlighted for easy analysis.
  18. Statistics Menu
    • Protocol hierarchy
    • Conversations
  19. Save Capture File
    .pcap file
  20. Open tcpdump Capture
    Import .pcap files from tcpdump.
  21. Wireshark vs tcpdump

  22. Use in DevOps
    • Debug API calls

  23. Use in Security
    • Detect suspicious traffic
    • Analyze attacks
  24. Cloud Troubleshooting
    • Analyze VM traffic
    • Debug load balancer issues
  25. Container/Kubernetes Debugging
    • Analyze pod communication
    • Debug service mesh issues
  26. Common Issues
    • No packets → wrong interface
    • Too much data → no filters
  27. Troubleshooting Workflow
    Capture traffic
Apply filters
Analyze packets
Identify issue
  28. Golden Debug Rule
    Packets tell the truth — always verify with them
  29. Best Practices
    • Use filters to reduce noise
    • Focus on specific protocols
    • Save captures for analysis
  30. Real-World Example
    • Slow API → TCP retransmissions
    • DNS issue → no response packet

  31. Summary
    Wireshark provides a powerful graphical interface for deep packet inspection, making it essential for advanced debugging, protocol analysis, and network troubleshooting.

Goal: Learn how to monitor real-time network bandwidth usage using iftop and analyze traffic patterns in Linux systems.

  1. What is iftop
    iftop is a command-line tool that displays real-time network bandwidth usage per connection.
    • Similar to top (CPU) but for network
    • Shows live traffic
  2. Why iftop is Important
    • Identify bandwidth usage
    • Detect unusual traffic
    • Debug network bottlenecks
  3. Install iftop
    sudo apt install iftop
  4. Run iftop
    sudo iftop
  5. Select Interface
    sudo iftop -i eth0
  6. Output Overview
    Displays:
    • Source IP
    • Destination IP
    • Bandwidth usage
  7. Traffic Columns
    • Last 2s
    • Last 10s
    • Last 40s
  8. Interpretation
    • High bandwidth → heavy traffic
    • Unknown IP → suspicious activity
  9. Show Ports
    Press: 
    P
  10. Toggle Hostnames
    Press: 
    n
  11. Show/Hide DNS Resolution
    iftop -n
  12. Filter by Host
    iftop -f "host 192.168.1.10"
  13. Filter by Port
    iftop -f "port 80"
  14. Sort Traffic
    Press: 
    s
  15. Pause Output
    Press: 
    p
  16. Show Help
    Press: 
    h
  17. Bandwidth Units
    • b → bits
    • B → bytes
  18. Identify Top Talkers
    • High usage connections
    • Traffic spikes
  19. DevOps Use Cases
    • Detect traffic spikes
    • Monitor API traffic
  20. Security Use Cases
    • Detect suspicious IPs
    • Identify data exfiltration
  21. Cloud Troubleshooting
    • Check instance bandwidth usage
    • Debug unexpected traffic
  22. Container Monitoring
    • Monitor container traffic
    • Check service communication
  23. Common Issues
    • No output → wrong interface
    • Too much data → use filters
  24. Combine with tcpdump
    • iftop → who is using bandwidth
    • tcpdump → what data is flowing
  25. Troubleshooting Workflow
    Run iftop
Identify high traffic
Filter traffic
Investigate source
  26. Golden Debug Rule
    High bandwidth = potential bottleneck or attack
  27. Best Practices
    • Always monitor production traffic
    • Use filters to focus
    • Combine with other tools
  28. Real-World Example
    • Server slow → high outgoing traffic
    • Unexpected load → unknown IP consuming bandwidth
    • API latency → network congestion
  29. Summary
    iftop provides real-time visibility into network bandwidth usage, making it a powerful tool for monitoring, troubleshooting, and detecting anomalies.
Completion check: You should now be able to monitor and analyze real-time bandwidth usage using iftop.

Goal: Learn how to monitor incoming and outgoing network traffic visually using nload and interpret real-time bandwidth usage.

  1. What is nload
    nload is a command-line tool that shows real-time incoming and outgoing traffic with a visual graph.
    • Lightweight and simple
    • Graph-based monitoring
  2. Why nload is Useful
    • Quick visual understanding of traffic
    • Easy to detect spikes
    • No complex configuration
  3. Install nload
    sudo apt install nload
  4. Run nload
    sudo nload
  5. Select Interface
    sudo nload eth0
  6. Interface Switching
    Use: 
    ← → (arrow keys)
  7. Output Layout
    Displays:
    • Incoming traffic (top graph)
    • Outgoing traffic (bottom graph)
  8. Graph Interpretation
    • Spikes → sudden traffic increase
    • Flat line → no activity
  9. Traffic Metrics
    • Current rate
    • Average rate
    • Maximum rate
  10. Units
    • kbit/s
    • Mbit/s
  11. Refresh Interval
    nload -t 500
    (refresh every 500ms)
  12. Show Multiple Interfaces
    nload eth0 wlan0
  13. Hide Traffic Bars
    nload -u h
  14. DevOps Use Cases
    • Quick server bandwidth check
    • Monitor deployments
  15. Security Use Cases
    • Detect unusual traffic spikes
    • Identify possible attacks
  16. Cloud Monitoring
    • Check VM traffic usage
    • Detect abnormal outbound traffic
  17. Container Monitoring
    • Monitor container network load
    • Check microservice communication spikes
  18. nload vs iftop
    Feature nload iftop
    View Graph Connections
    Detail Basic Detailed
  19. Common Issues
    • No traffic shown → wrong interface
    • Misleading spikes → short bursts
  20. Combine with Other Tools
    • nload → overall traffic
    • iftop → per-connection traffic
    • tcpdump → packet-level
  21. Troubleshooting Workflow
    Run nload
Observe spikes
Switch interface
Use iftop for details
Use tcpdump for deep analysis
  22. Golden Debug Rule
    Traffic spike → investigate source immediately
  23. Best Practices
    • Use nload for quick checks
    • Combine with detailed tools
    • Monitor regularly
  24. Real-World Example
    • Server slow → high outgoing traffic spike
    • Deployment → sudden incoming traffic
    • DDoS attack → continuous high inbound traffic
  25. Summary
    nload provides a simple and visual way to monitor real-time network traffic, making it ideal for quick diagnostics and traffic observation.
Completion check: You should now be able to visually monitor network traffic using nload.

Goal: Learn how to track and analyze long-term network usage statistics using vnStat for monitoring and capacity planning.

  1. What is vnStat
    vnStat is a network traffic monitor that logs bandwidth usage over time.
    • Tracks historical data
    • Lightweight and efficient
  2. Why vnStat is Important
    • Monitor long-term usage
    • Detect trends and patterns
    • Capacity planning
  3. Install vnStat
    sudo apt install vnstat
  4. Start vnStat Service
    systemctl start vnstat
systemctl enable vnstat
  5. Initialize Interface
    vnstat -u -i eth0
  6. Check Summary
    vnstat
  7. Hourly Statistics
    vnstat -h
  8. Daily Statistics
    vnstat -d
  9. Monthly Statistics
    vnstat -m
  10. Top Traffic Days
    vnstat -t
  11. Live Traffic (vnstat + real-time)
    vnstat -l
  12. Specific Interface
    vnstat -i eth0
  13. Reset Database
    vnstat --remove -i eth0
  14. Database Location
    /var/lib/vnstat/
  15. Graph Output (Optional)
    vnstat -hg
  16. Difference from Other Tools
    • iftop → real-time connections
    • nload → visual live traffic
    • vnstat → historical tracking
  17. Interpretation
    • High daily usage → heavy traffic load
    • Consistent growth → scaling needed
  18. DevOps Use Cases
    • Monitor server bandwidth over time
    • Plan infrastructure scaling
  19. Cloud Monitoring
    • Track data transfer costs
    • Monitor egress traffic
  20. Security Use Cases
    • Detect unusual traffic spikes
    • Identify data exfiltration patterns
  21. Container Monitoring
    • Monitor host-level traffic
    • Analyze long-term service usage
  22. Common Issues
    • No data → not initialized
    • Wrong interface selected
  23. Combine with Other Tools
    • vnstat → history
    • iftop → live connections
    • tcpdump → packet analysis
  24. Troubleshooting Workflow
    Check vnstat data
Identify spikes
Use iftop for live traffic
Use tcpdump for deep analysis
  25. Golden Debug Rule
    Trend over time reveals real problems
  26. Best Practices
    • Run vnstat continuously
    • Monitor trends regularly
    • Combine with alerting tools
  27. Real-World Example
    • Monthly spike → billing issue
    • Gradual increase → scaling needed
    • Unexpected usage → possible security issue
  28. Summary
    vnStat provides long-term network usage statistics, helping engineers monitor trends, optimize performance, and plan infrastructure effectively.
Completion check: You should now be able to track and analyze long-term network usage using vnStat.
