Linux Networking - IP & Routing

•server

Goal: Understand how to manually assign IP addresses using the ip command, including configuration, verification, and troubleshooting.

  1. What is Manual IP Assignment
    Manual IP assignment means configuring an IP address directly on a network interface using system commands instead of DHCP.
  2. Why Manual IP is Used
    • Servers require fixed IPs
    • Testing network configurations
    • Troubleshooting DHCP issues
    • Static infrastructure setup
  3. ip Command Overview
    The ip command is used to manage networking in Linux.
    For IP assignment:
    ip addr add
  4. Basic Syntax
    ip addr add <IP_ADDRESS>/<CIDR> dev <INTERFACE>
  5. Example Command
    ip addr add 192.168.1.100/24 dev eth0
  6. Understanding the Command
    • 192.168.1.100: IP address
    • /24: Subnet mask (255.255.255.0)
    • eth0: Interface name
  7. Checking Assigned IP
    ip addr show eth0
  8. Removing IP Address
    ip addr del 192.168.1.100/24 dev eth0
  9. Assigning Multiple IPs
    ip addr add 192.168.1.101/24 dev eth0
    Interfaces can have multiple IPs.
  10. Bringing Interface Up
    ip link set eth0 up
  11. Assigning Gateway (Routing)
    ip route add default via 192.168.1.1
  12. Verifying Connectivity
    ping 192.168.1.1
ping 8.8.8.8
  13. Temporary Configuration
    Changes made using ip are temporary and lost after reboot.
  14. Manual vs DHCP
    Type Behavior
    Manual Static, fixed IP
    DHCP Dynamic, automatic
  15. IPv6 Assignment
    ip addr add 2001:db8::1/64 dev eth0
  16. Real-World Use Case
    • Assign static IP to server
    • Configure test environment
    • Fix broken DHCP setup
  17. Use in Containers
    • Containers get IP automatically
    • Manual assignment used for debugging
  18. Use in Cloud
    • Instances usually use DHCP
    • Static IP configured via cloud settings
  19. Common Mistakes
    • Wrong subnet
    • Missing gateway
    • Interface down
  20. Troubleshooting Steps
    ip addr
ip route
ping gateway
  21. Best Practices
    • Use static IP for servers
    • Verify configuration after assignment
    • Use persistent config for production
  22. Summary
    Manual IP assignment using the ip command is a powerful way to configure network interfaces, especially for testing, troubleshooting, and server setup.
Completion check: You should now understand how to manually assign, verify, and manage IP addresses using the ip command.

Goal: Understand the differences between static and dynamic IP addresses, how they work, and when to use each in real-world systems.

  1. What is an IP Address
    An IP address uniquely identifies a device in a network and enables communication between systems.
  2. Types of IP Assignment
    • Static IP Address
    • Dynamic IP Address
  3. What is a Static IP Address
    A static IP is manually assigned to a device and does not change unless modified by an administrator.
  4. Characteristics of Static IP
    • Fixed and permanent
    • Configured manually
    • Used for servers and infrastructure
  5. What is a Dynamic IP Address
    A dynamic IP is automatically assigned by a DHCP server and can change over time.
  6. Characteristics of Dynamic IP
    • Automatically assigned
    • Changes periodically
    • Used for client devices
  7. How Dynamic IP Works
    DHCP assigns IP using: 
    Discover → Offer → Request → Acknowledge
  8. Static IP Configuration Example
    ip addr add 192.168.1.100/24 dev eth0
  9. Dynamic IP Configuration
    dhclient eth0
  10. Static vs Dynamic Comparison
    Feature Static IP Dynamic IP
    Assignment Manual Automatic (DHCP)
    Change Fixed Can change
    Use Case Servers Clients
  11. Advantages of Static IP
    • Stable and predictable
    • Required for servers
    • Easy remote access
  12. Disadvantages of Static IP
    • Manual configuration required
    • Risk of IP conflicts
  13. Advantages of Dynamic IP
    • Automatic management
    • No manual setup needed
    • Efficient IP utilization
  14. Disadvantages of Dynamic IP
    • IP may change
    • Not suitable for servers
  15. DHCP Reservation (Hybrid)
    Assigns fixed IP via DHCP based on MAC address.
  16. Use Cases
    • Static → Web servers, databases
    • Dynamic → Laptops, mobile devices
  17. Static IP in Cloud
    • Elastic IP (AWS)
    • Reserved IP (GCP/Azure)
  18. Dynamic IP in Cloud
    • Assigned at instance startup
    • May change after restart
  19. Containers and IPs
    • Containers use dynamic IPs
    • Service discovery used instead of static IP
  20. Common Issues
    • IP conflict (static misconfiguration)
    • DHCP failure
    • Wrong subnet
  21. Troubleshooting
    ip addr
dhclient
ip route
  22. Best Practices
    • Use static IP for servers
    • Use DHCP for clients
    • Use DHCP reservation when needed
  23. Real-World Example
    • Web server → Static IP
    • Laptop → Dynamic IP from router
  24. Summary
    Static IPs provide stability and are used for servers, while dynamic IPs offer flexibility and automation using DHCP.
Completion check: You should now understand static and dynamic IP addressing and when to use each in real-world systems.

Goal: Understand what a default gateway is, how it works, and how it enables communication between local networks and external networks like the internet.

  1. What is a Default Gateway
    A default gateway is the device (usually a router) that forwards traffic from a local network to external networks.
  2. Why Default Gateway is Needed
    • Allows access to internet
    • Routes traffic outside local network
    • Acts as exit point for all external communication
  3. Basic Concept
    If a destination IP is not in the local network: 
    Send packet → Default Gateway → Internet
  4. Example Network
    Device IP:       192.168.1.10
Gateway IP:      192.168.1.1
Destination:     8.8.8.8
  5. How Default Gateway Works
    1 → Device checks destination IP
2 → Not in local subnet
3 → Sends packet to gateway
4 → Router forwards to internet
  6. Local vs External Communication
    • Local: Direct communication
    • External: Uses gateway
  7. Subnet Role in Gateway Decision
    Subnet determines if destination is local: 
    192.168.1.10/24 → Local range: 192.168.1.0–255
  8. Viewing Default Gateway
    ip route
    Example output:
    default via 192.168.1.1 dev eth0
  9. Adding Default Gateway
    ip route add default via 192.168.1.1
  10. Deleting Default Gateway
    ip route del default
  11. Multiple Gateways
    Systems can have multiple routes with priorities (metrics).
  12. Gateway in DHCP
    DHCP automatically assigns default gateway to clients.
  13. Gateway vs Router
    • Gateway → Concept
    • Router → Device implementing gateway
  14. Real-World Example
    • Home router → default gateway
    • Cloud VPC router → default gateway
  15. Testing Gateway Connectivity
    ping 192.168.1.1
  16. Common Issues
    • No internet access
    • Wrong gateway configured
    • Gateway unreachable
  17. Troubleshooting Steps
    ip addr
ip route
ping gateway
ping 8.8.8.8
  18. Default Gateway in Containers
    • Docker bridge acts as gateway
    • Containers route through host
  19. Default Gateway in Cloud
    • Defined in VPC routing table
    • Internet Gateway used for outbound traffic
  20. Advanced Routing Concept
    • Default route = 0.0.0.0/0
    • Catch-all route for unknown destinations
  21. Security Considerations
    • Gateway controls outbound traffic
    • Firewalls often placed at gateway
  22. Best Practices
    • Always verify gateway configuration
    • Use consistent network design
    • Monitor gateway availability
  23. Summary
    The default gateway enables communication between local networks and external networks by routing traffic to appropriate destinations.
Completion check: You should now understand how the default gateway works and how it enables internet connectivity.

Goal: Understand routing tables, how packets are forwarded, and how to configure and troubleshoot routing in Linux systems.

  1. What is a Routing Table
    A routing table is a set of rules used by a system to determine where to send network packets.
  2. Why Routing Tables are Important
    • Determine packet path
    • Enable communication between networks
    • Core of internet routing
  3. Basic Concept
    When sending data: 
    Check routing table → Select route → Forward packet
  4. Viewing Routing Table
    ip route
  5. Example Output
    default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0 proto kernel
  6. Understanding Routing Table Fields
    • Destination: Target network
    • Gateway: Next hop
    • Interface: Outgoing interface
  7. Types of Routes
    • Direct Route: Local network
    • Default Route: External networks
    • Static Route: Manually added
  8. Default Route
    default via 192.168.1.1
    Used when no specific route matches.
  9. Network Route
    192.168.1.0/24 dev eth0
  10. Adding a Route
    ip route add 10.0.0.0/24 via 192.168.1.1
  11. Deleting a Route
    ip route del 10.0.0.0/24
  12. Route Selection Process
    • Longest prefix match wins
    • More specific routes preferred
  13. Routing Metrics
    Used to prioritize routes: 
    metric 100
  14. Packet Flow Example
    Destination: 8.8.8.8
→ Not local
→ Use default route
→ Send to gateway
  15. Static vs Dynamic Routing
    Type Description
    Static Manually configured
    Dynamic Learned automatically (routing protocols)
  16. Routing in Linux
    Commands: 
    ip route
route -n
  17. Routing in Containers
    • Containers have their own routing table
    • Default route via bridge
  18. Routing in Cloud
    • VPC route tables
    • Internet gateway routes
    • Private vs public routing
  19. Policy-Based Routing (Advanced)
    Allows routing based on:
    • Source IP
    • Interface
    • Traffic type
  20. Common Issues
    • No route to host
    • Wrong gateway
    • Missing route
  21. Troubleshooting Steps
    ip route
ip addr
ping gateway
traceroute 8.8.8.8
  22. Real-World Example
    • Server sends request → routing table decides path
    • Router forwards packet → reaches destination
  23. Best Practices
    • Keep routing simple
    • Validate routes after changes
    • Use proper subnetting
  24. Summary
    Routing tables define how packets are forwarded between networks, making them the backbone of communication across systems and the internet.
Completion check: You should now understand routing tables, route configuration, and packet forwarding in Linux.

Goal: Understand how to add, modify, and remove routes using the ip route command to control network traffic flow in Linux systems.

  1. What is Route Management
    Route management involves adding or removing routing rules that define how network traffic is forwarded.
  2. Why Route Management is Important
    • Control traffic flow between networks
    • Enable communication across subnets
    • Fix routing issues
    • Support complex network setups
  3. Viewing Current Routes
    ip route
  4. Basic Route Add Syntax
    ip route add <DESTINATION> via <GATEWAY>
  5. Example: Add Network Route
    ip route add 10.0.0.0/24 via 192.168.1.1
  6. Example: Add Host Route
    ip route add 10.0.0.5 via 192.168.1.1
  7. Adding Default Route
    ip route add default via 192.168.1.1
  8. Route Without Gateway
    Direct route: 
    ip route add 192.168.2.0/24 dev eth0
  9. Specifying Interface
    ip route add 10.0.0.0/24 dev eth0
  10. Adding Route with Metric
    ip route add 10.0.0.0/24 via 192.168.1.1 metric 100
  11. Deleting Route
    ip route del 10.0.0.0/24
  12. Deleting Default Route
    ip route del default
  13. Replacing Route
    ip route replace 10.0.0.0/24 via 192.168.1.2
  14. Route Selection Logic
    • Longest prefix match
    • Lowest metric wins
  15. Temporary vs Persistent Routes
    • Temporary: Using ip command
    • Persistent: Configured in network config files
  16. Real-World Use Case
    • Access another subnet via router
    • Configure multi-network servers
    • Set custom routing paths
  17. Routing in Containers
    • Each container has its own routes
    • Default route points to bridge
  18. Routing in Cloud
    • Routes defined in VPC route tables
    • Used for internet and private traffic
  19. Advanced Routing
    • Multiple routing tables
    • Policy-based routing
  20. Common Errors
    • Network unreachable
    • No route to host
    • Invalid gateway
  21. Troubleshooting
    ip route
ip addr
ping gateway
traceroute destination
  22. Security Considerations
    • Avoid incorrect routing paths
    • Prevent traffic leaks
  23. Best Practices
    • Verify routes after adding
    • Use meaningful subnet design
    • Avoid overlapping routes
  24. Summary
    Route management allows precise control over how traffic flows between networks, making it essential for advanced networking and troubleshooting.
Completion check: You should now understand how to add, remove, and manage routes using ip route commands.

Goal: Understand policy-based routing, how it differs from traditional routing, and how to control traffic using rules and multiple routing tables.

  1. What is Policy-Based Routing (PBR)
    Policy-based routing allows routing decisions based on rules such as source IP, interface, or traffic type instead of only destination IP.
  2. Why PBR is Needed
    • Multiple network interfaces
    • Different gateways for different traffic
    • Advanced traffic control
    • VPN routing
  3. Traditional vs Policy Routing
    Type Behavior
    Traditional Based on destination IP
    PBR Based on rules (source, interface, etc.)
  4. Key Components of PBR
    • Routing Tables
    • Rules
    • Selectors (source, destination, interface)
  5. Multiple Routing Tables
    Linux supports multiple routing tables: 
    /etc/iproute2/rt_tables
  6. Example Routing Table Entry
    100 custom_table
  7. Adding Route to Custom Table
    ip route add default via 192.168.1.1 table custom_table
  8. Adding Policy Rule
    ip rule add from 192.168.1.100 table custom_table
  9. How PBR Works
    1 → Packet arrives
2 → System checks rules
3 → Matching rule selects routing table
4 → Route is applied
  10. Viewing Rules
    ip rule show
  11. Viewing Table Routes
    ip route show table custom_table
  12. Deleting Rule
    ip rule del from 192.168.1.100
  13. Use Case: Multiple ISPs
    • Traffic from interface A → ISP1
    • Traffic from interface B → ISP2
  14. Use Case: Source-Based Routing
    Route traffic differently based on source IP.
  15. Use Case: VPN Routing
    • Specific traffic routed through VPN
    • Other traffic via normal gateway
  16. Interface-Based Routing
    ip rule add iif eth1 table custom_table
  17. Mark-Based Routing (Advanced)
    Uses firewall marks: 
    iptables -t mangle -A PREROUTING -j MARK
  18. Routing Priority
    Rules have priorities: 
    ip rule add priority 100
  19. Default Rules
    Linux has built-in rules: 
    0 → local
32766 → main
32767 → default
  20. Persistence of PBR
    Must be configured in:
    • Netplan
    • Network scripts
  21. PBR in Containers
    • Used in advanced networking setups
    • Managed by CNI plugins
  22. PBR in Cloud
    • Simulated using route tables and policies
    • Used for traffic segmentation
  23. Common Issues
    • Rules not matching
    • Wrong routing table
    • Priority conflicts
  24. Troubleshooting
    ip rule
ip route show table all
ip addr
  25. Best Practices
    • Keep rules simple
    • Use clear table naming
    • Document configurations
  26. Summary
    Policy-based routing enables advanced traffic control by allowing routing decisions based on rules rather than just destination IP, making it essential for complex networking environments.
Completion check: You should now understand policy-based routing, rule configuration, and advanced traffic control in Linux.
