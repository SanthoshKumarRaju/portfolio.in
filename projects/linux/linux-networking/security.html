Linux Networking - Interfaces

•server

Goal: Understand how firewalls control network traffic, how packet filtering works in Linux, and how to configure and troubleshoot firewall rules in real-world environments.

  1. What is a Firewall
    A firewall is a system that monitors and controls incoming and outgoing network traffic.
    • Acts as a security barrier
    • Filters packets based on rules
  2. Why Firewalls are Important
    • Prevent unauthorized access
    • Protect servers and applications
    • Control network traffic
  3. Types of Firewalls
    • Packet filtering firewall
    • Stateful firewall
    • Application-level firewall
  4. Linux Firewall Stack
    • Netfilter → Kernel-level engine
    • iptables → Traditional tool
    • nftables → Modern replacement
    • firewalld → High-level manager
  5. Packet Flow in Linux
    Incoming → PREROUTING → INPUT → Application
Outgoing → OUTPUT → POSTROUTING
Forwarded → PREROUTING → FORWARD → POSTROUTING
  6. Firewall Chains
    • INPUT → Incoming traffic
    • OUTPUT → Outgoing traffic
    • FORWARD → Routed traffic
  7. Rule Actions
    • ACCEPT → Allow traffic
    • DROP → Block silently
    • REJECT → Block with response
  8. Basic iptables Command
    iptables -L
  9. Allow Traffic Example
    iptables -A INPUT -p tcp --dport 22 -j ACCEPT
  10. Block Traffic Example
    iptables -A INPUT -p tcp --dport 80 -j DROP
  11. Stateful Firewall
    iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
  12. NAT (Network Address Translation)
    • SNAT → Change source IP
    • DNAT → Change destination IP
  13. Port Forwarding
    iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to 192.168.1.10
  14. MASQUERADE
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
  15. firewalld Overview
    High-level firewall management tool.
  16. Check firewalld
    firewall-cmd --list-all
  17. Open Port (firewalld)
    firewall-cmd --add-port=80/tcp --permanent
firewall-cmd --reload
  18. Zones in firewalld
    • public
    • private
    • trusted
  19. nftables Basics
    nft list ruleset
  20. Advanced Concepts
    • Connection tracking
    • Rate limiting
    • Logging
  21. Rate Limiting Example
    iptables -A INPUT -p tcp --dport 22 -m limit --limit 5/min -j ACCEPT
  22. Logging Packets
    iptables -A INPUT -j LOG --log-prefix "Dropped: "
  23. Firewall in DevOps
    • Secure APIs
    • Restrict microservices
    • Protect infrastructure
  24. Firewall in Containers
    • Docker uses iptables
    • Bridge networking
  25. Firewall in Kubernetes
    • Network policies
    • Pod-level security
  26. Firewall in Cloud
    • Security Groups
    • Network ACLs
  27. Common Issues
    • Port blocked
    • Wrong rule order
    • Service unreachable
  28. Troubleshooting Workflow
    Check service (systemctl)
Check port (ss -tuln)
Check firewall rules
Test (curl / nc)
  29. Best Practices
    • Least privilege access
    • Log critical traffic
    • Avoid open-all rules
  30. Real-World Example
    • Web app down → port 80 blocked
    • SSH attack → rate limit applied
    • API security → restrict IP range
  31. Summary
    Firewalls are essential for controlling network traffic and securing systems. Mastering iptables, firewalld, and nftables enables complete control over network security in Linux environments.

Goal: Master iptables for configuring firewall rules, controlling traffic, implementing NAT, and debugging real-world networking issues.

  1. What is iptables
    iptables is a command-line tool used to configure the Linux kernel firewall (Netfilter).
    • Controls packet filtering
    • Defines firewall rules
  2. Why iptables is Important
    • Core of Linux networking security
    • Used by Docker, Kubernetes, cloud systems
    • Fine-grained traffic control
  3. iptables Architecture
    • Tables → filter, nat, mangle
    • Chains → INPUT, OUTPUT, FORWARD
    • Rules → match + action
  4. Tables Overview
    • filter → Packet filtering (default)
    • nat → Address translation
    • mangle → Packet modification
  5. Chains Overview
    • INPUT → Incoming packets
    • OUTPUT → Outgoing packets
    • FORWARD → Routed packets
  6. Basic Command
    iptables -L
    Lists all rules.
  7. Default Policy
    iptables -P INPUT DROP
  8. Add Rule
    iptables -A INPUT -p tcp --dport 22 -j ACCEPT
  9. Delete Rule
    iptables -D INPUT -p tcp --dport 22 -j ACCEPT
  10. Allow All Loopback Traffic
    iptables -A INPUT -i lo -j ACCEPT
  11. Allow Established Connections
    iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
  12. Block Specific IP
    iptables -A INPUT -s 192.168.1.50 -j DROP
  13. Allow Specific Port
    iptables -A INPUT -p tcp --dport 80 -j ACCEPT
  14. Reject Traffic
    iptables -A INPUT -p tcp --dport 443 -j REJECT
  15. NAT Table Usage
    iptables -t nat -L
  16. Port Forwarding (DNAT)
    iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to 192.168.1.10:80
  17. Masquerading (SNAT)
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
  18. Rate Limiting
    iptables -A INPUT -p tcp --dport 22 -m limit --limit 5/min -j ACCEPT
  19. Logging
    iptables -A INPUT -j LOG --log-prefix "IPTables-Dropped: "
  20. Save Rules
    iptables-save > /etc/iptables.rules
  21. Restore Rules
    iptables-restore < /etc/iptables.rules
  22. Rule Order Importance
    Rules are processed top to bottom.
  23. Check Packet Counters
    iptables -L -v
  24. Advanced Concepts
    • Connection tracking
    • Packet marking
    • Custom chains
  25. Create Custom Chain
    iptables -N MYCHAIN
iptables -A INPUT -j MYCHAIN
  26. iptables in Docker
    • Docker automatically creates rules
    • Handles container networking
  27. iptables in Kubernetes
    • Used by kube-proxy
    • Handles service routing
  28. iptables in Cloud
    • Works alongside security groups
    • Controls instance-level traffic
  29. Common Issues
    • Wrong rule order
    • Blocked SSH access
    • NAT misconfiguration
  30. Troubleshooting Workflow
    Check rules → iptables -L -v
Check ports → ss -tuln
Check logs → journalctl
Test → curl / nc
  31. Best Practices
    • Allow loopback and established connections
    • Use DROP as default policy
    • Log important traffic
  32. Real-World Example
    • Web server → allow 80/443 only
    • SSH secure → restrict IP access
    • NAT gateway → enable internet access
  33. Summary
    iptables is a powerful firewall tool that provides fine-grained control over network traffic, enabling secure, scalable, and production-ready networking configurations.
Completion check: You should now be able to configure, manage, and debug firewall rules using iptables in real-world environments.

Goal: Master nftables for modern Linux firewall management, including rule creation, NAT, performance optimization, and real-world debugging.

  1. What is nftables
    nftables is the modern replacement for iptables in Linux.
    • Unified firewall framework
    • Replaces iptables, ip6tables, arptables
  2. Why nftables is Important
    • Better performance
    • Simpler syntax
    • Unified IPv4 and IPv6 handling
  3. nftables Architecture
    • Tables → containers for rules
    • Chains → processing points
    • Rules → match + action
    • Sets → efficient filtering
  4. Check nftables Status
    nft list ruleset
  5. Create Table
    nft add table inet myfilter
  6. Create Chain
    nft add chain inet myfilter input { type filter hook input priority 0 \; }
  7. Add Rule
    nft add rule inet myfilter input tcp dport 22 accept
  8. Block Traffic
    nft add rule inet myfilter input tcp dport 80 drop
  9. Allow Established Connections
    nft add rule inet myfilter input ct state established,related accept
  10. Default Policy
    nft add chain inet myfilter input { type filter hook input priority 0 \; policy drop \; }
  11. List Rules
    nft list ruleset
  12. Delete Rule
    nft delete rule inet myfilter input handle 5
  13. NAT Configuration
    nft add table ip nat
  14. Port Forwarding
    nft add rule ip nat prerouting tcp dport 80 dnat to 192.168.1.10:80
  15. Masquerading
    nft add rule ip nat postrouting oif eth0 masquerade
  16. Sets (Powerful Feature)
    nft add set inet myfilter blacklist { type ipv4_addr \; }
nft add rule inet myfilter input ip saddr @blacklist drop
  17. Rate Limiting
    nft add rule inet myfilter input tcp dport 22 limit rate 5/minute accept
  18. Logging
    nft add rule inet myfilter input log prefix "Dropped: "
  19. Persistent Configuration
    /etc/nftables.conf
  20. Apply Config
    nft -f /etc/nftables.conf
  21. iptables vs nftables
    Feature iptables nftables
    Syntax Complex Simple
    Performance Lower Higher
    IPv4/IPv6 Separate Unified
  22. Advanced Concepts
    • Stateful filtering (conntrack)
    • Packet classification
    • Flowtables (hardware acceleration)
  23. nftables in Docker
    • Replacing iptables backend
    • Improves container networking performance
  24. nftables in Kubernetes
    • Future replacement for iptables mode
    • Better scalability
  25. nftables in Cloud
    • Instance-level firewall
    • Works with security groups
  26. Common Issues
    • Rule not applied
    • Wrong chain hook
    • NAT misconfiguration
  27. Debugging
    nft list ruleset
journalctl -u nftables
  28. Troubleshooting Workflow
    Check rules → nft list ruleset
Check ports → ss -tuln
Test → curl / nc
Verify NAT
  29. Best Practices
    • Use sets for performance
    • Keep rules simple and readable
    • Use persistent configs
  30. Real-World Example
    • Web server → allow 80/443
    • SSH protection → rate limit
    • Cloud VM → secure inbound traffic
  31. Summary
    nftables is the modern, efficient, and scalable firewall system in Linux, replacing iptables and providing better performance and flexibility for modern infrastructure.
Completion check: You should now understand how to configure and manage firewall rules using nftables in modern Linux environments.

Goal: Learn how to use UFW to configure and manage firewall rules easily in Ubuntu systems, including advanced usage and troubleshooting.

  1. What is UFW
    UFW (Uncomplicated Firewall) is a user-friendly interface for managing firewall rules in Ubuntu.
    • Built on top of iptables
    • Simplifies firewall configuration
  2. Why UFW is Important
    • Easy to use
    • Quick setup for servers
    • Reduces complexity of iptables
  3. Install UFW
    sudo apt install ufw
  4. Check Status
    ufw status
  5. Enable UFW
    ufw enable
  6. Disable UFW
    ufw disable
  7. Default Policies
    ufw default deny incoming
ufw default allow outgoing
  8. Allow a Port
    ufw allow 80
  9. Allow Specific Protocol
    ufw allow 22/tcp
  10. Allow Specific IP
    ufw allow from 192.168.1.100
  11. Allow IP to Port
    ufw allow from 192.168.1.100 to any port 22
  12. Deny a Port
    ufw deny 80
  13. Delete Rule
    ufw delete allow 80
  14. List Rules with Numbers
    ufw status numbered
  15. Delete by Number
    ufw delete 1
  16. Application Profiles
    ufw app list
ufw allow "Nginx Full"
  17. Enable Logging
    ufw logging on
  18. Log Location
    /var/log/ufw.log
  19. Advanced: Rate Limiting (SSH)
    ufw limit 22/tcp
  20. Advanced: Allow Range of Ports
    ufw allow 1000:2000/tcp
  21. Advanced: IPv6 Support
    Enabled in: 
    /etc/default/ufw
  22. Reload Firewall
    ufw reload
  23. UFW vs iptables
    Feature UFW iptables
    Ease of Use Easy Complex
    Control Limited Full
  24. UFW Internals
    • Uses iptables backend
    • Stores rules in config files
  25. Use in DevOps
    • Quick server security setup
    • Automated provisioning scripts
  26. Use in Cloud
    • Extra layer beyond security groups
    • Protect instance-level access
  27. Use in Containers
    • Used on host level
    • Works with Docker networking
  28. Common Issues
    • SSH locked out
    • Port blocked unintentionally
    • Rules not applied
  29. Debugging
    ufw status verbose
journalctl -u ufw
  30. Troubleshooting Workflow
    Check rules → ufw status
Check ports → ss -tuln
Check logs → /var/log/ufw.log
Test → curl / nc
  31. Best Practices
    • Always allow SSH before enabling
    • Use deny by default
    • Enable logging
  32. Real-World Example
    • Web server → allow 80, 443
    • SSH security → limit access
    • API server → restrict IP ranges
  33. Summary
    UFW provides a simple and efficient way to manage firewall rules in Ubuntu, making it ideal for quick setup, basic security, and DevOps environments.
Completion check: You should now be able to configure and manage firewall rules easily using UFW in Ubuntu systems.

Goal: Master firewalld to manage firewall rules dynamically in enterprise Linux systems, including zones, services, advanced configurations, and troubleshooting.

  1. What is firewalld
    firewalld is a dynamic firewall management tool used in RHEL-based systems.
    • Built on top of nftables/iptables
    • Supports runtime and permanent configurations
  2. Why firewalld is Important
    • Used in enterprise environments
    • Dynamic rule updates without restart
    • Zone-based security model
  3. Check firewalld Status
    systemctl status firewalld
  4. Start / Stop firewalld
    systemctl start firewalld
systemctl stop firewalld
  5. Enable firewalld
    systemctl enable firewalld
  6. Check Active Zones
    firewall-cmd --get-active-zones
  7. List All Settings
    firewall-cmd --list-all
  8. What are Zones
    Zones define trust levels for network connections.
    • public → untrusted
    • private → internal network
    • trusted → full access
  9. List Available Zones
    firewall-cmd --get-zones
  10. Set Default Zone
    firewall-cmd --set-default-zone=public
  11. Assign Interface to Zone
    firewall-cmd --zone=public --add-interface=eth0
  12. Open a Port (Runtime)
    firewall-cmd --add-port=80/tcp
  13. Open a Port (Permanent)
    firewall-cmd --add-port=80/tcp --permanent
firewall-cmd --reload
  14. Remove Port
    firewall-cmd --remove-port=80/tcp --permanent
  15. Allow Services
    firewall-cmd --add-service=http --permanent
  16. List Services
    firewall-cmd --get-services
  17. Rich Rules (Advanced)
    firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.1.100" accept'
  18. Masquerading (NAT)
    firewall-cmd --add-masquerade --permanent
  19. Port Forwarding
    firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080
  20. Runtime vs Permanent
    • Runtime → temporary
    • Permanent → saved after reboot
  21. Reload Configuration
    firewall-cmd --reload
  22. Direct Rules (Low-Level)
    firewall-cmd --direct --add-rule ipv4 filter INPUT 0 -p tcp --dport 22 -j ACCEPT
  23. firewalld vs iptables
    Feature firewalld iptables
    Type Dynamic Static
    Ease Easy Complex
  24. firewalld vs nftables
    • firewalld → management layer
    • nftables → backend engine
  25. Use in DevOps
    • Automate firewall rules
    • Secure microservices
  26. Use in Cloud
    • Instance-level firewall
    • Works with security groups
  27. Use in Containers
    • Controls host-level traffic
    • Works with container networking
  28. Common Issues
    • Port not accessible
    • Wrong zone assigned
    • Runtime vs permanent confusion
  29. Debugging
    firewall-cmd --list-all
journalctl -u firewalld
  30. Troubleshooting Workflow
    Check service → systemctl status
Check zone → firewall-cmd --get-active-zones
Check ports → ss -tuln
Test → curl / nc
  31. Best Practices
    • Use zones effectively
    • Use services instead of ports
    • Always reload after permanent changes
  32. Real-World Example
    • Web server → allow http/https services
    • Internal network → use private zone
    • Production → restrict access via rich rules
  33. Summary
    firewalld is a powerful and flexible firewall manager widely used in enterprise Linux systems, providing dynamic rule management and zone-based security.

Goal: Understand NAT concepts, types, packet flow, and how to configure and debug NAT in Linux and real-world environments.

  1. What is NAT
    NAT (Network Address Translation) allows private IP addresses to communicate with external networks using a public IP.
    • Translates private IP → public IP
    • Used in routers, cloud, containers
  2. Why NAT is Important
    • Conserves IPv4 addresses
    • Enables internet access for private networks
    • Adds a layer of security
  3. Private vs Public IP
    • Private → 192.168.x.x, 10.x.x.x
    • Public → Internet-routable IP
  4. Basic NAT Flow
    Client (192.168.1.10) → Router → Internet
Translated to → Public IP (1.2.3.4)
  5. Types of NAT
    • SNAT (Source NAT)
    • DNAT (Destination NAT)
    • PAT (Port Address Translation)
  6. SNAT (Source NAT)
    Changes source IP for outgoing traffic.
  7. DNAT (Destination NAT)
    Changes destination IP for incoming traffic.
  8. PAT (Port Address Translation)
    Multiple clients share one public IP using ports.
  9. Linux NAT Table
    iptables -t nat -L
  10. Enable IP Forwarding
    echo 1 > /proc/sys/net/ipv4/ip_forward
  11. SNAT Example (Internet Access)
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
  12. DNAT Example (Port Forwarding)
    iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to 192.168.1.10:80
  13. Packet Flow with NAT
    Incoming → PREROUTING (DNAT)
Outgoing → POSTROUTING (SNAT)
  14. MASQUERADE vs SNAT
    • MASQUERADE → Dynamic IP
    • SNAT → Static IP
  15. nftables NAT Example
    nft add rule ip nat postrouting oif eth0 masquerade
  16. NAT in Home Networks
    • Router assigns private IPs
    • Uses one public IP for internet
  17. NAT in Cloud
    • NAT Gateway in AWS
    • Private subnets access internet
  18. NAT in Docker
    • Bridge network uses NAT
    • Container → host → internet
  19. NAT in Kubernetes
    • Cluster networking uses NAT
    • Service routing via iptables
  20. Common Issues
    • No internet access
    • Port forwarding not working
    • IP forwarding disabled
  21. Debug NAT Issues
    iptables -t nat -L -v
sysctl net.ipv4.ip_forward
ss -tuln
  22. Test NAT
    curl ifconfig.me
  23. Troubleshooting Workflow
    Check IP forwarding
Check NAT rules
Check firewall rules
Test connectivity
  24. Security Considerations
    • NAT is not a firewall
    • Use firewall with NAT
  25. Performance Considerations
    • High traffic → CPU load
    • Use connection tracking efficiently
  26. Best Practices
    • Enable IP forwarding properly
    • Use MASQUERADE for dynamic IPs
    • Monitor NAT traffic
  27. Real-World Example
    • Home router → NAT for internet
    • Cloud private subnet → NAT gateway
    • Docker container → NAT networking
  28. Summary
    NAT enables communication between private and public networks, making it essential for modern networking, cloud infrastructure, and containerized environments.
Completion check: You should now understand NAT types, configuration, and real-world usage across Linux, cloud, and container environments.

Goal: Understand port forwarding, how traffic is redirected, and how to configure and debug it in Linux, cloud, and container environments.

  1. What is Port Forwarding
    Port forwarding redirects incoming network traffic from one port to another.
    • External request → redirected internally
    • Common in NAT environments
  2. Why Port Forwarding is Important
    • Expose internal services to external users
    • Used in web servers, APIs, gaming, SSH
  3. Basic Concept
    Public IP:80 → Private IP:8080
  4. How It Works
    • Client sends request to public IP
    • Router/firewall rewrites destination
    • Traffic forwarded to internal server
  5. Types of Port Forwarding
    • Local port forwarding
    • Remote port forwarding
    • Dynamic forwarding (SOCKS)
  6. Enable IP Forwarding
    echo 1 > /proc/sys/net/ipv4/ip_forward
  7. iptables Port Forwarding
    iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to 192.168.1.10:8080
  8. Allow Forwarding Traffic
    iptables -A FORWARD -p tcp -d 192.168.1.10 --dport 8080 -j ACCEPT
  9. nftables Port Forwarding
    nft add rule ip nat prerouting tcp dport 80 dnat to 192.168.1.10:8080
  10. Port Forwarding with firewalld
    firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080
  11. Port Forwarding with UFW
    Edit: 
    /etc/ufw/before.rules
  12. Port Forwarding in Home Routers
    • Expose internal services
    • Example: access CCTV or web server
  13. Port Forwarding in Cloud
    • Load balancer → backend server
    • Public → private subnet routing
  14. Port Forwarding in Docker
    docker run -p 8080:80 nginx
    Maps host port to container port.
  15. Port Forwarding in Kubernetes
    kubectl port-forward pod/my-pod 8080:80
  16. SSH Port Forwarding
    ssh -L 8080:localhost:80 user@server
  17. Packet Flow
    Client → Public IP:80 → DNAT → Internal IP:8080
  18. Common Issues
    • Port not accessible
    • Firewall blocking traffic
    • IP forwarding disabled
  19. Debugging
    iptables -t nat -L -v
ss -tuln
netstat -tuln
  20. Test Port Forwarding
    curl http://public-ip
  21. Troubleshooting Workflow
    Check service running
Check port listening
Check NAT rules
Check firewall
Test externally
  22. Security Considerations
    • Exposes internal services
    • Use firewall + authentication
  23. Performance Considerations
    • High traffic → NAT overhead
    • Use load balancing for scaling
  24. Best Practices
    • Limit access by IP
    • Use non-standard ports if needed
    • Monitor traffic
  25. Real-World Example
    • Expose web server → 80 → 8080
    • Remote DB access → 3306
    • SSH via custom port
  26. Summary
    Port forwarding enables external access to internal services by redirecting traffic, making it essential for web hosting, cloud infrastructure, and containerized applications.
