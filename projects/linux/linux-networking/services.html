Goal: Master SSH for secure remote access, authentication methods, tunneling, automation, and real-world DevOps usage.

  1. What is SSH
    SSH (Secure Shell) is a protocol used for secure remote access to systems over a network.
    • Encrypted communication
    • Replaces insecure protocols like Telnet
  2. Why SSH is Important
    • Secure remote server access
    • Used in DevOps, cloud, automation
    • Supports tunneling and file transfer
  3. SSH Architecture
    • Client → ssh command
    • Server → sshd (daemon)
    • Default port → 22
  4. Basic SSH Command
    ssh user@hostname
  5. SSH with Port
    ssh -p 2222 user@host
  6. SSH Authentication Types
    • Password-based
    • Key-based (recommended)
  7. Generate SSH Key
    ssh-keygen -t rsa -b 4096
  8. Copy Key to Server
    ssh-copy-id user@host
  9. SSH Config File
    ~/.ssh/config
    Example: 
    Host myserver
  HostName 192.168.1.10
  User ubuntu
  Port 22
  10. SSH Server Config
    /etc/ssh/sshd_config
  11. Important SSH Settings
    • PermitRootLogin no
    • PasswordAuthentication no
    • Port 22
  12. Restart SSH Service
    systemctl restart sshd
  13. SSH Port Forwarding (Local)
    ssh -L 8080:localhost:80 user@host
  14. SSH Remote Forwarding
    ssh -R 8080:localhost:80 user@host
  15. Dynamic Port Forwarding (SOCKS)
    ssh -D 1080 user@host
  16. Copy Files (scp)
    scp file.txt user@host:/path/
  17. Sync Files (rsync over SSH)
    rsync -avz file.txt user@host:/path/
  18. SSH Agent
    ssh-agent
ssh-add
  19. SSH in DevOps
    • Remote server management
    • CI/CD deployments
    • Automation scripts
  20. SSH in Cloud
    • AWS EC2 access
    • Azure VM login
  21. SSH in Containers
    • Rare inside containers
    • Used for debugging hosts
  22. Common Issues
    • Connection refused
    • Permission denied
    • Key mismatch
  23. Debug SSH
    ssh -v user@host
  24. Check SSH Service
    systemctl status sshd
  25. Troubleshooting Workflow
    Check service
Check port (ss -tuln)
Check firewall
Check logs (/var/log/auth.log)
  26. Security Best Practices
    • Disable root login
    • Use key-based auth
    • Change default port
    • Use fail2ban
  27. Real-World Example
    • Access cloud VM via SSH
    • Deploy app using SSH scripts
    • Secure internal services via tunnels
  28. Summary
    SSH is a critical tool for secure remote access, automation, and system management, forming the backbone of modern DevOps and cloud operations.
Completion check: You should now be able to securely access, configure, and automate systems using SSH.

Goal: Understand how web servers work, how to configure Nginx and Apache, serve HTTP/HTTPS traffic, and use them in real-world DevOps environments.

  1. What is a Web Server
    A web server is software that serves web content to clients over HTTP/HTTPS.
    • Handles browser requests
    • Returns HTML, CSS, JS, APIs
  2. Popular Web Servers
    • Nginx → High performance, event-driven
    • Apache → Feature-rich, process-based
  3. HTTP vs HTTPS
    • HTTP → Port 80 (unencrypted)
    • HTTPS → Port 443 (encrypted via SSL/TLS)
  4. Basic Request Flow
    Browser → DNS → Server IP → Web Server → Response
  5. Install Nginx
    sudo apt install nginx
  6. Install Apache
    sudo apt install apache2
  7. Start Web Server
    systemctl start nginx
systemctl start apache2
  8. Check Status
    systemctl status nginx
  9. Default Web Root
    /var/www/html
  10. Test Web Server
    curl http://localhost
  11. Nginx Configuration
    /etc/nginx/nginx.conf
/etc/nginx/sites-available/
  12. Apache Configuration
    /etc/apache2/apache2.conf
/etc/apache2/sites-available/
  13. Virtual Hosts
    Serve multiple websites on one server.
  14. Nginx Server Block Example
    server {
  listen 80;
  server_name example.com;
  root /var/www/example;
}
  15. Apache Virtual Host Example
    <VirtualHost *:80>
  ServerName example.com
  DocumentRoot /var/www/example
</VirtualHost>
  16. Enable Site
    ln -s /etc/nginx/sites-available/example /etc/nginx/sites-enabled/
  17. Reload Configuration
    systemctl reload nginx
  18. Reverse Proxy (Important)
    location / {
  proxy_pass http://localhost:3000;
}
  19. Load Balancing
    upstream backend {
  server 192.168.1.10;
  server 192.168.1.11;
}
  20. Enable HTTPS (SSL)
    sudo apt install certbot
certbot --nginx
  21. SSL Configuration
    • Certificates
    • Private keys
  22. Nginx vs Apache
    Feature Nginx Apache
    Architecture Event-driven Process-based
    Performance High Moderate
  23. Use in DevOps
    • Reverse proxy for apps
    • Load balancing
    • API gateway
  24. Use in Cloud
    • Behind load balancers
    • Serving static content
  25. Use in Containers
    • Nginx as frontend
    • Proxy for microservices
  26. Common Issues
    • Port 80/443 blocked
    • Permission issues
    • Config syntax errors
  27. Debugging
    nginx -t
journalctl -u nginx
  28. Check Open Ports
    ss -tuln | grep 80
  29. Troubleshooting Workflow
    Check service
Check config
Check firewall
Test with curl
  30. Best Practices
    • Use HTTPS always
    • Use reverse proxy
    • Monitor logs
  31. Real-World Example
    • Nginx → reverse proxy for Node.js app
    • Apache → PHP application hosting
    • Cloud → load-balanced web servers
  32. Summary
    Web servers like Nginx and Apache are the backbone of web infrastructure, serving content, handling requests, and enabling scalable and secure web applications.
Completion check: You should now understand how to configure, deploy, and troubleshoot web servers in real-world environments.

Goal: Understand FTP and SFTP protocols, how to configure file transfer servers, secure data transfers, and troubleshoot real-world issues.

  1. What is FTP
    FTP (File Transfer Protocol) is used to transfer files between systems over a network.
    • Uses port 21
    • Unencrypted (not secure)
  2. What is SFTP
    SFTP (SSH File Transfer Protocol) is a secure file transfer method using SSH.
    • Uses port 22
    • Encrypted communication
  3. FTP vs SFTP
    Feature FTP SFTP
    Security No Yes
    Port 21 22
  4. FTP Modes
    • Active mode
    • Passive mode (most used)
  5. Install FTP Server (vsftpd)
    sudo apt install vsftpd
  6. Start FTP Service
    systemctl start vsftpd
  7. FTP Configuration File
    /etc/vsftpd.conf
  8. Enable Local Users
    local_enable=YES
write_enable=YES
  9. FTP Login
    ftp server-ip
  10. Basic FTP Commands
    ls
get file.txt
put file.txt
exit
  11. Passive Mode Configuration
    pasv_enable=YES
pasv_min_port=10000
pasv_max_port=10100
  12. Firewall for FTP
    ufw allow 21
ufw allow 10000:10100/tcp
  13. What is SFTP Internally
    • Runs over SSH
    • No separate service required
  14. SFTP Login
    sftp user@server
  15. SFTP Commands
    ls
get file.txt
put file.txt
exit
  16. Restrict SFTP Users (Chroot)
    /etc/ssh/sshd_config
    Example: 
    Match User sftpuser
  ChrootDirectory /home/sftpuser
  ForceCommand internal-sftp
  17. Restart SSH
    systemctl restart sshd
  18. File Transfer Alternatives
    • scp
    • rsync
  19. FTP in DevOps
    • Legacy systems
    • Bulk file transfers
  20. SFTP in DevOps
    • Secure deployments
    • Backup transfers
  21. Use in Cloud
    • SFTP for secure file uploads
    • FTP rarely used
  22. Use in Containers
    • SFTP-based data transfer
    • Volumes and storage integration
  23. Common Issues
    • FTP passive mode failure
    • Firewall blocking ports
    • Permission denied
  24. Debugging FTP
    journalctl -u vsftpd
  25. Debugging SFTP
    ssh -v user@host
  26. Troubleshooting Workflow
    Check service
Check ports (21/22)
Check firewall
Check permissions
  27. Security Best Practices
    • Avoid FTP (use SFTP)
    • Use key-based authentication
    • Restrict user access
  28. Real-World Example
    • Upload website files via SFTP
    • Backup logs to remote server
    • Legacy FTP system migration
  29. Summary
    FTP and SFTP are essential file transfer protocols, with SFTP being the secure and preferred choice for modern systems and DevOps workflows.
Completion check: You should now understand how to configure, use, and secure FTP and SFTP for file transfers.

Goal: Understand NFS and SMB protocols, how to configure shared storage, and use them in enterprise, cloud, and DevOps environments.

  1. What is File Sharing
    File sharing allows multiple systems to access files over a network.
    • Centralized storage
    • Shared access
  2. What is NFS
    NFS (Network File System) is a Linux-based file sharing protocol.
    • Common in Unix/Linux
    • Uses port 2049
  3. What is SMB
    SMB (Server Message Block) is used for file sharing in Windows environments.
    • Implemented via Samba in Linux
    • Uses port 445
  4. NFS vs SMB
    Feature NFS SMB
    Platform Linux/Unix Windows/Linux
    Performance High Moderate
  5. NFS Server Setup
    sudo apt install nfs-kernel-server
  6. Create Shared Directory
    mkdir /shared
chmod 777 /shared
  7. Configure NFS Exports
    /etc/exports
    Example: 
    /shared 192.168.1.0/24(rw,sync,no_root_squash)
  8. Apply NFS Config
    exportfs -a
systemctl restart nfs-kernel-server
  9. NFS Client Setup
    sudo apt install nfs-common
  10. Mount NFS Share
    mount 192.168.1.10:/shared /mnt
  11. Persistent Mount
    /etc/fstab
  12. SMB Server Setup (Samba)
    sudo apt install samba
  13. Configure Samba
    /etc/samba/smb.conf
    Example: 
    [shared]
  path = /shared
  read only = no
  14. Add Samba User
    smbpasswd -a username
  15. Restart Samba
    systemctl restart smbd
  16. Access SMB Share
    smbclient //server/shared
  17. Mount SMB Share
    mount -t cifs //server/shared /mnt -o username=user
  18. Permissions & Access Control
    • NFS → UID/GID based
    • SMB → Username/password
  19. Firewall Configuration
    ufw allow 2049
ufw allow 445
  20. Advanced: NFS Versions
    • NFSv3 → older
    • NFSv4 → secure and efficient
  21. Advanced: Performance Tuning
    • Use async option
    • Optimize mount options
  22. Use in DevOps
    • Shared storage for apps
    • Central logs storage
  23. Use in Kubernetes
    • NFS Persistent Volumes
    • Shared storage across pods
  24. Use in Cloud
    • AWS EFS (NFS)
    • Azure Files (SMB)
  25. Common Issues
    • Permission denied
    • Mount failure
    • Firewall blocking
  26. Debugging
    showmount -e server
journalctl -u nfs-server
  27. Troubleshooting Workflow
    Check service
Check exports/config
Check firewall
Test mount
  28. Security Best Practices
    • Restrict IP access
    • Use authentication
    • Avoid open shares
  29. Real-World Example
    • NFS → shared storage for Kubernetes
    • SMB → Windows file sharing
    • Cloud → managed file storage services
  30. Summary
    NFS and SMB enable network-based file sharing, providing scalable and centralized storage solutions for enterprise, cloud, and DevOps environments.
Completion check: You should now understand how to configure and use NFS and SMB for network file sharing.
