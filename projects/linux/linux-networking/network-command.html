Goal: Understand how ping works, how to test connectivity, and how to troubleshoot network issues using ICMP.

  1. What is ping
    ping is a command used to test connectivity between two systems on a network.
  2. How ping Works
    Ping uses ICMP (Internet Control Message Protocol). 
    Request → Reply
  3. Basic Command
    ping 8.8.8.8
  4. Ping a Domain
    ping google.com
  5. Example Output
    64 bytes from 8.8.8.8: time=10ms
  6. Understanding Output
    • bytes: Packet size
    • time: Latency
    • ttl: Time to live
  7. Ping Loopback
    ping 127.0.0.1
    Tests local network stack.
  8. Ping Local Network
    ping 192.168.1.1
    Tests gateway connectivity.
  9. Ping External Network
    ping 8.8.8.8
  10. Count Option
    ping -c 4 8.8.8.8
  11. Interval Option
    ping -i 2 8.8.8.8
  12. Packet Size
    ping -s 1000 8.8.8.8
  13. Timeout Option
    ping -W 2 8.8.8.8
  14. Continuous Monitoring
    Ping runs continuously until stopped.
  15. Latency Measurement
    Measures round-trip time (RTT).
  16. Packet Loss
    Indicates network issues: 
    0% → Good
>0% → Problem
  17. TTL (Time to Live)
    Limits packet lifetime across hops.
  18. ICMP Protocol
    Used for:
    • Diagnostics
    • Error reporting
  19. Common Ping Tests
    • Ping localhost → Check system
    • Ping gateway → Check LAN
    • Ping internet → Check external connectivity
  20. Ping vs DNS Issue
    ping 8.8.8.8 → Works
ping google.com → Fails
    This indicates DNS issue.
  21. Firewall Impact
    ICMP may be blocked by firewalls.
  22. Ping in Containers
    Used to test container networking.
  23. Ping in Cloud
    May be blocked by security groups.
  24. Common Errors
    • Destination unreachable
    • Request timeout
  25. Troubleshooting Workflow
    ping 127.0.0.1
ping gateway
ping external IP
ping domain
  26. Best Practices
    • Use ping as first test
    • Combine with traceroute
  27. Real-World Example
    • Server down? → ping test
    • Network issue? → check packet loss
  28. Summary
    Ping is a simple but powerful tool used to test connectivity, measure latency, and diagnose network issues using ICMP.
Completion check: You should now understand how to use ping for connectivity testing and network troubleshooting.

Goal: Understand how traceroute and tracepath work, how packets travel across networks, and how to diagnose network path and latency issues.

  1. What is traceroute
    traceroute is a command used to display the path packets take from source to destination across networks.
  2. What is tracepath
    tracepath is a similar tool that traces the network path without requiring root privileges.
  3. Why These Tools are Important
    • Identify network path
    • Detect where delays occur
    • Troubleshoot routing issues
  4. How traceroute Works
    Uses TTL (Time To Live): 
    TTL=1 → first router
TTL=2 → second router
...
  5. Packet Flow
    1 → Packet sent with TTL=1
2 → Router drops packet
3 → Sends ICMP response
4 → Next TTL value used
  6. Basic Command
    traceroute google.com
  7. Using tracepath
    tracepath google.com
  8. Example Output
    1 192.168.1.1 1ms
2 10.0.0.1 5ms
3 8.8.8.8 20ms
  9. Understanding Output
    • Each line = one hop
    • IP address = router
    • Time = latency
  10. What is a Hop
    Each router between source and destination is called a hop.
  11. Latency Measurement
    Shows time taken to reach each hop.
  12. Detecting Network Issues
    • High latency at specific hop
    • Packet drops
    • Routing loops
  13. * * * in Output
    Indicates:
    • No response from router
    • Firewall blocking
  14. Difference: traceroute vs tracepath
    Feature traceroute tracepath
    Privileges Requires root No root needed
    Control More options Simpler
  15. Protocol Used
    • ICMP
    • UDP (default)
  16. Using ICMP Mode
    traceroute -I google.com
  17. Limiting Hops
    traceroute -m 10 google.com
  18. Changing Packet Size
    traceroute -s 100 google.com
  19. Real-World Use Cases
    • Slow internet debugging
    • Identifying ISP issues
    • Diagnosing routing problems
  20. Traceroute vs Ping
    Feature Ping Traceroute
    Purpose Connectivity Path analysis
  21. Use in Containers
    Helps debug container-to-container communication.
  22. Use in Cloud
    • Identify routing through VPC
    • Check network latency
  23. Common Issues
    • Blocked ICMP
    • Incomplete trace
    • Firewall restrictions
  24. Troubleshooting Workflow
    ping destination
traceroute destination
analyze hops
  25. Best Practices
    • Combine with ping
    • Check multiple destinations
  26. Summary
    Traceroute and tracepath reveal the path packets take across networks, helping identify latency, routing issues, and connectivity problems.
Completion check: You should now understand how traceroute and tracepath work and how to use them for network diagnostics.

Goal: Understand how MTR works, how it combines ping and traceroute, and how to use it for real-time network diagnostics and troubleshooting.

  1. What is MTR
    MTR (My Traceroute) is a tool that combines the functionality of ping and traceroute to provide continuous, real-time network diagnostics.
  2. Why MTR is Important
    • Real-time monitoring of network path
    • Detect intermittent issues
    • Analyze latency and packet loss
  3. How MTR Works
    Traceroute → Finds path
Ping → Measures latency
MTR → Combines both continuously
  4. Installing MTR
    apt install mtr
  5. Basic Command
    mtr google.com
  6. Example Output
    HOST: local        Loss%   Snt   Last   Avg   Best   Wrst
1. 192.168.1.1     0.0%    10    1.2    1.1    1.0    2.0
2. 10.0.0.1        5.0%    10    5.0    4.5    4.0    6.0
  7. Understanding Output Columns
    • Loss%: Packet loss percentage
    • Snt: Packets sent
    • Last: Last response time
    • Avg: Average latency
    • Best: Lowest latency
    • Wrst: Highest latency
  8. Real-Time Monitoring
    MTR continuously updates statistics, unlike traceroute.
  9. Identifying Packet Loss
    • Loss at early hop → local issue
    • Loss at later hop → upstream issue
  10. Identifying Latency Issues
    High latency at specific hop indicates bottleneck.
  11. Running in Report Mode
    mtr -r google.com
  12. Limiting Number of Packets
    mtr -c 10 google.com
  13. Using ICMP Mode
    mtr -I google.com
  14. Using TCP Mode
    mtr -T google.com
  15. Use Cases
    • Debug intermittent network issues
    • Monitor connection stability
    • Analyze ISP performance
  16. MTR vs Ping
    • Ping → single endpoint
    • MTR → full path analysis
  17. MTR vs Traceroute
    • Traceroute → one-time snapshot
    • MTR → continuous monitoring
  18. Use in DevOps
    • Monitor service connectivity
    • Debug production latency issues
  19. Use in Containers
    Helps debug container networking issues.
  20. Use in Cloud
    • Analyze routing in VPC
    • Check cross-region latency
  21. Common Issues
    • Firewall blocking ICMP
    • False packet loss (rate-limited routers)
  22. Troubleshooting Workflow
    ping destination
traceroute destination
mtr destination
  23. Best Practices
    • Run for longer duration for accuracy
    • Analyze trends, not single values
  24. Real-World Example
    • Website slow → use MTR to find bottleneck hop
    • Packet loss → identify where loss occurs
  25. Summary
    MTR provides real-time visibility into network paths, combining ping and traceroute to diagnose latency, packet loss, and routing issues effectively.
Completion check: You should now understand how to use MTR for real-time network diagnostics and troubleshooting.

Goal: Understand how to use curl to test HTTP/HTTPS endpoints, interact with APIs, and debug network and application-level issues.

  1. What is curl
    curl (Client URL) is a command-line tool used to send requests to servers and retrieve responses using various protocols like HTTP and HTTPS.
  2. Why curl is Important
    • Test APIs and web services
    • Debug backend services
    • Check service availability
    • Automate HTTP requests
  3. Basic Syntax
    curl <URL>
  4. Example Request
    curl https://example.com
  5. Understanding HTTP Methods
    • GET → Retrieve data
    • POST → Send data
    • PUT → Update data
    • DELETE → Remove data
  6. GET Request
    curl -X GET https://api.example.com
  7. POST Request
    curl -X POST https://api.example.com \
-d "name=test"
  8. Sending JSON Data
    curl -X POST https://api.example.com \
-H "Content-Type: application/json" \
-d '{"name":"test"}'
  9. Adding Headers
    curl -H "Authorization: Bearer token" https://api.example.com
  10. Viewing Response Headers
    curl -I https://example.com
  11. Verbose Mode
    curl -v https://example.com
    Shows full request/response details.
  12. Silent Mode
    curl -s https://example.com
  13. Saving Output
    curl -o file.html https://example.com
  14. Follow Redirects
    curl -L https://example.com
  15. Authentication
    curl -u user:password https://example.com
  16. Timeout Control
    curl --max-time 5 https://example.com
  17. Testing APIs
    • Check endpoint response
    • Validate JSON output
    • Debug API errors
  18. HTTP Status Codes
    • 200 → OK
    • 404 → Not Found
    • 500 → Server Error
  19. Debugging with curl
    • Service not responding
    • API returning error
    • Network connectivity issues
  20. curl vs wget
    Feature curl wget
    Usage API testing File download
  21. Use in DevOps
    • Health checks
    • CI/CD pipelines
    • Service validation
  22. Use in Containers
    • Test internal services
    • Verify container networking
  23. Use in Cloud
    • Test endpoints
    • Validate load balancers
  24. Common Errors
    • Connection refused
    • Timeout
    • SSL issues
  25. Troubleshooting Workflow
    ping server
curl -v endpoint
check response
  26. Best Practices
    • Use verbose mode for debugging
    • Validate headers and status codes
    • Use scripts for automation
  27. Real-World Example
    • API not working → test with curl
    • Check service health in production
  28. Summary
    curl is a powerful tool for interacting with web services and APIs, making it essential for debugging, testing, and automation in modern systems.
Completion check: You should now understand how to use curl for API testing and HTTP debugging.

Goal: Understand how to use wget to download files, automate data retrieval, and handle network-based file transfers in Linux systems.

  1. What is wget
    wget is a command-line tool used to download files from remote servers using protocols like HTTP, HTTPS, and FTP.
  2. Why wget is Important
    • Download files from servers
    • Automate downloads in scripts
    • Reliable in unstable networks
  3. Basic Syntax
    wget <URL>
  4. Example Download
    wget https://example.com/file.zip
  5. Saving File with Custom Name
    wget -O myfile.zip https://example.com/file.zip
  6. Download in Background
    wget -b https://example.com/file.zip
  7. Resuming Downloads
    wget -c https://example.com/file.zip
    Continues interrupted downloads.
  8. Limiting Download Speed
    wget --limit-rate=200k https://example.com/file.zip
  9. Recursive Download
    wget -r https://example.com/
    Downloads entire website structure.
  10. Download Specific File Types
    wget -r -A .pdf https://example.com
  11. Download with Authentication
    wget --user=user --password=pass https://example.com
  12. Handling HTTPS
    wget https://secure-site.com
  13. Ignoring SSL Errors
    wget --no-check-certificate https://example.com
  14. Download Multiple Files
    wget -i urls.txt
  15. Retry Failed Downloads
    wget --tries=5 https://example.com/file.zip
  16. Timeout Control
    wget --timeout=10 https://example.com
  17. Viewing Download Progress
    Shows:
    • Speed
    • File size
    • Time remaining
  18. wget vs curl
    Feature wget curl
    Purpose Download files API requests
    Recursive Yes No
  19. Use in DevOps
    • Download artifacts
    • Fetch dependencies
    • Automate setup scripts
  20. Use in Containers
    • Download files inside containers
    • Install packages
  21. Use in Cloud
    • Download deployment packages
    • Fetch data from remote storage
  22. Common Errors
    • 404 Not Found
    • Connection timeout
    • Permission denied
  23. Troubleshooting
    ping server
wget URL
check logs
  24. Best Practices
    • Use resume for large files
    • Validate downloaded content
    • Use scripts for automation
  25. Real-World Example
    • Download application package in CI/CD
    • Fetch backup files from remote server
  26. Summary
    wget is a reliable and powerful tool for downloading files from remote servers, widely used in automation, scripting, and DevOps workflows.
Completion check: You should now understand how to use wget for downloading and automating file retrieval tasks.

Goal: Understand the ip command as a complete networking toolkit for managing interfaces, IP addresses, routing, and advanced networking in Linux.

  1. What is the ip Command
    ip is a modern Linux command used to manage networking, replacing older tools like ifconfig and route.
  2. Why ip Command is Important
    • Unified networking tool
    • Supports advanced features
    • Used in modern Linux systems
  3. ip Command Structure
    ip [OBJECT] [COMMAND]
    Common objects:
    • link → Interfaces
    • addr → IP addresses
    • route → Routing
    • rule → Policy routing
  4. ip link (Interface Management)
    ip link
ip link set eth0 up
ip link set eth0 down
  5. ip addr (IP Management)
    ip addr
ip addr add 192.168.1.100/24 dev eth0
  6. ip route (Routing)
    ip route
ip route add default via 192.168.1.1
  7. ip rule (Policy Routing)
    ip rule
ip rule add from 192.168.1.100 table custom
  8. Viewing All Network Info
    ip a
ip r
  9. Creating Virtual Interfaces
    ip link add veth0 type veth peer name veth1
  10. Deleting Interfaces
    ip link delete veth0
  11. Network Namespaces
    ip netns add ns1
ip netns exec ns1 ip a
  12. Monitoring Network Changes
    ip monitor
  13. Show Neighbor Table (ARP)
    ip neigh
  14. Show Routing Tables
    ip route show table all
  15. ip vs ifconfig
    Feature ip ifconfig
    Status Modern Deprecated
    Capabilities Advanced Limited
  16. Use in Troubleshooting
    ip addr
ip route
ip link
  17. Use in DevOps
    • Server configuration
    • Network debugging
    • Automation scripts
  18. Use in Containers
    • Container networking uses ip command internally
    • Used to debug Docker and Kubernetes
  19. Use in Cloud
    • Inspect instance networking
    • Validate routes and IPs
  20. Advanced Features
    • Policy-based routing
    • Network namespaces
    • Traffic control
  21. Common Mistakes
    • Forgetting persistence
    • Wrong interface name
    • Incorrect CIDR
  22. Troubleshooting Workflow
    ip addr
ip route
ping
traceroute
  23. Best Practices
    • Use ip instead of ifconfig
    • Verify changes immediately
    • Document configurations
  24. Real-World Example
    • Configure server networking
    • Debug container communication
    • Fix routing issues
  25. Summary
    The ip command is a powerful and unified tool for managing all aspects of networking in Linux, from interfaces to routing and advanced configurations.
Completion check: You should now understand the ip command as a complete networking management tool in Linux.
