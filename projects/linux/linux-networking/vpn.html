Goal: Understand how SSH tunneling securely forwards traffic using encrypted channels and acts as a lightweight VPN mechanism.

  1. What is SSH Tunneling
    SSH tunneling is a method of forwarding network traffic securely through an encrypted SSH connection.
  2. Why SSH Tunneling
    • Secure data transmission
    • Access restricted services
    • Bypass firewalls
  3. Basic Flow
    Client → SSH Tunnel → Remote Server → Target Service
  4. Encryption Layer
    Data → Encrypted → SSH Tunnel → Decrypted → Destination
  5. SSH Protocol
    • Secure Shell (SSH)
    • Uses port 22
  6. Types of SSH Tunneling
    • Local Port Forwarding
    • Remote Port Forwarding
    • Dynamic Port Forwarding
  7. Local Port Forwarding
    ssh -L local_port:target_host:target_port user@ssh_server
    Access remote service locally.
  8. Example (Local Forwarding)
    ssh -L 8080:localhost:3000 user@remote-server
  9. Remote Port Forwarding
    ssh -R remote_port:localhost:local_port user@ssh_server
    Exposes local service to remote server.
  10. Dynamic Port Forwarding
    ssh -D 1080 user@ssh_server
    Creates a SOCKS proxy (acts like VPN).
  11. SOCKS Proxy
    • Routes traffic dynamically
    • Used by browsers
  12. Use Cases
    • Access private servers
    • Secure database connections
    • Bypass network restrictions
  13. SSH Tunnel vs VPN
    • SSH → application-level
    • VPN → full network-level
  14. Authentication
    • Password
    • SSH key-based authentication
  15. Key-Based Authentication
    ssh-keygen
ssh-copy-id user@server
  16. Security Benefits
    • Encrypted communication
    • Prevents data interception
  17. Port Forwarding Flow
    Local App → Local Port → SSH Tunnel → Remote Service
  18. Firewall Bypass
    Uses SSH port (22) to bypass restrictions.
  19. Background Execution
    ssh -N -f -L 8080:localhost:3000 user@server
  20. Keep Alive Settings
    ServerAliveInterval 60
  21. Compression
    ssh -C user@server
  22. Debug Mode
    ssh -v user@server
  23. Common Issues
    • Port already in use
    • Firewall blocking SSH
    • Wrong host configuration
  24. Troubleshooting Flow
    Check SSH connection
Check ports
Check logs
Test connectivity
  25. Performance Considerations
    • Encryption overhead
    • Latency increase
  26. Security Best Practices
    • Disable root login
    • Use key-based auth
    • Change default SSH port
  27. Real-World Example
    Access private DB securely via SSH tunnel
  28. Summary
    SSH tunneling securely forwards traffic through encrypted channels, enabling safe communication, remote access, and lightweight VPN functionality.
Completion check: You should now understand how SSH tunneling works and how it securely forwards traffic across networks.

Goal: Understand how OpenVPN enables secure remote access to private networks using encrypted tunnels over public internet.

  1. What is OpenVPN
    OpenVPN is an open-source VPN solution that creates secure tunnels between client and private network.
  2. Why OpenVPN
    • Secure remote access
    • Encrypts internet traffic
    • Access private resources
  3. Basic Flow
    Client → Internet → OpenVPN Server → Private Network
  4. VPN Tunnel Concept
    User Traffic → Encrypted Tunnel → Secure Network
  5. Protocols Used
    • TCP
    • UDP (preferred for performance)
  6. Ports Used
    • 1194 (default)
  7. Encryption
    • AES encryption
    • TLS for key exchange
  8. Authentication Methods
    • Username & Password
    • Certificates (most secure)
  9. Certificate-Based Auth
    CA → Server Cert → Client Cert
  10. Client-Server Architecture
    Multiple Clients → OpenVPN Server → Internal Network
  11. TUN vs TAP
    • TUN → Layer 3 (IP routing)
    • TAP → Layer 2 (Ethernet bridging)
  12. Routing Through VPN
    Client → VPN → Internal IP (10.x.x.x)
  13. Split Tunneling
    • Only specific traffic goes through VPN
  14. Full Tunnel
    • All traffic routed through VPN
  15. DNS Handling
    • VPN can push DNS settings
  16. Firewall Integration
    • Allow UDP 1194
  17. OpenVPN Server Setup (Basic)
    apt install openvpn
  18. Server Config Example
    port 1194
proto udp
dev tun
server 10.8.0.0 255.255.255.0
  19. Client Config
    client
dev tun
proto udp
remote server-ip 1194
  20. IP Address Assignment
    • Clients get virtual IPs
  21. NAT & Routing
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
  22. High Availability
    • Multiple VPN servers
  23. Performance Considerations
    • Encryption overhead
    • Latency
  24. Security Best Practices
    • Use strong encryption
    • Rotate certificates
    • Restrict access
  25. Debug Commands
    systemctl status openvpn
tail -f /var/log/syslog
  26. Common Issues
    • Port blocked
    • Certificate mismatch
    • Routing issues
  27. Troubleshooting Flow
    Check service
Check port
Check config
Check logs
  28. Use Cases
    • Remote employee access
    • Secure cloud access
    • Site-to-site connectivity
  29. Summary
    OpenVPN creates secure encrypted tunnels over the internet, enabling safe remote access to private networks and resources.
Completion check: You should now understand how OpenVPN provides secure remote connectivity and protects network traffic.

Goal: Understand how WireGuard provides fast, secure, and modern VPN connectivity using simple configuration and efficient cryptography.

  1. What is WireGuard
    WireGuard is a modern VPN protocol designed to be simple, fast, and secure.
  2. Why WireGuard
    • High performance
    • Minimal configuration
    • Strong cryptography
  3. Basic Flow
    Client → Internet → WireGuard Server → Private Network
  4. VPN Tunnel Concept
    Traffic → Encrypted → Tunnel → Decrypted → Destination
  5. Protocol
    • Uses UDP only
  6. Default Port
    • 51820 (UDP)
  7. Modern Cryptography
    • ChaCha20 encryption
    • Poly1305 authentication
    • Curve25519 key exchange
  8. Key-Based Authentication
    Private Key + Public Key
  9. Peer-to-Peer Model
    Client ↔ Server (Peers)
  10. Configuration Simplicity
    Uses simple config files instead of complex certificates.
  11. Interface Concept
    wg0 → virtual network interface
  12. Server Config Example
    [Interface]
Address = 10.0.0.1/24
PrivateKey = SERVER_PRIVATE_KEY
ListenPort = 51820
  13. Peer Config Example
    [Peer]
PublicKey = CLIENT_PUBLIC_KEY
AllowedIPs = 10.0.0.2/32
  14. Client Config Example
    [Interface]
PrivateKey = CLIENT_PRIVATE_KEY
Address = 10.0.0.2/24

[Peer]
PublicKey = SERVER_PUBLIC_KEY
Endpoint = server-ip:51820
AllowedIPs = 0.0.0.0/0
  15. AllowedIPs
    Defines which traffic goes through VPN.
  16. Full Tunnel
    AllowedIPs = 0.0.0.0/0
  17. Split Tunnel
    AllowedIPs = 10.0.0.0/24
  18. Routing
    Traffic routed through wg0 interface.
  19. NAT Configuration
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
  20. Bring Up Interface
    wg-quick up wg0
  21. Check Status
    wg show
  22. Performance Benefits
    • Low latency
    • High throughput
  23. Security Benefits
    • Modern encryption
    • Small attack surface
  24. Roaming Support
    Automatically reconnects when IP changes.
  25. Firewall Integration
    • Allow UDP 51820
  26. High Availability
    • Multiple peers
  27. Debug Commands
    wg show
ip a
journalctl -u wg-quick@wg0
  28. Common Issues
    • Wrong keys
    • Firewall blocking UDP
    • Routing issues
  29. Troubleshooting Flow
    Check keys
Check port
Check routing
Check logs
  30. WireGuard vs OpenVPN
    • WireGuard → faster, simpler
    • OpenVPN → more mature, flexible
  31. Use Cases
    • Remote access VPN
    • Site-to-site VPN
    • Cloud networking
  32. Summary
    WireGuard is a fast, modern VPN solution that uses simple configuration and strong cryptography to provide secure and efficient networking.
Completion check: You should now understand how WireGuard provides modern, secure, and high-performance VPN connectivity.

Goal: Understand how GRE tunnels encapsulate traffic between networks to enable communication across different network segments.

  1. What is GRE Tunnel
    GRE (Generic Routing Encapsulation) is a tunneling protocol used to encapsulate packets inside another IP packet.
  2. Why GRE
    • Connect remote networks
    • Transport different protocols
    • Enable site-to-site connectivity
  3. Basic Flow
    Network A → GRE Tunnel → Network B
  4. Encapsulation Concept
    Original Packet → GRE Header → New IP Header → Transmission
  5. Packet Flow
    Source → Encapsulation → Internet → Decapsulation → Destination
  6. Protocol Number
    • IP Protocol 47 (not port-based)
  7. GRE vs VPN
    • GRE → no encryption
    • VPN → encrypted
  8. Use Cases
    • Site-to-site connectivity
    • Routing protocols over internet
    • Cloud networking
  9. Supports Multiple Protocols
    • IPv4
    • IPv6
    • Multicast
  10. Tunnel Endpoints
    Local IP ↔ Remote IP
  11. Linux GRE Tunnel Setup
    ip tunnel add gre1 mode gre remote 2.2.2.2 local 1.1.1.1 ttl 255
ip link set gre1 up
ip addr add 10.0.0.1/30 dev gre1
  12. Remote Side Setup
    ip tunnel add gre1 mode gre remote 1.1.1.1 local 2.2.2.2 ttl 255
ip link set gre1 up
ip addr add 10.0.0.2/30 dev gre1
  13. Routing Through Tunnel
    ip route add 192.168.2.0/24 via 10.0.0.2
  14. GRE Interface
    gre1 → virtual tunnel interface
  15. MTU Considerations
    • Encapsulation reduces MTU
  16. Keepalive (Optional)
    • Detect tunnel failure
  17. Performance
    • Low overhead
    • No encryption cost
  18. Security Consideration
    • No built-in encryption
    • Use IPsec with GRE for security
  19. GRE over IPsec
    GRE Tunnel → IPsec Encryption → Secure Tunnel
  20. Firewall Requirements
    • Allow protocol 47 (GRE)
  21. Debug Commands
    ip tunnel show
ip addr
ping 10.0.0.2
tcpdump -i gre1
  22. Common Issues
    • Protocol 47 blocked
    • Wrong tunnel IP
    • Routing misconfiguration
  23. Troubleshooting Flow
    Check tunnel interface
Check routes
Check firewall
Check connectivity
  24. Comparison with IPsec
    • GRE → flexible, no encryption
    • IPsec → secure, encrypted
  25. Real-World Example
    Connect two cloud VPC networks using GRE tunnel
  26. High Availability
    • Multiple GRE tunnels for redundancy
  27. Use in Routing Protocols
    • OSPF over GRE
    • BGP over GRE
  28. Summary
    GRE tunnels encapsulate traffic between networks, enabling flexible and efficient communication across different network environments.
Completion check: You should now understand how GRE tunnels encapsulate and transport traffic between networks.
