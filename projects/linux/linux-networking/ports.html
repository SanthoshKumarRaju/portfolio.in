Linux Networking - Ports

•server

Goal: Understand ports and sockets, how communication happens in Linux networking, and how to monitor connections using ss and netstat.

  1. What are Ports
    Ports are logical endpoints used by applications to communicate over a network.
    • IP Address → Identifies system
    • Port → Identifies application
  2. Port Range Classification
    • 0–1023 → Well-known ports (HTTP, SSH)
    • 1024–49151 → Registered ports
    • 49152–65535 → Ephemeral (dynamic)
  3. Common Ports
    • 80 → HTTP
    • 443 → HTTPS
    • 22 → SSH
    • 3306 → MySQL
    • 6379 → Redis
  4. What are Sockets
    A socket is a combination of: 
    IP Address + Port + Protocol
    It represents a communication endpoint.
  5. Types of Sockets
    • TCP → Reliable, connection-oriented
    • UDP → Fast, connectionless
    • UNIX sockets → Local communication
  6. TCP vs UDP
    Feature TCP UDP
    Reliability Yes No
    Speed Slower Faster
    Use Case Web, SSH Streaming, DNS
  7. Connection States
    • LISTEN → Waiting for connection
    • ESTABLISHED → Active communication
    • CLOSE_WAIT → Closing phase
    • TIME_WAIT → Final cleanup
  8. Check Open Ports using ss
    ss -tuln
    • -t → TCP
    • -u → UDP
    • -l → Listening
    • -n → Numeric output
  9. Check Established Connections
    ss -tan
  10. Filter by Port
    ss -tuln | grep 80
  11. Show Process Using Port
    ss -tulnp
  12. Using netstat (Legacy Tool)
    netstat -tuln
    Note: netstat is older and replaced by ss.
  13. Check Port Usage
    lsof -i :80
  14. Test Port Connectivity
    nc -zv google.com 80
  15. Understanding Listening Services
    Services like nginx, sshd, and mysql listen on specific ports for incoming connections.
  16. Firewall and Ports
    • iptables / firewalld control access
    • Ports must be opened to allow traffic
  17. Ports in Client-Server Model
    • Server → Fixed port (e.g., 80)
    • Client → Random ephemeral port
  18. Debugging Port Issues
    ss -tuln
lsof -i :PORT
nc -zv host PORT
  19. Use in DevOps
    • Check service availability
    • Debug API connectivity
    • Monitor microservices communication
  20. Use in Containers (Docker)
    • Port mapping (host → container)
    • Expose services using ports
  21. Use in Kubernetes
    • ClusterIP → Internal communication
    • NodePort → External access
    • LoadBalancer → Public access
  22. Use in Cloud
    • Security Groups control ports
    • Load balancers route traffic
  23. Common Issues
    • Port already in use
    • Service not listening
    • Firewall blocking traffic
  24. Troubleshooting Workflow
    Check service running
Check port listening (ss)
Check firewall rules
Test connectivity (nc/curl)
  25. Best Practices
    • Use ss instead of netstat
    • Close unused ports
    • Monitor open connections
  26. Real-World Example
    • App not accessible → check port 8080
    • DB connection failed → verify 3306
    • Service down → check LISTEN state
  27. Summary
    Ports and sockets are the foundation of network communication. Tools like ss and netstat help monitor connections, debug issues, and ensure services are reachable.
Completion check: You should now understand ports, sockets, connection states, and how to monitor and debug network communication in Linux.

Goal: Master the ss command to inspect sockets, monitor network connections, analyze ports, and debug real-world networking issues in Linux systems.

  1. What is ss Command
    ss (socket statistics) is a modern Linux tool used to display network connections and socket information.
    • Faster than netstat
    • Directly reads from kernel (Netlink)
    • Shows detailed socket information
  2. Why ss is Important
    • Monitor active connections
    • Debug port issues
    • Inspect services
    • Analyze system networking
  3. Basic Usage
    ss
    Shows all active sockets.
  4. List Listening Ports
    ss -l
  5. Show TCP Connections
    ss -t
  6. Show UDP Connections
    ss -u
  7. Combine Filters
    ss -tuln
    • -t → TCP
    • -u → UDP
    • -l → Listening
    • -n → Numeric (no DNS resolution)
  8. Show Established Connections
    ss -tan state established
  9. Filter by Port
    ss -tuln | grep :80
  10. Show Process Using Port
    ss -tulnp
    Displays PID and program name.
  11. Connection States
    • LISTEN
    • ESTABLISHED
    • TIME_WAIT
    • CLOSE_WAIT
    • SYN_SENT / SYN_RECV
  12. Advanced Filtering
    ss state listening
ss state established '( dport = :80 )'
  13. Show Statistics Summary
    ss -s
    Displays summary of connections.
  14. Show Socket Memory Usage
    ss -m
  15. Show Detailed Info
    ss -e
    Extended information.
  16. Kernel-Level Insight
    ss reads data from:
    • /proc/net/*
    • Netlink interface
  17. Compare ss vs netstat
    Feature ss netstat
    Speed Fast Slow
    Modern Support Yes Deprecated
  18. Debugging Port Issues
    ss -tulnp
lsof -i :PORT
  19. Check Service Availability
    ss -lnt | grep 8080
  20. Detect High Connections
    ss -tan | wc -l
  21. Use in DevOps
    • Debug API failures
    • Check microservice communication
    • Monitor traffic spikes
  22. Use in Docker
    • Verify container port mapping
    • Check exposed services
  23. Use in Kubernetes
    • Debug pod networking
    • Verify service ports
  24. Use in Cloud
    • Check instance open ports
    • Validate load balancer connections
  25. Common Issues
    • Port not listening
    • Too many connections
    • Connection stuck in TIME_WAIT
  26. Troubleshooting Workflow
    Check service → systemctl status
Check ports → ss -tuln
Check process → ss -tulnp
Test connection → curl / nc
  27. Performance Analysis
    • Identify connection leaks
    • Monitor socket usage
    • Detect bottlenecks
  28. Best Practices
    • Use ss instead of netstat
    • Always use -n for faster output
    • Combine filters for precise results
  29. Real-World Example
    • App not reachable → check LISTEN port
    • High traffic → analyze ESTABLISHED connections
    • Port conflict → identify process using port
  30. Summary
    The ss command is a powerful and efficient tool for inspecting sockets, monitoring connections, and debugging network issues in Linux systems, making it essential for DevOps and system administrators.

  2. Why netstat is Important

    • Useful for troubleshooting
    • Provides network insights
  3. Basic Usage
    netstat
    Shows active connections.
  4. List All Listening Ports

  5. Show TCP Connections

  6. Show UDP Connections
    netstat -u

    • ESTABLISHED

    netstat -r
  11. Show Network Interfaces
    netstat -i
  12. Show Statistics

Goal: Understand TCP connection states, how connections are established and terminated, and how to debug networking issues using these states.

  1. What are Connection States
    Connection states represent the lifecycle of a network connection between client and server.
    • Managed by TCP protocol
    • Tracked by the Linux kernel
  2. Why Connection States are Important
    • Debug network issues
    • Understand application behavior
    • Detect performance bottlenecks
  3. Overview of TCP Lifecycle
    • Connection Start → 3-way handshake
    • Data Transfer → ESTABLISHED
    • Connection Close → 4-way termination
  4. TCP 3-Way Handshake
    Client → SYN
Server → SYN-ACK
Client → ACK
    Connection becomes ESTABLISHED.
  5. Main TCP States
    • LISTEN
    • SYN_SENT
    • SYN_RECV
    • ESTABLISHED
    • FIN_WAIT_1
    • FIN_WAIT_2
    • CLOSE_WAIT
    • LAST_ACK
    • TIME_WAIT
    • CLOSED
  6. LISTEN State
    Server is waiting for incoming connections. 
    ss -lnt
  7. SYN_SENT
    Client has sent SYN and is waiting for response.
  8. SYN_RECV
    Server received SYN and sent SYN-ACK.
  9. ESTABLISHED
    Active communication between client and server. 
    ss -tan state established
  10. Connection Termination (4-Way)
    Client → FIN
Server → ACK
Server → FIN
Client → ACK
  11. FIN_WAIT_1 & FIN_WAIT_2
    Client is closing connection.
  12. CLOSE_WAIT
    Server received FIN but hasn’t closed yet. ⚠️ Indicates possible application issue.
  13. LAST_ACK
    Server is waiting for final ACK.
  14. TIME_WAIT
    Waiting before fully closing connection.
    • Prevents delayed packet issues
    • Common in high traffic systems
  15. CLOSED
    Connection fully terminated.
  16. View Connection States
    ss -tan
netstat -an
  17. Count Connections by State
    ss -tan | awk '{print $1}' | sort | uniq -c
  18. Debugging with States
    • Too many ESTABLISHED → High traffic
    • Too many TIME_WAIT → Short-lived connections
    • Too many CLOSE_WAIT → App not closing properly
  19. TIME_WAIT Problem
    ss -tan state time-wait
    Causes:
    • High request rate
    • Short-lived HTTP connections
  20. CLOSE_WAIT Issue
    • Application not closing sockets
    • Memory/resource leak
  21. Use in DevOps
    • Debug API latency
    • Detect connection leaks
    • Monitor service health
  22. Use in Microservices
    • High ESTABLISHED → normal traffic
    • High TIME_WAIT → inefficient connections
  23. Use in Kubernetes
    • Debug pod networking
    • Identify service connection issues
  24. Use in Cloud
    • Analyze load balancer connections
    • Monitor traffic spikes
  25. Performance Tuning
    sysctl net.ipv4.tcp_fin_timeout
sysctl net.ipv4.tcp_tw_reuse
  26. Troubleshooting Workflow
    Check states → ss -tan
Identify abnormal state
Trace application
Tune kernel if needed
  27. Best Practices
    • Monitor connection states regularly
    • Fix CLOSE_WAIT issues immediately
    • Optimize connection reuse
  28. Real-World Example
    • API slow → many TIME_WAIT
    • Server crash → many CLOSE_WAIT
    • Traffic spike → ESTABLISHED surge
  29. Summary
    Connection states define the lifecycle of TCP communication. Understanding them is critical for debugging, performance tuning, and building reliable systems.
Completion check: You should now understand TCP connection states and how to use them for debugging and performance analysis.
