Linux Networking - Interfaces

Goal: Understand Linux bridges, how they connect multiple interfaces into a single network, and how they are used in virtualization and containers.

  1. What is a Linux Bridge
    A Linux bridge connects multiple network interfaces into a single virtual network.
    • Acts like a virtual switch
    • Operates at Layer 2 (Data Link)
  2. Why Bridges are Important
    • Used in virtualization (VMs)
    • Used in Docker/Kubernetes
    • Connect multiple interfaces
  3. Basic Concept
    eth0 + veth0 → bridge (br0) → same network
  4. Bridge vs Router
    • Bridge → Layer 2 (no IP routing)
    • Router → Layer 3 (IP routing)
  5. Install Bridge Tools
    sudo apt install bridge-utils
  6. Create Bridge
    ip link add name br0 type bridge
  7. Bring Bridge Up
    ip link set br0 up
  8. Add Interface to Bridge
    ip link set eth0 master br0
  9. Remove Interface from Bridge
    ip link set eth0 nomaster
  10. Assign IP to Bridge
    ip addr add 192.168.1.100/24 dev br0
  11. Check Bridge
    brctl show
  12. Modern Alternative
    bridge link
  13. Forwarding Database (FDB)
    bridge fdb show
  14. Packet Flow
    Device → Bridge → Forward to correct interface
  15. Bridge in Virtualization
    • VM connects to bridge
    • Gets IP from same network
  16. Bridge in Docker
    • docker0 bridge
    • Containers connected via veth pairs
  17. Bridge in Kubernetes
    • Pod networking
    • CNI plugins use bridges
  18. Advanced: STP (Spanning Tree Protocol)
    Prevents loops in network.
  19. Enable STP
    brctl stp br0 on
  20. Bridge with Netplan
    Example: 
    network:
  version: 2
  bridges:
    br0:
      interfaces: [eth0]
      dhcp4: yes
  21. Common Issues
    • No connectivity → interface not added
    • Loop issues → STP disabled
  22. Debugging
    ip link
bridge link
bridge fdb show
  23. Troubleshooting Workflow
    Check bridge → brctl show
Check interfaces → ip link
Check traffic → tcpdump
  24. DevOps Use Cases
    • VM networking
    • Container networking
  25. Cloud Use Cases
    • Virtual networking
    • Overlay networks
  26. Security Considerations
    • Traffic flows freely within bridge
    • Use firewall rules if needed
  27. Golden Debug Rule
    If devices are on same bridge → they should communicate directly
  28. Real-World Example
    • VM gets IP from same LAN
    • Docker containers communicate via bridge
    • Kubernetes pod networking
  29. Summary
    Linux bridges act as virtual switches, enabling multiple interfaces to operate within the same network, forming the backbone of virtualization and container networking.
Completion check: You should now understand how to configure and use Linux bridges in advanced networking environments.

Goal: Learn how to combine multiple network interfaces into a single logical interface for redundancy and performance using bonding.

  1. What is Network Bonding
    Network bonding combines multiple network interfaces into one logical interface.
    • Provides redundancy
    • Improves performance
  2. Why Bonding is Important
    • Failover support
    • Load balancing
    • High availability
  3. Basic Concept
    eth0 + eth1 → bond0 → single logical interface
  4. Bonding Modes
    • mode=0 → balance-rr (round-robin)
    • mode=1 → active-backup
    • mode=2 → balance-xor
    • mode=4 → 802.3ad (LACP)
  5. Mode Explanation
    • Active-backup → failover only
    • LACP → load balancing + redundancy
  6. Install Bonding Module
    modprobe bonding
  7. Create Bond Interface
    ip link add bond0 type bond
  8. Set Bond Mode
    echo active-backup > /sys/class/net/bond0/bonding/mode
  9. Add Interfaces to Bond
    ip link set eth0 master bond0
ip link set eth1 master bond0
  10. Bring Interfaces Up
    ip link set bond0 up
  11. Assign IP Address
    ip addr add 192.168.1.100/24 dev bond0
  12. Check Bond Status
    cat /proc/net/bonding/bond0
  13. Bonding with Netplan
    network:
  version: 2
  bonds:
    bond0:
      interfaces: [eth0, eth1]
      parameters:
        mode: active-backup
      dhcp4: yes
  14. LACP (802.3ad)
    Requires switch support for aggregation.
  15. Bonding vs Bridge
    Feature Bonding Bridge
    Purpose Redundancy/Performance Network connection
  16. Bonding in Virtualization
    • Host NIC redundancy
    • High availability for VMs
  17. Bonding in Cloud
    • Used in private clouds
    • Limited in public cloud
  18. Bonding in Kubernetes
    • Node-level network redundancy
  19. Failover Testing
    ip link set eth0 down
  20. Common Issues
    • Interfaces not added correctly
    • Wrong bonding mode
    • Switch not configured (LACP)
  21. Debugging
    cat /proc/net/bonding/bond0
ip link
  22. Troubleshooting Workflow
    Check bond status
Check interfaces
Test failover
Check switch config
  23. Performance Considerations
    • LACP improves throughput
    • Mode selection matters
  24. Security Considerations
    • Ensure proper switch configuration
  25. Golden Debug Rule
    If one link fails → traffic should continue
  26. Real-World Example
    • Data center servers with dual NICs
    • High-availability web servers
    • Storage network redundancy
  27. Summary
    Network bonding combines multiple interfaces to provide redundancy and improved performance, making it essential for high-availability systems.
Completion check: You should now understand how to configure and use network bonding for redundancy and performance.

Goal: Understand VLANs, how they segment networks logically, and how to configure and troubleshoot VLANs in Linux and enterprise environments.

  1. What is a VLAN
    VLAN (Virtual LAN) allows logical segmentation of a network within the same physical infrastructure.
    • Separates traffic
    • Improves security
  2. Why VLANs are Important
    • Network isolation
    • Reduced broadcast domains
    • Better performance & security
  3. Basic Concept
    Same switch → VLAN 10, VLAN 20 → isolated networks
  4. VLAN ID
    • Range: 1–4094
  5. Tagged vs Untagged
    • Tagged → VLAN ID added to frame
    • Untagged → default VLAN
  6. Access Port
    • Single VLAN
  7. Trunk Port
    • Carries multiple VLANs
  8. Install VLAN Package
    sudo apt install vlan
  9. Load VLAN Module
    modprobe 8021q
  10. Create VLAN Interface
    ip link add link eth0 name eth0.10 type vlan id 10
  11. Bring VLAN Interface Up
    ip link set eth0.10 up
  12. Assign IP Address
    ip addr add 192.168.10.1/24 dev eth0.10
  13. Check VLAN Interfaces
    ip -d link
  14. Delete VLAN
    ip link delete eth0.10
  15. VLAN with Netplan
    network:
  version: 2
  vlans:
    vlan10:
      id: 10
      link: eth0
      dhcp4: yes
  16. VLAN in Switch
    • Configure VLAN ID
    • Assign ports
  17. VLAN in Virtualization
    • Separate VM networks
  18. VLAN in Docker
    • Macvlan networks
  19. VLAN in Kubernetes
    • Used in advanced CNI setups
  20. Inter-VLAN Routing
    Requires router or Layer 3 switch.
  21. Common Issues
    • Wrong VLAN ID
    • Switch misconfiguration
    • No trunk setup
  22. Debugging VLAN
    ip link
tcpdump -i eth0
  23. Check Tagged Traffic
    tcpdump -e
  24. Troubleshooting Workflow
    Check VLAN interface
Check switch config
Check tagging
Test connectivity
  25. Security Benefits
    • Isolation between departments
    • Reduce attack surface
  26. Performance Benefits
    • Reduced broadcast traffic
  27. Golden Debug Rule
    If VLAN mismatch → no communication
  28. Real-World Example
    • Office → HR VLAN, Dev VLAN
    • Data center → tenant isolation
    • Cloud → virtual network segmentation
  29. Summary
    VLANs logically segment networks within the same physical infrastructure, providing isolation, security, and improved performance in modern networking environments.
Completion check: You should now understand how to configure and use VLANs for network segmentation.

Goal: Understand overlay networks, how they enable communication across distributed systems, and how they are used in Docker Swarm and Kubernetes.

  1. What is an Overlay Network
    An overlay network is a virtual network built on top of another network.
    • Abstracts physical network
    • Connects distributed nodes
  2. Why Overlay Networks are Needed
    • Multiple hosts need to communicate
    • Containers across nodes must connect
  3. Basic Concept
    Container A (Host1) → Overlay → Container B (Host2)
  4. Underlay vs Overlay
    • Underlay → physical network
    • Overlay → virtual network
  5. Encapsulation
    Packets are wrapped inside another packet.
  6. VXLAN (Key Technology)
    • Encapsulates Layer 2 over Layer 3
    • Uses UDP port 4789
  7. VXLAN Concept
    Original Packet → Encapsulation → Transport → Decapsulation
  8. VNI (VXLAN Network Identifier)
    • Identifies overlay network
  9. Overlay in Docker Swarm
    docker network create -d overlay mynet
  10. Attach Service to Overlay
    docker service create --network mynet nginx
  11. Overlay in Kubernetes
    • Pod-to-pod networking
    • CNI plugins (Flannel, Calico)
  12. Overlay Components
    • Tunnel endpoints
    • Encapsulation protocol
  13. Benefits
    • Scalability
    • Isolation
    • Flexibility
  14. Overlay vs Bridge
    Feature Overlay Bridge
    Scope Multi-host Single host
  15. Overlay vs VLAN
    • VLAN → Layer 2 segmentation
    • Overlay → virtual cross-host network
  16. Overlay in Cloud
    • VPC networking
    • Software-defined networking
  17. Security
    • Encrypted tunnels
    • Network isolation
  18. Common Issues
    • MTU mismatch
    • Firewall blocking UDP 4789
    • Encapsulation overhead
  19. Debug Overlay Networks
    ip link
ip route
tcpdump -i eth0 udp port 4789
  20. Check VXLAN Interface
    ip -d link show
  21. MTU Consideration
    Reduce MTU to avoid fragmentation.
  22. Performance Consideration
    • Encapsulation adds overhead
  23. DevOps Use Cases
    • Microservices communication
    • Multi-node clusters
  24. Kubernetes Deep Use Case
    • Pods communicate across nodes seamlessly
  25. Troubleshooting Workflow
    Check overlay network
Check VXLAN interface
Check firewall
Capture packets
  26. Golden Debug Rule
    If overlay fails → check underlying network first
  27. Real-World Example
    • Docker Swarm services across nodes
    • Kubernetes pod networking
    • Cloud virtual networking
  28. Summary
    Overlay networks enable seamless communication across distributed systems by abstracting the underlying physical network, forming the foundation of modern container and cloud networking.
Completion check: You should now understand overlay networks and how they work in distributed systems.

Goal: Understand advanced routing techniques like policy-based routing, multiple routing tables, and traffic control used in complex network environments.

  1. What is Advanced Routing
    Advanced routing allows controlling how traffic flows based on rules instead of just destination IP.
  2. Why Advanced Routing is Needed
    • Multiple network interfaces
    • Traffic segregation
    • Load balancing
  3. Basic Routing Limitation
    • Uses single routing table
    • Based only on destination
  4. Policy-Based Routing (PBR)
    Routing decisions based on:
    • Source IP
    • Interface
    • Mark
  5. Multiple Routing Tables
    Defined in: 
    /etc/iproute2/rt_tables
  6. Add Custom Table
    100 custom1
  7. Add Route to Table
    ip route add default via 192.168.1.1 table custom1
  8. Add Rule
    ip rule add from 192.168.1.100 table custom1
  9. View Rules
    ip rule show
  10. View All Tables
    ip route show table all
  11. Source-Based Routing
    Different source IP → different gateway.
  12. Multi-NIC Routing
    Each interface uses separate route.
  13. Load Balancing Routes
    ip route add default nexthop via 192.168.1.1 nexthop via 192.168.1.2
  14. Traffic Marking
    iptables -t mangle -A PREROUTING -j MARK --set-mark 1
  15. Route Based on Mark
    ip rule add fwmark 1 table custom1
  16. Advanced Use Cases
    • Split traffic across ISPs
    • VPN routing
  17. Routing in Cloud
    • Multiple gateways
    • Custom route tables
  18. Routing in Kubernetes
    • Pod traffic routing
    • Service routing
  19. Routing in Containers
    • Custom network routing
  20. Common Issues
    • Rule mismatch
    • Wrong table priority
  21. Debug Routing Rules
    ip rule show
ip route show table custom1
  22. Check Route Selection
    ip route get 8.8.8.8
  23. Troubleshooting Workflow
    Check rules
Check tables
Test routing path
Capture packets
  24. Performance Consideration
    • More rules → more processing
  25. Security Use Cases
    • Route sensitive traffic via secure path
  26. Golden Debug Rule
    Routing = rules + tables + priority
  27. Real-World Example
    • Multi-ISP setup
    • VPN split tunneling
    • Traffic isolation in enterprise
  28. Summary
    Advanced routing enables precise control over traffic flow using rules, multiple routing tables, and policies, making it essential for complex and large-scale network environments.
Completion check: You should now understand how to implement and troubleshoot advanced routing techniques.
