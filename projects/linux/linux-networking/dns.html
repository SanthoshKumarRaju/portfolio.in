Linux Networking - DNS

•server

Goal: Understand how DNS resolution works, how domain names are converted to IP addresses, and how to troubleshoot DNS issues in real environments.

  1. What is DNS Resolution
    DNS resolution is the process of converting a domain name into an IP address. 
    google.com → 142.250.x.x
  2. Why DNS Resolution is Important
    • Humans use names, systems use IPs
    • Essential for web, APIs, and services
  3. Step-by-Step Resolution Process
    1 → Browser request
2 → OS resolver
3 → Local cache check
4 → DNS server query
5 → Response with IP
  4. DNS Resolution Flow (Detailed)
    Client → Recursive Resolver → Root → TLD → Authoritative → IP
  5. Local DNS Cache
    OS and browser store resolved IPs to improve performance.
  6. /etc/hosts File
    Local static mapping: 
    127.0.0.1 localhost
192.168.1.10 myapp.local
  7. DNS Server Configuration
    /etc/resolv.conf
    Example: 
    nameserver 8.8.8.8
  8. nsswitch.conf Role
    Controls lookup order: 
    hosts: files dns
  9. DNS Lookup Tools
    dig google.com
nslookup google.com
host google.com
  10. Using dig
    dig google.com
    Shows detailed DNS response.
  11. Using nslookup
    nslookup google.com
  12. Using host
    host google.com
  13. DNS Record Types
    • A → IPv4
    • AAAA → IPv6
    • CNAME → Alias
    • MX → Mail
  14. TTL (Time to Live)
    Defines how long DNS results are cached.
  15. Forward Lookup
    Domain → IP
  16. Reverse Lookup
    dig -x 8.8.8.8
  17. DNS Caching Layers
    • Browser cache
    • OS cache
    • Resolver cache
  18. DNS in Containers
    • Docker provides internal DNS
    • Service names resolve automatically
  19. DNS in Kubernetes
    • CoreDNS used for service discovery
    • Pods communicate via DNS names
  20. DNS in Cloud
    • Managed DNS services
    • Internal service resolution
  21. Common DNS Issues
    • Domain not resolving
    • Wrong DNS server
    • Cache issues
  22. Debugging DNS Issues
    ping google.com
dig google.com
cat /etc/resolv.conf
  23. DNS vs Connectivity Issue
    ping 8.8.8.8 → Works
ping google.com → Fails
    This indicates DNS problem.
  24. DNS Security
    • DNS Spoofing
    • DNSSEC
  25. Real-World Example
    • User enters URL
    • DNS resolves IP
    • Browser connects to server
  26. Best Practices
    • Use reliable DNS servers
    • Monitor DNS latency
    • Clear cache when debugging
  27. Summary
    DNS resolution converts domain names into IP addresses, enabling communication across networks and forming the backbone of internet connectivity.
Completion check: You should now understand DNS resolution, lookup flow, tools, and troubleshooting techniques.

Goal: Understand how /etc/resolv.conf works, how DNS servers are configured, and how to manage and troubleshoot DNS resolution in Linux systems.

  1. What is /etc/resolv.conf
    /etc/resolv.conf is a configuration file that defines which DNS servers a system uses for domain name resolution.
  2. Why resolv.conf is Important
    • Controls DNS resolution
    • Required for internet access using domain names
    • Critical for debugging DNS issues
  3. Basic Structure
    nameserver 8.8.8.8
nameserver 1.1.1.1
  4. nameserver Directive
    Defines DNS servers used by the system.
    • Multiple entries allowed
    • Tried in order
  5. search Domain
    search example.com
    Automatically appends domain for short names.
  6. domain Directive
    domain example.com
  7. options Directive
    options timeout:2 attempts:3
    • timeout → query timeout
    • attempts → retry count
  8. How DNS Resolution Uses resolv.conf
    Application → OS resolver → resolv.conf → DNS server
  9. Viewing File
    cat /etc/resolv.conf
  10. Editing resolv.conf
    nano /etc/resolv.conf
  11. Temporary vs Persistent Changes
    • Manual edits → temporary
    • Overwritten by system services
  12. systemd-resolved
    Modern systems manage DNS dynamically. 
    /run/systemd/resolve/resolv.conf
  13. NetworkManager Interaction
    Automatically updates resolv.conf based on network settings.
  14. Netplan and resolv.conf
    DNS configured via Netplan: 
    nameservers:
  addresses: [8.8.8.8, 1.1.1.1]
  15. DNS Priority
    First nameserver is used first, then fallback.
  16. Testing DNS Configuration
    ping google.com
dig google.com
  17. Common DNS Servers
    • 8.8.8.8 → Google
    • 1.1.1.1 → Cloudflare
  18. DNS Resolution Order
    Controlled by: 
    /etc/nsswitch.conf
  19. resolv.conf in Containers
    • Auto-generated inside containers
    • Uses host DNS settings
  20. resolv.conf in Kubernetes
    • Managed by cluster DNS (CoreDNS)
    • Pods inherit DNS configuration
  21. resolv.conf in Cloud
    • Provided automatically by cloud provider
    • Uses internal DNS servers
  22. Common Issues
    • Wrong nameserver
    • File overwritten
    • No DNS response
  23. Troubleshooting Steps
    cat /etc/resolv.conf
ping 8.8.8.8
dig google.com
  24. Fixing Issues
    • Add valid nameserver
    • Restart network service
    • Check systemd-resolved
  25. Best Practices
    • Use reliable DNS servers
    • Avoid manual edits in managed systems
    • Configure via proper tools (Netplan, NM)
  26. Real-World Example
    • DNS not working → check resolv.conf
    • Update DNS → fix connectivity issue
  27. Summary
    /etc/resolv.conf defines which DNS servers are used, making it a critical component for domain resolution and network connectivity in Linux systems.
Completion check: You should now understand how resolv.conf works and how to configure and troubleshoot DNS settings.

Goal: Understand how /etc/hosts works, how to manually map hostnames to IP addresses, and how to use it for development, testing, and troubleshooting.

  1. What is /etc/hosts
    /etc/hosts is a local file used to map hostnames to IP addresses manually.
  2. Why /etc/hosts is Important
    • Override DNS resolution
    • Test applications locally
    • Useful in development and debugging
  3. Basic Structure
    127.0.0.1   localhost
192.168.1.10 myapp.local
  4. File Format
    IP_ADDRESS   HOSTNAME   ALIAS
  5. How It Works
    When resolving a hostname: 
    Check /etc/hosts → If found → use it
Else → query DNS server
  6. Priority Over DNS
    /etc/hosts is checked before DNS (based on nsswitch.conf).
  7. Viewing the File
    cat /etc/hosts
  8. Editing /etc/hosts
    sudo nano /etc/hosts
  9. Adding Entry Example
    192.168.1.100 myapi.local
  10. Testing Mapping
    ping myapi.local
  11. Use Case: Local Development
    • Map domain to localhost
    • Test applications without DNS
  12. Use Case: Domain Override
    Redirect a domain: 
    127.0.0.1 example.com
  13. Blocking Websites
    127.0.0.1 facebook.com
  14. Multiple Hostnames
    192.168.1.10 app.local api.local db.local
  15. Loopback Mapping
    127.0.0.1 localhost
  16. IPv6 Entries
    ::1 localhost
  17. nsswitch.conf Integration
    hosts: files dns
    files → /etc/hosts
  18. No Need to Restart
    Changes take effect immediately.
  19. Limitations
    • Manual updates required
    • Not scalable
    • No dynamic updates
  20. /etc/hosts in Containers
    • Auto-generated inside containers
    • Can be overridden
  21. /etc/hosts in Kubernetes
    • Managed automatically
    • Used for pod-level resolution
  22. /etc/hosts in Cloud
    • Used for internal hostname mapping
    • Often combined with DNS
  23. Common Issues
    • Wrong IP mapping
    • Conflicts with DNS
    • Forgotten entries
  24. Troubleshooting
    cat /etc/hosts
ping hostname
dig hostname
  25. Security Considerations
    • Can be used for spoofing
    • Restrict unauthorized changes
  26. Best Practices
    • Use for local testing only
    • Keep file clean
    • Document changes
  27. Real-World Example
    • Test API before DNS is ready
    • Override domain during migration
  28. Summary
    /etc/hosts provides manual hostname-to-IP mapping, enabling quick overrides and local testing without relying on DNS servers.
Completion check: You should now understand how to use /etc/hosts for manual DNS mapping and troubleshooting.

Goal: Understand how nsswitch.conf controls name resolution order, how it interacts with DNS and hosts files, and how to troubleshoot resolution issues.

  1. What is nsswitch.conf
    /etc/nsswitch.conf defines how a system resolves names (hostnames, users, groups, etc.).
  2. Why nsswitch.conf is Important
    • Controls resolution order
    • Determines where system looks first
    • Critical for DNS troubleshooting
  3. Basic Structure
    hosts: files dns
  4. Understanding "hosts" Line
    • files: /etc/hosts
    • dns: DNS servers
  5. Resolution Flow
    Request hostname
→ Check /etc/hosts
→ If not found → Query DNS
  6. Viewing File
    cat /etc/nsswitch.conf
  7. Editing File
    sudo nano /etc/nsswitch.conf
  8. Common Configurations
    hosts: files dns
hosts: dns files
  9. files vs dns Priority
    • files first → local overrides DNS
    • dns first → DNS preferred
  10. Other Services in nsswitch.conf
    • passwd → user accounts
    • group → group info
    • shadow → passwords
  11. Example Full Config
    passwd: files
group: files
shadow: files
hosts: files dns
  12. Advanced Control Options
    hosts: files [NOTFOUND=return] dns
  13. Meaning of Conditions
    • NOTFOUND → if not found
    • return → stop lookup
  14. How It Affects /etc/hosts
    If "files" is first:
    • /etc/hosts overrides DNS
  15. How It Affects DNS
    If "dns" is first:
    • DNS used before local mapping
  16. Real-World Example
    hosts: files dns
    • Check /etc/hosts first
    • Then query DNS
  17. Testing Resolution Order
    ping hostname
getent hosts hostname
  18. getent Command
    getent hosts google.com
    Uses nsswitch rules.
  19. nsswitch.conf in Containers
    • Copied from host or base image
    • Affects container DNS resolution
  20. nsswitch.conf in Kubernetes
    • Controls pod-level resolution
    • Works with CoreDNS
  21. nsswitch.conf in Cloud
    • Works with cloud DNS services
    • Controls internal name resolution
  22. Common Issues
    • Wrong resolution order
    • /etc/hosts ignored
    • DNS not used
  23. Troubleshooting
    cat /etc/nsswitch.conf
cat /etc/hosts
dig hostname
getent hosts hostname
  24. Security Considerations
    • Incorrect config may expose systems
    • Ensure proper resolution order
  25. Best Practices
    • Use "files dns" in most cases
    • Avoid unnecessary complexity
    • Test after changes
  26. Summary
    nsswitch.conf controls the order of name resolution, determining how the system looks up hostnames using files, DNS, and other services.
Completion check: You should now understand how nsswitch.conf controls name resolution and how to troubleshoot related issues.

Goal: Understand how DNS caching works using systemd-resolved and dnsmasq, and how these services improve performance and reliability.

  1. What is DNS Caching
    DNS caching stores previously resolved domain names to reduce lookup time and improve performance.
  2. Why DNS Caching is Important
    • Faster DNS resolution
    • Reduced network traffic
    • Improved performance
  3. What is systemd-resolved
    A system service that provides DNS resolution, caching, and stub resolver functionality in modern Linux systems.
  4. What is dnsmasq
    A lightweight DNS forwarder and DHCP server that provides caching and local DNS services.
  5. systemd-resolved Architecture
    Application → Stub Resolver → systemd-resolved → DNS Server
  6. dnsmasq Architecture
    Client → dnsmasq → Upstream DNS → Response → Cache
  7. systemd-resolved Stub Resolver
    127.0.0.53
    Local DNS resolver address.
  8. Checking systemd-resolved Status
    systemctl status systemd-resolved
  9. Viewing DNS Configuration
    resolvectl status
  10. Flushing DNS Cache
    resolvectl flush-caches
  11. dnsmasq Installation
    apt install dnsmasq
  12. dnsmasq Configuration File
    /etc/dnsmasq.conf
  13. Basic dnsmasq Setup
    server=8.8.8.8
cache-size=1000
  14. Starting dnsmasq
    systemctl start dnsmasq
  15. Cache Behavior
    • First request → DNS server
    • Next requests → cache
  16. TTL in Caching
    Cache entries expire based on TTL values.
  17. systemd-resolved vs dnsmasq
    Feature systemd-resolved dnsmasq
    Type System service Standalone tool
    Features DNS only DNS + DHCP
  18. Use Cases
    • Local DNS caching
    • Speed up repeated queries
    • Reduce external DNS load
  19. Use in Containers
    • Containers may use host DNS caching
    • dnsmasq used in container networking setups
  20. Use in Kubernetes
    • CoreDNS acts as DNS cache
    • Similar concept to dnsmasq
  21. Use in Cloud
    • Cloud DNS services provide caching
    • Instances may use systemd-resolved
  22. Common Issues
    • Stale DNS cache
    • Incorrect DNS server
    • Service not running
  23. Troubleshooting
    resolvectl status
systemctl status dnsmasq
dig google.com
  24. Flushing Cache (dnsmasq)
    systemctl restart dnsmasq
  25. Performance Benefits
    • Reduced DNS latency
    • Faster application response
  26. Security Considerations
    • Cache poisoning risks
    • Use trusted DNS servers
  27. Best Practices
    • Enable caching for performance
    • Monitor DNS services
    • Flush cache during debugging
  28. Real-World Example
    • Frequent API calls → cached DNS → faster response
    • DNS issue → flush cache → fix resolution
  29. Summary
    systemd-resolved and dnsmasq provide DNS caching services that improve performance, reduce latency, and enhance reliability in modern Linux systems.
Completion check: You should now understand DNS caching mechanisms and how to use systemd-resolved and dnsmasq effectively.
