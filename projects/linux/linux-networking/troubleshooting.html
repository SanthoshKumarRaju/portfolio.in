Linux Networking - Interfaces

•server

Goal: Learn how to troubleshoot network issues starting from interfaces and IP addresses, building a strong debugging workflow used in real-world systems.

  1. What is Network Troubleshooting
    Network troubleshooting is the process of identifying and fixing connectivity issues.
    • Systematic approach
    • Layer-by-layer debugging
  2. Why Start with Interfaces & IP
    • Most issues occur at this level
    • Foundation for all network communication
  3. Step 1: Check Interfaces
    ip a
    Look for:
    • Interface status (UP/DOWN)
    • Assigned IP
  4. Alternative Command
    ifconfig
  5. Check Interface State
    ip link
  6. Bring Interface Up
    ip link set eth0 up
  7. Bring Interface Down
    ip link set eth0 down
  8. Step 2: Check IP Address
    ip addr show
  9. Assign IP Manually
    ip addr add 192.168.1.100/24 dev eth0
  10. Remove IP
    ip addr del 192.168.1.100/24 dev eth0
  11. Check Routing Table
    ip route
  12. Check Default Gateway
    ip route | grep default
  13. Step 3: Test Connectivity (Local)
    ping 127.0.0.1
  14. Test Gateway
    ping 192.168.1.1
  15. Test External IP
    ping 8.8.8.8
  16. Test DNS
    ping google.com
  17. Check DNS Config
    cat /etc/resolv.conf
  18. Check Open Ports
    ss -tuln
  19. Check Network Services
    systemctl status NetworkManager
  20. Check Firewall
    iptables -L
ufw status
  21. Common Issues
    • Interface DOWN
    • No IP assigned
    • Wrong gateway
    • DNS misconfiguration
  22. Layered Troubleshooting Approach
    • Layer 1 → Interface
    • Layer 2 → IP
    • Layer 3 → Routing
    • Layer 4 → Ports
    • Layer 7 → Application
  23. Advanced Debugging Tools
    • tcpdump
    • traceroute
    • netstat
  24. Real DevOps Workflow
    ip a → check IP
ip route → check gateway
ping → test connectivity
ss -tuln → check ports
curl → test application
  25. Cloud Troubleshooting
    • Check security groups
    • Check subnet routing
  26. Container Troubleshooting
    • Check container IP
    • Check bridge network
  27. Common Real Scenarios
    • No internet → gateway/DNS issue
    • Service not reachable → firewall/port issue
    • SSH not working → port or service down
  28. Best Practices
    • Follow step-by-step debugging
    • Verify each layer
    • Use logs and tools
  29. Golden Rule
    Always start from basics: 
    Interface → IP → Route → DNS → Service
  30. Summary
    Network troubleshooting begins with checking interfaces and IP addresses, forming the foundation for diagnosing and resolving all networking issues effectively.
Completion check: You should now be able to troubleshoot basic network issues starting from interfaces and IP configurations.

Goal: Learn how routing works, how to read routing tables, and how to diagnose and fix routing issues in Linux and real-world environments.

  1. What is Routing
    Routing is the process of forwarding packets from one network to another.
    • Uses routing tables
    • Determines packet path
  2. What is a Routing Table
    A routing table is a list of routes that tells the system where to send network traffic.
  3. Why Routing Tables Matter
    • Controls packet flow
    • Critical for internet access
    • Used in servers, routers, cloud
  4. View Routing Table
    ip route
  5. Legacy Command
    route -n
  6. Sample Output
    default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0 proto kernel scope link
  7. Key Fields Explained
    • default → default route
    • via → gateway
    • dev → interface
  8. Default Gateway
    The route used when no specific route exists.
  9. Check Default Route
    ip route | grep default
  10. Add Route
    ip route add 10.0.0.0/24 via 192.168.1.1
  11. Delete Route
    ip route del 10.0.0.0/24
  12. Add Default Gateway
    ip route add default via 192.168.1.1
  13. Routing Decision Process
    • Match destination IP
    • Choose best route (longest prefix match)
  14. Longest Prefix Match
    More specific route is preferred.
  15. Check Route for Specific IP
    ip route get 8.8.8.8
  16. Common Routing Issues
    • No default route
    • Wrong gateway
    • Missing subnet route
  17. No Internet Scenario
    Check: 
    ip route
    If no default → no internet.
  18. Wrong Gateway Scenario
    Packets go to incorrect router → no response.
  19. Multiple Interfaces Issue
    Wrong interface used for routing.
  20. Advanced: Policy Routing
    ip rule show
  21. Advanced: Multiple Routing Tables
    ip route show table all
  22. Routing in Cloud
    • Route tables control subnet traffic
    • NAT gateways for private subnets
  23. Routing in Docker
    • Bridge network routing
    • Container traffic flows through host
  24. Routing in Kubernetes
    • Pod-to-pod communication
    • Overlay networking
  25. Debug Routing
    ip route
ip route get 8.8.8.8
traceroute 8.8.8.8
  26. Troubleshooting Workflow
    Check IP → ip a
Check route → ip route
Check gateway → ping gateway
Check external → ping 8.8.8.8
  27. Best Practices
    • Always verify default route
    • Use correct gateway
    • Keep routing simple
  28. Real-World Example
    • Server no internet → missing default route
    • Multi-NIC server → wrong route selected
    • Cloud VM → subnet route misconfiguration
  29. Golden Debug Rule
    If IP works but no internet → routing issue
  30. Summary
    Routing tables determine how packets travel across networks, and diagnosing routing issues is essential for resolving connectivity problems in any environment.
Completion check: You should now be able to read routing tables and diagnose routing issues effectively.

Goal: Understand how gateways enable external connectivity, how to configure them, and how to troubleshoot gateway-related issues in real-world systems.

  1. What is a Gateway
    A gateway is a network device (usually a router) that connects a local network to external networks (like the internet).
  2. Why Gateway is Important
    • Enables internet access
    • Routes traffic outside local network
  3. Default Gateway
    The default gateway is used when no specific route is found.
  4. Basic Flow
    Client → Gateway → Internet → Response
  5. Check Default Gateway
    ip route | grep default
  6. Example Output
    default via 192.168.1.1 dev eth0
  7. Test Gateway Connectivity
    ping 192.168.1.1
  8. Set Default Gateway
    ip route add default via 192.168.1.1
  9. Delete Default Gateway
    ip route del default
  10. Gateway vs Router
    • Gateway → logical concept
    • Router → physical device
  11. Gateway in Private Networks
    • Typically 192.168.x.1
    • Handles NAT and routing
  12. Gateway in Cloud
    • Internet Gateway (IGW)
    • NAT Gateway for private subnets
  13. Gateway in Containers
    • Docker bridge gateway
    • Container → host → internet
  14. Common Gateway Issues
    • No default route
    • Wrong gateway IP
    • Gateway unreachable
  15. No Internet Scenario
    If: 
    ping 8.8.8.8 → FAIL
ping gateway → FAIL
    → Gateway issue
  16. Gateway Reachable but No Internet
    • ISP issue
    • NAT misconfiguration
  17. Debug Gateway Issues
    ip route
ping gateway-ip
traceroute 8.8.8.8
  18. Check ARP Table
    ip neigh
  19. Routing + Gateway Relation
    Gateway is defined inside routing table.
  20. Firewall Impact
    • Firewall may block gateway traffic
  21. Advanced: Multiple Gateways
    • Used for failover
    • Load balancing
  22. Advanced: Policy Routing
    Different gateways for different traffic.
  23. Cloud Troubleshooting
    • Check route tables
    • Check NAT gateway
  24. DevOps Scenario
    • Server deployed but no internet
    • Check gateway → fix routing
  25. Troubleshooting Workflow
    Check IP → ip a
Check route → ip route
Ping gateway
Ping external IP
Check DNS
  26. Best Practices
    • Always verify gateway
    • Use correct subnet
    • Monitor connectivity
  27. Golden Debug Rule
    If gateway is unreachable → no internet
  28. Real-World Example
    • Cloud VM no internet → missing IGW route
    • Server misconfigured → wrong gateway
    • Docker container → bridge gateway issue
  29. Summary
    Gateway connectivity is essential for accessing external networks, and diagnosing gateway issues is a key skill for solving real-world networking problems.
Completion check: You should now be able to diagnose and fix gateway-related connectivity issues.

Goal: Learn how to verify internet connectivity by testing external IPs and differentiate between network, routing, and DNS issues.

  1. What is External IP Testing
    Testing external IPs checks whether a system can reach the internet.
    • Uses direct IP (no DNS)
    • Validates routing + gateway + NAT
  2. Why It is Important
    • Separates network issues from DNS issues
    • Quick internet connectivity check
  3. Common External IPs
    • 8.8.8.8 (Google DNS)
    • 1.1.1.1 (Cloudflare DNS)
  4. Basic Connectivity Test
    ping 8.8.8.8
  5. Interpret Results
    • Success → Internet working
    • Fail → Routing/gateway issue
  6. Test Without ICMP (Ping Blocked)
    curl http://1.1.1.1
  7. Check Public IP
    curl ifconfig.me
  8. Check Route to External IP
    ip route get 8.8.8.8
  9. Trace Path to Internet
    traceroute 8.8.8.8
  10. DNS vs Network Test
    ping 8.8.8.8   → Network
ping google.com → DNS
  11. Scenario 1: External IP Works
    DNS might be broken.
  12. Scenario 2: External IP Fails
    • Gateway issue
    • Routing problem
    • Firewall block
  13. Check Gateway
    ip route
ping gateway-ip
  14. Check Firewall
    iptables -L
ufw status
  15. Check NAT
    iptables -t nat -L
  16. Cloud Troubleshooting
    • Check security groups
    • Check route tables
    • Check NAT gateway
  17. Container Troubleshooting
    • Check container network
    • Check bridge NAT
  18. Advanced: Use nc (Netcat)
    nc -zv 8.8.8.8 53
  19. Advanced: Use telnet
    telnet 8.8.8.8 53
  20. Check DNS Resolution
    nslookup google.com
  21. Common Issues
    • No default route
    • Gateway unreachable
    • Firewall blocking outbound
  22. Real DevOps Workflow
    ping 8.8.8.8 → check internet
ping google.com → check DNS
curl → check application
  23. Golden Debug Rule
    If external IP fails → network problem
If domain fails → DNS problem
  24. Best Practices
    • Always test external IP first
    • Separate DNS vs network issues
    • Use multiple tools
  25. Real-World Example
    • Server can't reach internet → gateway missing
    • Ping works but domain fails → DNS broken
    • Cloud VM no access → security group issue
  26. Summary
    Testing external IPs is a fundamental troubleshooting step that verifies internet connectivity and helps isolate network issues from DNS problems.
Completion check: You should now be able to verify internet connectivity and diagnose network vs DNS issues effectively.

Goal: Understand how DNS works, how domain resolution happens, and how to diagnose and fix DNS-related issues in real-world environments.

  1. What is DNS
    DNS (Domain Name System) translates domain names into IP addresses.
    • example.com → 93.184.216.34
  2. Why DNS Issues Occur
    • Misconfigured DNS server
    • Network DNS unreachable
    • Cache issues
  3. DNS Resolution Flow
    Client → Resolver → Root → TLD → Authoritative → IP
  4. Basic Test (Compare)
    ping 8.8.8.8      → Network OK
ping google.com   → DNS check
  5. Check DNS Config
    cat /etc/resolv.conf
  6. Example resolv.conf
    nameserver 8.8.8.8
nameserver 1.1.1.1
  7. Test DNS Resolution
    nslookup google.com
  8. Advanced DNS Query Tool
    dig google.com
  9. Check Specific DNS Server
    dig @8.8.8.8 google.com
  10. Flush DNS Cache
    systemd-resolve --flush-caches
  11. Check systemd-resolved
    systemctl status systemd-resolved
  12. Restart DNS Service
    systemctl restart systemd-resolved
  13. Common DNS Issues
    • Wrong nameserver
    • DNS server unreachable
    • Cache corruption
  14. Scenario 1: IP Works, Domain Fails
    DNS issue confirmed.
  15. Scenario 2: nslookup Fails
    DNS server problem.
  16. Scenario 3: dig Works but ping Fails
    Possible firewall or ICMP block.
  17. Check Hosts File
    /etc/hosts
  18. Example Hosts Entry
    127.0.0.1 example.com
  19. DNS in Cloud
    • Route53 (AWS)
    • Private DNS zones
  20. DNS in Containers
    • Docker internal DNS
    • Kubernetes CoreDNS
  21. DNS in Kubernetes
    • Service discovery
    • Pod-to-pod communication
  22. Check DNS Port
    ss -tuln | grep 53
  23. Firewall Issues
    • Port 53 blocked
  24. Advanced Debugging
    tcpdump -i eth0 port 53
  25. Troubleshooting Workflow
    ping 8.8.8.8 → network
ping domain → DNS
cat resolv.conf
nslookup domain
dig domain
  26. Golden Debug Rule
    If IP works but domain fails → DNS issue
  27. Best Practices
    • Use reliable DNS (8.8.8.8, 1.1.1.1)
    • Monitor DNS latency
    • Keep backup DNS servers
  28. Real-World Example
    • App can't reach API → DNS misconfigured
    • Cloud service down → DNS propagation delay
    • Kubernetes issue → CoreDNS failure
  29. Summary
    DNS issues can break connectivity even when the network is functioning properly, making DNS troubleshooting a critical skill in real-world systems.
Completion check: You should now be able to diagnose and fix DNS-related issues effectively.

Goal: Learn how to check open ports, verify services, and troubleshoot service availability issues in Linux and real-world environments.

  1. What are Open Ports
    Open ports are network ports where services are actively listening for connections.
    • Port = communication endpoint
    • Service binds to a port
  2. Why Checking Ports is Important
    • Confirms service is running
    • Helps diagnose connectivity issues
  3. Common Ports
    • 22 → SSH
    • 80 → HTTP
    • 443 → HTTPS
    • 3306 → MySQL
  4. Check Open Ports (ss)
    ss -tuln
  5. Filter Specific Port
    ss -tuln | grep 80
  6. Show Process Using Port
    ss -tulnp
  7. Legacy Tool (netstat)
    netstat -tuln
  8. Using lsof
    lsof -i :80
  9. Test Port Locally
    nc -zv localhost 80
  10. Test Port Remotely
    nc -zv server-ip 80
  11. Using curl
    curl http://localhost
  12. Check Service Status
    systemctl status nginx
  13. Start Service
    systemctl start nginx
  14. Check Listening Address
    0.0.0.0:80 → all interfaces
127.0.0.1:80 → localhost only
  15. Common Issues
    • Service not running
    • Port not listening
    • Firewall blocking
  16. Port Open but Not Accessible
    Possible causes:
    • Firewall rules
    • Binding to localhost only
  17. Check Firewall
    ufw status
iptables -L
  18. Check SELinux (RHEL)
    getenforce
  19. Advanced: Scan Ports (nmap)
    nmap localhost
  20. DevOps Workflow
    Check service → systemctl
Check port → ss -tuln
Test → curl / nc
Check firewall
  21. Cloud Troubleshooting
    • Check security groups
    • Check load balancer
  22. Container Troubleshooting
    • Check container port mapping
    • Docker: -p 8080:80
  23. Kubernetes Troubleshooting
    • Check service port
    • Check pod listening port
  24. Debugging Workflow
    ss -tuln
lsof -i :port
systemctl status service
curl localhost
  25. Golden Debug Rule
    If port is not listening → service is not running
  26. Best Practices
    • Always verify port binding
    • Use ss over netstat
    • Monitor service logs
  27. Real-World Example
    • Website down → port 80 not listening
    • API unreachable → firewall blocking
    • SSH fail → port 22 closed
  28. Summary
    Checking open ports is a fundamental step in verifying services and diagnosing connectivity issues in Linux systems.
Completion check: You should now be able to verify open ports and troubleshoot service availability issues.

Goal: Master a structured, step-by-step troubleshooting methodology to isolate and resolve network problems efficiently in real-world environments.

  1. What is Structured Troubleshooting
    A systematic approach to diagnosing issues by checking each layer step by step.
    • Avoids guesswork
    • Speeds up debugging
  2. Why It is Important
    • Reduces downtime
    • Ensures accurate root cause analysis
    • Used in production environments
  3. Golden Rule
    Always start from basics → move to advanced
  4. Layer-Based Approach (OSI Thinking)
    • Layer 1 → Interface
    • Layer 2 → IP
    • Layer 3 → Routing
    • Layer 4 → Ports
    • Layer 7 → Application
  5. Step 1: Check Interface
    ip a
ip link
  6. Step 2: Check IP Address
    ip addr show
  7. Step 3: Check Routing
    ip route
  8. Step 4: Check Gateway
    ping gateway-ip
  9. Step 5: Test External Connectivity
    ping 8.8.8.8
  10. Step 6: Check DNS
    ping google.com
nslookup google.com
  11. Step 7: Check Ports
    ss -tuln
  12. Step 8: Check Application
    curl http://localhost
  13. Visual Debug Flow
    Interface → IP → Route → Gateway → Internet → DNS → Port → App
  14. Common Debug Patterns
    • No IP → interface/config issue
    • No route → routing issue
    • No DNS → name resolution issue
    • Port closed → service issue
  15. Scenario 1: No Internet
    Check IP → Check route → Check gateway → Check NAT
  16. Scenario 2: Service Not Reachable
    Check port → Check firewall → Check service
  17. Scenario 3: Domain Not Resolving
    Check DNS → resolv.conf → nslookup
  18. Scenario 4: Works Locally but Not Remotely
    • Firewall issue
    • Port binding issue
  19. Use of Tools
    • ip → interface & routing
    • ping → connectivity
    • ss → ports
    • curl → application
    • tcpdump → packet-level
  20. DevOps Workflow
    ip a → IP check
ip route → routing
ping → connectivity
ss → ports
curl → app
  21. Cloud Debugging
    • Check security groups
    • Check route tables
    • Check load balancer
  22. Container Debugging
    • Check container IP
    • Check port mapping
    • Check network bridge
  23. Kubernetes Debugging
    • Check pod IP
    • Check service
    • Check ingress
  24. Advanced Debugging
    • tcpdump → packet capture
    • traceroute → path analysis
  25. Common Mistakes
    • Skipping steps
    • Guessing instead of verifying
    • Ignoring logs
  26. Best Practices
    • Follow structured flow
    • Validate each layer
    • Document findings
  27. Golden Debug Workflow
    1. Interface
2. IP
3. Route
4. Gateway
5. Internet
6. DNS
7. Port
8. Application
  28. Real-World Example
    • Production outage → firewall rule blocked port
    • Cloud app down → missing route
    • API failure → DNS issue
  29. Final Insight
    Good engineers guess. Great engineers verify step by step.
  30. Summary
    A structured troubleshooting approach ensures efficient problem isolation and resolution, making it an essential skill for networking and DevOps professionals.
Completion check: You should now be able to systematically diagnose and resolve network issues using a structured approach.
