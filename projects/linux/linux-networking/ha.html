Goal: Understand how Keepalived provides high availability using Virtual IPs (VIP) and automatic failover between servers.

  1. What is Keepalived
    Keepalived is a tool that provides failover and high availability using Virtual IP addresses.
  2. Why Keepalived
    • Eliminate single point of failure
    • Ensure service availability
    • Automatic failover
  3. Basic Concept
    Client → Virtual IP → Active Server
  4. Failover Flow
    Primary Down → VIP moves → Backup becomes Active
  5. Virtual IP (VIP)
    • Shared IP between multiple servers
  6. VRRP Protocol
    • Virtual Router Redundancy Protocol
    • Used by Keepalived for failover
  7. VRRP Roles
    • MASTER → active node
    • BACKUP → standby node
  8. Heartbeat Mechanism
    MASTER → sends heartbeat → BACKUP monitors
  9. Failure Detection
    No heartbeat → BACKUP takes over VIP
  10. Priority System
    • Higher priority → becomes MASTER
  11. Preemption
    • Higher priority node can reclaim VIP
  12. Keepalived Installation
    apt install keepalived
  13. Basic Config Example
    vrrp_instance VI_1 {
  state MASTER
  interface eth0
  virtual_router_id 51
  priority 100
  advert_int 1

  virtual_ipaddress {
    192.168.1.100
  }
}
  14. Backup Config
    state BACKUP
priority 90
  15. Health Checks
    track_script {
  chk_service
}
  16. Script Example
    vrrp_script chk_service {
  script "pidof nginx"
  interval 2
}
  17. Failover with Service Check
    If service fails → VIP moves to backup
  18. Integration with Load Balancer
    Client → VIP → HAProxy/Nginx → Backend
  19. Network Requirements
    • Same subnet
    • Multicast support (or unicast config)
  20. Unicast VRRP
    Used when multicast is not available.
  21. Firewall Requirements
    • Allow VRRP protocol (IP protocol 112)
  22. Check VIP
    ip addr show
  23. Check Status
    systemctl status keepalived
  24. Logs
    journalctl -u keepalived
  25. Common Issues
    • VIP not switching
    • Firewall blocking VRRP
    • Wrong interface
  26. Troubleshooting Flow
    Check service
Check VIP
Check logs
Check network
  27. High Availability Architecture
    Client → VIP → Active Node → Backup Node (standby)
  28. Performance Impact
    • Minimal overhead
  29. Security Consideration
    • Use authentication for VRRP
  30. Real-World Use Cases
    • HA load balancers
    • Database failover
    • Web server redundancy
  31. Summary
    Keepalived provides high availability by assigning a virtual IP that automatically fails over between servers when a failure occurs.
Completion check: You should now understand how Keepalived ensures high availability using virtual IP failover.

Goal: Understand how Virtual IPs (VIPs) provide seamless service availability by allowing failover between multiple servers without client impact.

  1. What is a Virtual IP (VIP)
    A Virtual IP is an IP address not tied to a single physical server, but shared across multiple servers.
  2. Why VIP
    • High availability
    • Failover support
    • Transparent to clients
  3. Basic Concept
    Client → VIP → Active Server
  4. Failover Flow
    Primary fails → VIP moves → Backup takes over
  5. Client Perspective
    Client always connects to same IP (VIP)
  6. VIP vs Physical IP
    • Physical IP → tied to server
    • VIP → movable between servers
  7. How VIP Works
    • Assigned to active node
    • Moved during failover
  8. ARP Announcement
    New active node → broadcasts ARP → network updates mapping
  9. Protocols Used
    • VRRP (used by Keepalived)
  10. VIP with Keepalived
    Keepalived manages VIP movement between nodes
  11. Active-Passive Setup
    One active → one standby
  12. Active-Active Setup
    • Multiple nodes share load
  13. Health Checks
    If service fails → VIP reassigned
  14. VIP Configuration Example
    virtual_ipaddress {
  192.168.1.100
}
  15. Check VIP
    ip addr show
  16. Network Requirement
    • Same subnet for nodes
  17. Failover Speed
    • Usually within seconds
  18. DNS vs VIP
    • DNS → slower failover
    • VIP → instant failover
  19. Load Balancer Integration
    Client → VIP → Load Balancer → Backend Servers
  20. Cloud VIP Equivalent
    • Elastic IP (AWS)
    • Floating IP
  21. Security Consideration
    • Restrict VIP access
  22. Performance Impact
    • Minimal overhead
  23. Common Issues
    • VIP not moving
    • ARP cache delay
    • Network misconfiguration
  24. Troubleshooting Flow
    Check VIP
Check ARP
Check Keepalived
Check network
  25. Best Practices
    • Use health checks
    • Monitor failover
    • Test regularly
  26. Real-World Example
    HA web servers using VIP for zero downtime
  27. High Availability Architecture
    Client → VIP → Active Node → Backup Node
  28. Summary
    Virtual IPs enable seamless failover by allowing services to remain accessible through a constant IP address, even when underlying servers change.
Completion check: You should now understand how Virtual IPs provide seamless service availability during failures.

Goal: Understand how redundant networking ensures high availability by eliminating single points of failure in network infrastructure.

  1. What is Redundant Networking
    Redundant networking means having multiple network paths, devices, or connections to ensure continuous availability.
  2. Why Redundancy
    • Prevent downtime
    • Increase reliability
    • Ensure failover
  3. Basic Concept
    Primary Path + Backup Path → Continuous Connectivity
  4. Single Point of Failure (SPOF)
    One link failure → entire system down
  5. With Redundancy
    If primary fails → backup takes over
  6. Types of Redundancy
    • Network path redundancy
    • Device redundancy
    • Link redundancy
  7. Active-Passive
    Primary active → Backup standby
  8. Active-Active
    Both links active → load shared
  9. Failover Mechanism
    Failure detected → switch to backup path
  10. Failback
    • Return to primary after recovery
  11. Link Aggregation (Bonding)
    Multiple NICs → Single logical interface
  12. LACP (802.3ad)
    • Dynamic link aggregation protocol
  13. Multi-Homing
    • Multiple network connections to different ISPs
  14. Redundant Switches
    Server → Switch1 + Switch2
  15. Spanning Tree Protocol (STP)
    • Prevents loops in redundant networks
  16. VRRP / Keepalived
    Virtual IP failover between routers
  17. Load Balancer Integration
    Client → Load Balancer → Multiple Servers
  18. Cloud Redundancy
    • Multi-AZ deployment
    • Multi-region setup
  19. Routing Protocols
    • BGP
    • OSPF
  20. Health Checks
    Monitor links → detect failure
  21. Heartbeat Mechanism
    Nodes exchange signals to confirm availability
  22. Network Failures Covered
    • Link failure
    • Switch failure
    • ISP outage
  23. Performance Impact
    • Improved uptime
    • Better load distribution
  24. Security Consideration
    • Secure redundant paths
  25. Common Issues
    • Network loops
    • Misconfigured failover
    • Asymmetric routing
  26. Troubleshooting Flow
    Check links
Check routing
Check failover config
Check logs
  27. Best Practices
    • Eliminate SPOF
    • Use active-active where possible
    • Test failover regularly
  28. Real-World Example
    Data center with dual ISP + redundant switches + load balancers
  29. High Availability Architecture
    Client → Redundant Network → Load Balancer → Servers
  30. Summary
    Redundant networking ensures high availability by providing backup paths and eliminating single points of failure in network design.
Completion check: You should now understand how redundant networking ensures continuous availability and fault tolerance.
