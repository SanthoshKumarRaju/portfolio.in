Linux Networking Fundamentals

•server
Summary

Networking is the foundation of communication between systems, enabling data exchange through structured models like OSI and TCP/IP. It involves addressing (IPv4/IPv6), routing, and protocols such as TCP and UDP to ensure reliable or fast data transfer. Linux networking covers interface management, IP configuration, and essential tools for monitoring and troubleshooting connectivity. Core services like DNS, DHCP, and web servers support seamless communication across networks. Security mechanisms such as firewalls, NAT, and VPNs protect and control traffic flow. Advanced concepts like containers, proxies, cloud networking, and automation extend networking into scalable, modern infrastructures. Overall, it combines theory, system configuration, and practical tools to build and maintain efficient, secure networks.

Linux Networking - Basics

Goal: Understand what networking is, how systems communicate, and the core concepts behind data transmission across networks.

  1. What is Networking
    Networking is the process of connecting multiple computers or devices so they can communicate and share data.
    Examples:
    • Accessing a website
    • Sending emails
    • Connecting to servers
    Networking enables communication between systems locally and globally.
  2. Why Networking is Important
    Networking is the backbone of modern systems and applications.
    It enables:
    • Resource sharing (files, printers)
    • Remote access to systems
    • Internet communication
    • Cloud computing
    • Distributed systems (Docker, Kubernetes)
  3. Types of Networks
    Networks are categorized based on size and scope:
    • LAN (Local Area Network): Small area like home or office
    • WAN (Wide Area Network): Large scale networks like the internet
    • MAN (Metropolitan Area Network): City-level network
  4. Basic Components of Networking
    A network consists of:
    • Devices: Computers, servers, routers
    • Transmission Media: Cables or wireless
    • Protocols: Rules for communication
    • Services: Applications using the network
  5. What are Protocols
    Protocols are rules that define how data is transmitted between devices.
    Common protocols:
    • HTTP/HTTPS – Web communication
    • FTP – File transfer
    • SSH – Secure remote login
    • TCP/UDP – Transport protocols
  6. Client-Server Architecture
    Most applications follow a client-server model:
    • Client: Requests data (browser)
    • Server: Provides data (web server)
    Example: 
    Browser → Request → Server → Response
  7. Peer-to-Peer Networking
    In peer-to-peer (P2P), systems communicate directly without a central server.
    Example:
    • File sharing systems
  8. How Data Travels in a Network
    Data is broken into smaller units called packets.
    Steps:
    1 → Data created
2 → Broken into packets
3 → Routed through network
4 → Reassembled at destination
  9. What is an IP Address
    An IP address uniquely identifies a device on a network.
    Example:
    192.168.1.10
  10. What is a Port
    Ports identify services running on a system.
    Common ports:
    • 80 → HTTP
    • 443 → HTTPS
    • 22 → SSH
  11. Data Encapsulation
    As data moves through layers, each layer adds headers.
    This process is called encapsulation.
  12. Network Communication Flow
    Example of accessing a website: 
    1 → Enter URL
2 → DNS resolves domain
3 → TCP connection established
4 → HTTP request sent
5 → Server responds
  13. Wired vs Wireless Networking
    • Wired: Ethernet cables (stable, fast)
    • Wireless: Wi-Fi (flexible, convenient)
  14. Network Devices
    Important devices include:
    • Router: Connects networks
    • Switch: Connects devices in LAN
    • Modem: Connects to ISP
    • Firewall: Filters traffic
  15. Real-World Example
    When you open google.com:
    • DNS resolves domain to IP
    • Request goes through router
    • Server processes request
    • Response returns to browser
  16. Networking in DevOps
    Networking is critical for:
    • Docker container communication
    • Load balancing (Traefik)
    • Service discovery
    • Cloud deployments
  17. Common Networking Problems
    • No internet connectivity
    • DNS resolution failure
    • Incorrect IP configuration
    • Firewall blocking traffic
  18. Summary
    Networking enables systems to communicate using protocols, IP addresses, and structured data transmission. It is a foundational concept for Linux, DevOps, and cloud systems.
Completion check: You should now understand the fundamentals of networking, how systems communicate, and the key components involved.

Goal: Understand the OSI model, its 7 layers, and how data flows through each layer during network communication.

  1. What is the OSI Model
    The OSI (Open Systems Interconnection) model is a conceptual framework that standardizes how data is transmitted across a network.
    It divides networking into 7 layers to simplify understanding and troubleshooting.
  2. Why OSI Model is Important
    • Helps understand network communication step-by-step
    • Standardizes networking concepts
    • Useful for troubleshooting network issues
    • Separates responsibilities across layers
  3. 7 Layers of OSI Model
    Top → Bottom:
    7 → Application
6 → Presentation
5 → Session
4 → Transport
3 → Network
2 → Data Link
1 → Physical
  4. Layer 7: Application Layer
    Closest to the user, this layer interacts with software applications.
    Examples:
    • HTTP, HTTPS
    • FTP
    • SMTP
    Used in browsers, APIs, and user-facing applications.
  5. Layer 6: Presentation Layer
    Responsible for data formatting, encryption, and compression.
    • Converts data into readable format
    • Handles SSL/TLS encryption
  6. Layer 5: Session Layer
    Manages sessions between applications.
    • Session establishment
    • Session maintenance
    • Session termination
  7. Layer 4: Transport Layer
    Ensures reliable data delivery.
    • TCP (reliable, connection-oriented)
    • UDP (fast, connectionless)
    Handles:
    • Segmentation
    • Error checking
    • Flow control
  8. Layer 3: Network Layer
    Responsible for logical addressing and routing.
    • IP addressing
    • Packet routing
    Devices:
    • Routers
  9. Layer 2: Data Link Layer
    Handles communication within the same network.
    • MAC addresses
    • Frame creation
    • Error detection
    Devices:
    • Switches
  10. Layer 1: Physical Layer
    Deals with physical transmission of data.
    • Cables
    • Electrical signals
    • Binary transmission (0s and 1s)
  11. Data Flow in OSI Model (Encapsulation)
    Data moves from Layer 7 → Layer 1 before transmission. 
    Application → Presentation → Session → Transport → Network → Data Link → Physical
    Each layer adds its own header.
  12. Data Flow on Receiving Side (Decapsulation)
    Data moves from Layer 1 → Layer 7. 
    Physical → Data Link → Network → Transport → Session → Presentation → Application
  13. Real-World Example
    When you open a website:
    • Application: Browser sends HTTP request
    • Transport: TCP ensures delivery
    • Network: IP routes packet
    • Data Link: MAC address used
    • Physical: Data transmitted via cable/Wi-Fi
  14. OSI vs TCP/IP Model
    OSI Layer TCP/IP Equivalent
    Application, Presentation, Session Application
    Transport Transport
    Network Internet
    Data Link + Physical Network Access
  15. Common Troubleshooting Using OSI
    • Layer 1 → Cable unplugged
    • Layer 2 → MAC issues
    • Layer 3 → IP misconfiguration
    • Layer 4 → Port blocked
    • Layer 7 → Application failure
  16. Why OSI Matters in DevOps
    • Debug container networking
    • Understand load balancers
    • Troubleshoot service failures
    • Analyze traffic flow in microservices
  17. Memory Trick
    All People Seem To Need Data Processing
  18. Summary
    The OSI model divides networking into 7 layers, helping understand how data flows and where issues occur in communication.
Completion check: You should now understand all 7 OSI layers, their responsibilities, and how data flows across them.

Goal: Understand the TCP/IP model, its layers, protocols, and how real-world network communication works across systems and the internet.

  1. What is TCP/IP Model
    The TCP/IP model is the practical networking model used in real-world systems and the internet.
    It defines how data is transmitted between devices using a set of communication protocols.
  2. Why TCP/IP Model is Important
    • Used in all modern networks including the internet
    • Defines how devices communicate across networks
    • Foundation for Linux networking, cloud, and DevOps
    • Simpler and more practical than OSI model
  3. TCP/IP Layers Overview
    The TCP/IP model has 4 layers: 
    4 → Application Layer
3 → Transport Layer
2 → Internet Layer
1 → Network Access Layer
  4. Application Layer
    This layer interacts directly with user applications.
    Responsibilities:
    • Providing network services to applications
    • Data formatting and communication
    Protocols:
    • HTTP / HTTPS
    • FTP
    • SMTP
    • DNS
  5. Transport Layer
    Responsible for end-to-end communication and data delivery.
    Main protocols:
    • TCP: Reliable, connection-oriented
    • UDP: Fast, connectionless
    Functions:
    • Segmentation of data
    • Error detection
    • Flow control
    • Port-based communication
  6. Internet Layer
    Handles logical addressing and routing of packets.
    Main protocols:
    • IP (IPv4 / IPv6)
    • ICMP (for diagnostics)
    • ARP (IP to MAC mapping)
    Responsibilities:
    • Packet routing
    • Addressing
  7. Network Access Layer
    Responsible for transmitting data over physical network.
    Includes:
    • MAC addressing
    • Ethernet
    • Wi-Fi
  8. Data Flow in TCP/IP Model
    Data moves through layers before transmission: 
    Application → Transport → Internet → Network Access
  9. Encapsulation Process
    Each layer adds its own header:
    • Application → Data
    • Transport → Segment (TCP/UDP header added)
    • Internet → Packet (IP header added)
    • Network → Frame (MAC header added)
  10. Decapsulation Process
    At the receiving end, headers are removed layer by layer: 
    Frame → Packet → Segment → Data
  11. TCP vs UDP (Deep Understanding)
    Feature TCP UDP
    Connection Connection-oriented Connectionless
    Reliability Reliable Unreliable
    Speed Slower Faster
    Use Cases Web, SSH Streaming, DNS
  12. Three-Way Handshake (TCP)
    TCP establishes connection using: 
    1 → SYN (Client → Server)
2 → SYN-ACK (Server → Client)
3 → ACK (Client → Server)
  13. Real-World Example
    When you access a website:
    • Application → HTTP request
    • Transport → TCP connection established
    • Internet → IP routes packet
    • Network → Data sent via Ethernet/Wi-Fi
  14. OSI vs TCP/IP Model
    OSI TCP/IP
    7 Layers 4 Layers
    Theoretical Practical
    Detailed separation Combined layers
  15. Common Issues in TCP/IP
    • IP misconfiguration
    • Packet loss
    • Port blocking
    • DNS failures
  16. TCP/IP in Linux
    Linux heavily relies on TCP/IP stack:
    Useful commands:
    ip a
ip route
ss -tuln
ping
  17. TCP/IP in DevOps
    • Container communication (Docker)
    • Service networking (Kubernetes)
    • Load balancing (Traefik)
    • Cloud networking (VPC)
  18. Summary
    The TCP/IP model is the real-world networking model that defines how data flows across networks using layered communication and protocols like TCP and IP.
Completion check: You should now understand the TCP/IP model, its layers, protocols, and real-world applications in networking.

Goal: Understand IP addressing, differences between IPv4 and IPv6, and how addressing works in real-world networking environments.

  1. What is an IP Address
    An IP (Internet Protocol) address is a unique identifier assigned to each device on a network.
    It allows devices to locate and communicate with each other.
  2. Why IP Addressing is Important
    • Identifies devices uniquely
    • Enables communication across networks
    • Helps route data correctly
    • Foundation of internet communication
  3. What is IPv4
    IPv4 (Internet Protocol version 4) is the most widely used addressing system.
    Format:
    192.168.1.1
    It uses 32-bit addresses.
  4. IPv4 Structure
    IPv4 address is divided into 4 octets: 
    192 . 168 . 1 . 1
    Each octet ranges from 0 to 255.
  5. IPv4 Address Classes
    Class Range Usage
    A 1–126 Large networks
    B 128–191 Medium networks
    C 192–223 Small networks
  6. Private IP Ranges
    Used within internal networks: 
    10.0.0.0 – 10.255.255.255
172.16.0.0 – 172.31.255.255
192.168.0.0 – 192.168.255.255
  7. Public vs Private IP
    • Public IP: Accessible over internet
    • Private IP: Used inside local networks
  8. Limitations of IPv4
    • Limited address space (~4.3 billion)
    • Address exhaustion
    • Requires NAT
  9. What is IPv6
    IPv6 is the next-generation IP addressing system.
    Format:
    2001:0db8:85a3:0000:0000:8a2e:0370:7334
    Uses 128-bit addresses.
  10. IPv6 Structure
    • 8 groups of hexadecimal numbers
    • Each group is 16 bits
  11. IPv6 Shortening Rules
    • Leading zeros can be removed
    • Consecutive zeros replaced with ::
    Example:
    2001:db8::1
  12. Advantages of IPv6
    • Huge address space
    • No need for NAT
    • Built-in security (IPsec)
    • Better routing efficiency
  13. Types of IPv6 Addresses
    • Unicast: One-to-one
    • Multicast: One-to-many
    • Anycast: One-to-nearest
  14. IPv4 vs IPv6 Comparison
    Feature IPv4 IPv6
    Address Size 32-bit 128-bit
    Format Decimal Hexadecimal
    NAT Required Not required
    Security Optional Built-in
  15. Subnetting Basics
    Subnetting divides a network into smaller networks.
    Example:
    192.168.1.0/24
  16. CIDR Notation
    CIDR represents network and host portions: 
    /24 → 255.255.255.0
  17. Loopback Address
    • IPv4: 127.0.0.1
    • IPv6: ::1
  18. Checking IP in Linux
    ip a
hostname -I
  19. Real-World Example
    When accessing a website:
    • Domain → DNS resolves to IP
    • IP used to reach server
    • Response sent back to client IP
  20. IP Addressing in DevOps
    • Container IP allocation
    • Service networking
    • Cloud IP management
    • Load balancer configurations
  21. Common Issues
    • IP conflicts
    • Incorrect subnet
    • Wrong gateway
    • DNS mismatch
  22. Summary
    IPv4 and IPv6 are essential for identifying devices in a network, with IPv6 solving scalability and efficiency limitations of IPv4.
Completion check: You should now understand IPv4 and IPv6 addressing, structure, differences, and real-world usage.

Goal: Understand the difference between public and private IP addresses, how they are used, and how NAT enables communication between internal and external networks.

  1. What is an IP Address
    An IP address is a unique identifier assigned to a device in a network. It allows devices to send and receive data.
  2. What is a Public IP Address
    A public IP is an address that is globally unique and reachable over the internet.
    It is assigned by an ISP (Internet Service Provider).
  3. Characteristics of Public IP
    • Globally unique
    • Accessible over the internet
    • Assigned by ISP
    • Used by servers and routers
  4. Examples of Public IP
    8.8.8.8
1.1.1.1
  5. What is a Private IP Address
    A private IP is used within internal networks and is not accessible directly from the internet.
  6. Private IP Ranges
    10.0.0.0 – 10.255.255.255
172.16.0.0 – 172.31.255.255
192.168.0.0 – 192.168.255.255
  7. Characteristics of Private IP
    • Not globally unique
    • Used inside LAN (Local Area Network)
    • Reusable across networks
    • Not directly accessible from internet
  8. Real-World Example
    • Your laptop → 192.168.1.10 (private IP)
    • Your router → Public IP from ISP
  9. Why Private IPs Exist
    • IPv4 address shortage
    • Improved security
    • Efficient internal communication
  10. What is NAT (Network Address Translation)
    NAT allows private IP devices to communicate with the internet using a public IP.
  11. How NAT Works
    1 → Device (192.168.1.10) sends request
2 → Router replaces private IP with public IP
3 → Internet responds to public IP
4 → Router maps response back to private IP
  12. Types of NAT
    • SNAT (Source NAT)
    • DNAT (Destination NAT)
    • PAT (Port Address Translation)
  13. Public vs Private IP Comparison
    Feature Public IP Private IP
    Accessibility Internet Local network
    Uniqueness Global Local
    Assigned by ISP Router/Admin
  14. Checking IP Addresses in Linux
    Private IP:
    ip a
    Public IP:
    curl ifconfig.me
  15. Port Forwarding
    Port forwarding maps a public IP request to a private IP service.
    Example:
    PublicIP:80 → 192.168.1.10:80
  16. Security Considerations
    • Private IPs are safer by default
    • Public IP exposes services
    • Firewalls are required for protection
  17. Use in Cloud & DevOps
    • Public IP for external access
    • Private IP for internal communication
    • Load balancers expose public endpoints
    • Containers use private networking
  18. Common Issues
    • Port not accessible (NAT issue)
    • Wrong IP configuration
    • Firewall blocking traffic
  19. Summary
    Public IPs are used for internet communication, while private IPs are used inside internal networks. NAT bridges the gap between them.
Completion check: You should now understand public and private IPs, NAT, and how internal systems communicate with the internet.

Goal: Understand subnetting and CIDR, how networks are divided, and how to calculate subnets for real-world networking and DevOps use cases.

  1. What is Subnetting
    Subnetting is the process of dividing a large network into smaller networks called subnets.
    This improves network organization, performance, and security.
  2. Why Subnetting is Needed
    • Efficient IP address usage
    • Improved network performance
    • Better security and isolation
    • Easier management of large networks
  3. Basic Network Structure
    An IP address has two parts:
    • Network portion
    • Host portion
  4. What is a Subnet Mask
    A subnet mask defines which part of the IP is network and which is host.
    Example:
    IP Address:   192.168.1.10
Subnet Mask:  255.255.255.0
  5. Default Subnet Masks
    Class Subnet Mask
    A 255.0.0.0
    B 255.255.0.0
    C 255.255.255.0
  6. What is CIDR
    CIDR (Classless Inter-Domain Routing) is a modern way to represent IP ranges.
    Format:
    192.168.1.0/24
    /24 means first 24 bits are network portion.
  7. CIDR to Subnet Mask Mapping
    CIDR Subnet Mask
    /8 255.0.0.0
    /16 255.255.0.0
    /24 255.255.255.0
  8. Number of Hosts Calculation
    Formula: 
    2^(32 - CIDR) - 2
    Example:
    /24 → 2^(32-24) = 256 → 254 usable hosts
  9. Subnetting Example
    Given: 
    192.168.1.0/24
    Divide into 2 subnets: 
    Subnet 1 → 192.168.1.0/25
Subnet 2 → 192.168.1.128/25
  10. Network Address & Broadcast Address
    • Network Address: First IP in subnet
    • Broadcast Address: Last IP in subnet
  11. Usable IP Range
    Example:
    Network:   192.168.1.0
Usable:    192.168.1.1 → 192.168.1.254
Broadcast: 192.168.1.255
  12. Subnetting Steps (Easy Method)
    1 → Identify required subnets
2 → Convert CIDR
3 → Calculate block size
4 → Divide IP ranges
5 → Assign hosts
  13. Binary Understanding (Advanced)
    IP addresses are binary: 
    192 = 11000000
    Subnetting works by borrowing bits from host portion.
  14. VLSM (Variable Length Subnet Mask)
    VLSM allows creating subnets of different sizes.
    Useful for efficient IP allocation.
  15. Real-World Example
    Office network:
    • HR → 192.168.1.0/26
    • IT → 192.168.1.64/26
    • Sales → 192.168.1.128/26
  16. Subnetting in Cloud
    • AWS VPC uses CIDR blocks
    • Subnets divide public and private networks
    • Routing tables control traffic
  17. Subnetting in DevOps
    • Container networking (Docker, Kubernetes)
    • Service isolation
    • Microservices architecture
  18. Common Mistakes
    • Overlapping subnets
    • Wrong CIDR calculation
    • Ignoring broadcast address
  19. Checking Network in Linux
    ip a
ip route
  20. Summary
    Subnetting and CIDR divide networks into smaller segments for efficient management, better performance, and scalable network design.
Completion check: You should now understand subnetting, CIDR, IP calculations, and real-world usage in networking and cloud systems.

Goal: Understand MAC addresses, how devices communicate at Layer 2, and how ARP maps IP addresses to MAC addresses in real networks.

  1. What is a MAC Address
    A MAC (Media Access Control) address is a unique hardware identifier assigned to a network interface card (NIC).
    It is used for communication within a local network.
  2. MAC Address Format
    A MAC address is a 48-bit hexadecimal value: 
    00:1A:2B:3C:4D:5E
    It consists of 6 pairs of hexadecimal numbers.
  3. Structure of MAC Address
    • First 3 bytes: Manufacturer (OUI)
    • Last 3 bytes: Unique device identifier
  4. Why MAC Address is Important
    • Identifies devices in a local network
    • Used by switches for forwarding frames
    • Ensures data reaches correct device
  5. Layer of Operation
    MAC addresses operate at: 
    OSI Layer 2 (Data Link Layer)
  6. What is ARP
    ARP (Address Resolution Protocol) maps an IP address to a MAC address.
    It allows devices to find the physical address of another device in the same network.
  7. Why ARP is Needed
    • IP works at Layer 3
    • MAC works at Layer 2
    • ARP connects these two layers
  8. How ARP Works (Step-by-Step)
    1 → Device A wants to send data to 192.168.1.10
2 → It checks ARP cache
3 → If not found, sends ARP Request (broadcast)
4 → "Who has 192.168.1.10?"
5 → Device B replies with its MAC address
6 → Mapping stored in ARP cache
7 → Communication begins
  9. ARP Request & Reply
    • ARP Request: Broadcast to all devices
    • ARP Reply: Sent directly to requester
  10. ARP Table (Cache)
    Devices store IP-to-MAC mappings temporarily.
    View in Linux:
    arp -a
    or 
    ip neigh
  11. Types of ARP
    • Static ARP: Manually configured
    • Dynamic ARP: Automatically learned
  12. Gratuitous ARP
    A device sends ARP request for its own IP.
    Used for:
    • Detecting IP conflicts
    • Updating ARP tables
  13. Proxy ARP
    A router responds to ARP requests on behalf of another device.
  14. Real-World Example
    • Laptop wants to access server in LAN
    • Uses ARP to find MAC
    • Switch forwards data using MAC address
  15. Switching & MAC Address Table
    Switches maintain MAC tables:
    • Maps MAC → Port
    • Forwards frames efficiently
  16. MAC Address in Linux
    ip link
ifconfig
  17. MAC Address Spoofing
    Changing MAC address manually.
    Used for:
    • Testing
    • Privacy
  18. ARP Spoofing (Security Risk)
    Attack where fake ARP messages are sent.
    Results:
    • Man-in-the-middle attacks
    • Traffic interception
  19. Security Measures
    • Static ARP entries
    • Dynamic ARP inspection
    • Network segmentation
  20. MAC vs IP Address
    Feature MAC Address IP Address
    Layer Layer 2 Layer 3
    Type Hardware Logical
    Scope Local network Global network
  21. Role in DevOps & Containers
    • Container networking uses virtual MACs
    • Overlay networks abstract MAC layer
    • Important for debugging network issues
  22. Common Issues
    • ARP cache issues
    • Duplicate IP conflicts
    • Network unreachable errors
  23. Summary
    MAC addresses uniquely identify devices at Layer 2, while ARP maps IP addresses to MAC addresses, enabling communication within local networks.
Completion check: You should now understand MAC addressing, ARP workflow, and how devices communicate within a local network.

Goal: Understand TCP and UDP protocols, how they work, their differences, and when to use each in real-world networking and DevOps scenarios.

  1. What is Transport Layer
    The Transport Layer is responsible for end-to-end communication between devices.
    It ensures data is delivered correctly between applications.
  2. What is TCP
    TCP (Transmission Control Protocol) is a connection-oriented protocol that ensures reliable data delivery.
  3. Key Features of TCP
    • Connection-oriented
    • Reliable delivery
    • Error checking
    • Flow control
    • Ordered data transmission
  4. TCP Connection (Three-Way Handshake)
    Before data transfer, TCP establishes a connection: 
    1 → SYN (Client → Server)
2 → SYN-ACK (Server → Client)
3 → ACK (Client → Server)
  5. Data Transfer in TCP
    • Data is divided into segments
    • Each segment has sequence numbers
    • Acknowledgments confirm delivery
  6. Error Handling in TCP
    If a packet is lost:
    • Receiver detects missing sequence
    • Sender retransmits packet
  7. TCP Connection Termination
    1 → FIN
2 → ACK
3 → FIN
4 → ACK
  8. What is UDP
    UDP (User Datagram Protocol) is a connectionless protocol that sends data without establishing a connection.
  9. Key Features of UDP
    • Connectionless
    • Faster transmission
    • No reliability guarantee
    • No ordering of packets
  10. How UDP Works
    1 → Sender sends data
2 → Receiver may or may not receive
3 → No acknowledgment or retransmission
  11. TCP vs UDP Comparison
    Feature TCP UDP
    Connection Connection-oriented Connectionless
    Reliability Reliable Unreliable
    Speed Slower Faster
    Ordering Maintained Not maintained
  12. Common Use Cases of TCP
    • Web browsing (HTTP/HTTPS)
    • SSH connections
    • File transfers (FTP)
    • Database connections
  13. Common Use Cases of UDP
    • Video streaming
    • Online gaming
    • DNS queries
    • VoIP calls
  14. Ports and Protocols
    Both TCP and UDP use ports:
    • TCP 80 → HTTP
    • TCP 443 → HTTPS
    • UDP 53 → DNS
  15. Real-World Example
    • Opening a website → TCP ensures full page loads correctly
    • Watching a live stream → UDP prioritizes speed over perfection
  16. TCP Congestion Control (Advanced)
    TCP adjusts speed based on network conditions:
    • Slow start
    • Congestion avoidance
  17. UDP Limitations
    • No error recovery
    • No retransmission
    • Possible data loss
  18. Checking Connections in Linux
    ss -tuln
netstat -tuln
  19. TCP/UDP in DevOps
    • Microservices communication
    • Load balancer configuration
    • Container networking
    • Service ports management
  20. Common Issues
    • Port blocked
    • Connection timeout
    • Packet loss
  21. Summary
    TCP provides reliable, ordered communication, while UDP offers fast, connectionless transmission. Choosing between them depends on application requirements.
Completion check: You should now understand TCP and UDP, their differences, working mechanisms, and real-world applications.

Goal: Understand how ports work, how services use ports, and how to manage and troubleshoot ports in Linux systems and DevOps environments.

  1. What is a Port
    A port is a logical communication endpoint used by applications to send and receive data.
    It allows multiple services to run on the same IP address.
  2. Why Ports are Needed
    • Identify specific services on a system
    • Enable multiple applications to use network simultaneously
    • Help route traffic to correct process
  3. IP Address vs Port
    • IP Address: Identifies the device
    • Port: Identifies the service on that device
    Example:
    192.168.1.10:80
  4. Port Range
    Ports range from: 
    0 → 65535
  5. Types of Ports
    Type Range Usage
    Well-known 0–1023 System services
    Registered 1024–49151 User applications
    Dynamic 49152–65535 Temporary use
  6. Common Ports and Services
    Port Protocol Service
    22 TCP SSH
    80 TCP HTTP
    443 TCP HTTPS
    53 UDP DNS
    3306 TCP MySQL
  7. How Ports Work
    Client → IP + Port → Server
    Example: 
    Browser → 192.168.1.10:80
  8. Listening vs Established Ports
    • Listening: Service waiting for connection
    • Established: Active communication
  9. Sockets

    IP Address + Port + Protocol
  10. Checking Open Ports in Linux

  12. Binding Services to Ports

    • Nginx → Port 80

  13. Port Conflicts

  14. Opening and Closing Ports

  15. Port Forwarding

Goal: Understand how DNS works, how domain names are resolved into IP addresses, and how to troubleshoot DNS in real-world environments.

  1. What is DNS
    DNS (Domain Name System) translates human-readable domain names into IP addresses.
    Example:
    google.com → 142.250.183.14
  2. Why DNS is Needed
    • Humans remember names, not IPs
    • Enables easy access to websites
    • Abstracts infrastructure complexity
  3. DNS Hierarchy
    DNS follows a hierarchical structure: 
    Root → TLD → Domain → Subdomain
    • Root (.)
    • TLD (.com, .org)
    • Domain (google.com)
  4. Types of DNS Servers
    • Root Server
    • TLD Server
    • Authoritative Server
    • Recursive Resolver
  5. How DNS Resolution Works
    1 → User enters domain (google.com)
2 → Request goes to local resolver
3 → Resolver queries root server
4 → Root points to TLD server
5 → TLD points to authoritative server
6 → Authoritative server returns IP
7 → Browser connects to IP
  6. Recursive vs Iterative Query
    • Recursive: Server resolves fully
    • Iterative: Server returns next step
  7. DNS Record Types
    Record Purpose
    A Domain → IPv4
    AAAA Domain → IPv6
    CNAME Alias
    MX Mail server
    NS Name server
  8. DNS Caching
    DNS results are cached to improve performance.
    • Browser cache
    • OS cache
    • Resolver cache
  9. TTL (Time to Live)
    Defines how long DNS records are cached.
  10. DNS in Linux
    Configuration file:
    /etc/resolv.conf
    Example:
    nameserver 8.8.8.8
nameserver 1.1.1.1
  11. /etc/hosts File
    Used for local DNS overrides: 
    127.0.0.1 localhost
192.168.1.10 myapp.local
  12. DNS Troubleshooting Tools
    dig google.com
nslookup google.com
host google.com
  13. Reverse DNS Lookup
    Converts IP back to domain name: 
    dig -x 8.8.8.8
  14. DNS Resolution Order
    Controlled by: 
    /etc/nsswitch.conf
  15. DNS in Containers
    • Docker provides internal DNS
    • Containers communicate via service names
  16. DNS in Cloud
    • Route53 (AWS)
    • Cloud DNS (GCP)
    • Internal DNS for services
  17. Common DNS Issues
    • DNS not resolving
    • Wrong DNS server
    • Cache issues
    • Propagation delay
  18. DNS Propagation
    Changes in DNS take time to update globally.
  19. DNS Security
    • DNS Spoofing
    • DNSSEC
    • Secure resolvers
  20. Real-World Example
    • User enters website
    • DNS resolves domain
    • Browser connects to server IP
  21. DNS in DevOps
    • Service discovery
    • Load balancing
    • Microservices communication
  22. Summary
    DNS translates domain names into IP addresses and plays a critical role in enabling communication across networks and the internet.
Completion check: You should now understand DNS resolution, record types, configuration, and troubleshooting techniques.

Goal: Understand how DHCP automatically assigns IP addresses, how it works internally, and how to configure and troubleshoot DHCP in real environments.

  1. What is DHCP
    DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses and network configuration to devices in a network.
    It removes the need for manual IP configuration.
  2. Why DHCP is Needed
    • Automates IP address assignment
    • Prevents IP conflicts
    • Simplifies network management
    • Scales easily in large environments
  3. Manual vs Automatic IP Assignment
    Type Description
    Static IP Manually configured
    Dynamic IP Assigned by DHCP
  4. DHCP Components
    • DHCP Server: Assigns IP addresses
    • DHCP Client: Requests IP
    • IP Pool: Range of available IPs
  5. DHCP Process (DORA)
    DHCP follows a 4-step process: 
    1 → Discover (Client → Broadcast)
2 → Offer (Server → Client)
3 → Request (Client → Server)
4 → Acknowledge (Server → Client)
  6. DHCP Discover
    Client broadcasts request:
    "I need an IP address"
  7. DHCP Offer
    Server responds with:
    • Available IP
    • Subnet mask
    • Gateway
    • DNS
  8. DHCP Request
    Client selects one offer and requests that IP.
  9. DHCP Acknowledge
    Server confirms and assigns IP to client.
  10. Lease Time
    DHCP assigns IP for a limited duration.
    After expiry, client must renew.
  11. Lease Renewal
    50% → Renewal request sent
87.5% → Rebinding attempt
  12. DHCP Options
    DHCP also provides:
    • Default gateway
    • DNS servers
    • Domain name
  13. DHCP Server Configuration (Linux)
    Install: 
    apt install isc-dhcp-server
    Config file: 
    /etc/dhcp/dhcpd.conf
  14. Example DHCP Configuration
    subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.100 192.168.1.200;
  option routers 192.168.1.1;
  option domain-name-servers 8.8.8.8;
}
  15. Checking DHCP in Linux
    ip a
dhclient
journalctl -u isc-dhcp-server
  16. DHCP vs Static IP
    • DHCP → Dynamic, automatic
    • Static → Fixed, manual
  17. DHCP in Home Network
    Router acts as DHCP server assigning IPs to devices.
  18. DHCP in Cloud
    • Cloud assigns private IP automatically
    • Elastic IP used for public access
  19. DHCP in Containers
    • Docker assigns IP internally
    • Kubernetes uses CNI for IP management
  20. DHCP Relay
    Allows DHCP across different networks using routers.
  21. Common Issues
    • No IP assigned
    • IP conflicts
    • DHCP server down
  22. Security Concerns
    • Rogue DHCP servers
    • IP spoofing
  23. Real-World Example
    • You connect to Wi-Fi
    • Router assigns IP automatically
    • Device connects to internet
  24. Summary
    DHCP automates IP address assignment, simplifies network management, and is essential for scalable networking environments.
Completion check: You should now understand DHCP workflow, configuration, and its role in networking systems.
