Goal: Understand how MTU defines the maximum packet size for transmission and its impact on performance, fragmentation, and networking.

  1. What is MTU
    MTU (Maximum Transmission Unit) is the maximum size of a packet that can be transmitted over a network.
  2. Why MTU Matters
    • Affects performance
    • Prevents fragmentation
    • Optimizes throughput
  3. Basic Concept
    Packet Size ≤ MTU → Sent directly
Packet Size > MTU → Fragmented
  4. Standard MTU Values
    • Ethernet → 1500 bytes
    • Loopback → 65536 bytes
    • VPN/Tunnel → lower than 1500
  5. Packet Structure
    [Headers] + [Payload] = Total Packet Size
  6. Fragmentation
    Large Packet → Split → Multiple Smaller Packets
  7. Fragmentation Issues
    • Increased latency
    • Packet loss risk
    • Performance degradation
  8. Path MTU Discovery (PMTUD)
    Determines the smallest MTU along the path.
  9. PMTUD Flow
    Send packet → Too large → ICMP error → Adjust MTU
  10. Don't Fragment (DF) Flag
    Prevents fragmentation; packet dropped if too large.
  11. MTU in Tunnels
    • GRE, VPN add extra headers
    • Reduces effective MTU
  12. Example
    1500 (Ethernet) - 50 (Tunnel Overhead) = 1450 MTU
  13. MTU vs MSS
    • MTU → full packet size
    • MSS → TCP payload size
  14. MSS Calculation
    MSS = MTU - 40 (IP + TCP headers)
  15. Jumbo Frames
    • MTU > 1500 (e.g., 9000 bytes)
  16. Benefits of Jumbo Frames
    • Higher throughput
    • Lower CPU usage
  17. Limitations of Jumbo Frames
    • Not supported everywhere
  18. Check MTU
    ip link show
  19. Set MTU
    ip link set dev eth0 mtu 1400
  20. Test MTU (Ping)
    ping -M do -s 1472 google.com
  21. MTU Issues
    • Websites not loading
    • Connection drops
    • Slow performance
  22. Black Hole MTU
    Packets dropped silently due to incorrect MTU.
  23. Troubleshooting Flow
    Check MTU
Test with ping
Adjust MTU
Verify connectivity
  24. MTU in Docker
    docker network inspect
  25. MTU in Kubernetes
    • Overlay networks reduce MTU
  26. Performance Impact
    • Optimal MTU → best performance
  27. Security Consideration
    • Fragmentation can be exploited
  28. Best Practices
    • Avoid fragmentation
    • Use consistent MTU
    • Adjust for tunnels
  29. Real-World Example
    VPN users facing slow internet due to MTU mismatch
  30. Summary
    MTU defines the maximum packet size and plays a critical role in performance, fragmentation, and network efficiency.
Completion check: You should now understand how MTU impacts packet transmission and network performance.

Goal: Understand how TCP tuning improves network performance by adjusting kernel parameters related to buffering, connections, and congestion control.

  1. What is TCP Tuning
    TCP tuning involves adjusting Linux kernel parameters to optimize network performance and resource usage.
  2. Why TCP Tuning
    • Improve throughput
    • Reduce latency
    • Handle high traffic
  3. Basic Concept
    Client ↔ TCP Stack ↔ Kernel Parameters ↔ Network
  4. Key Areas of Tuning
    • Buffer sizes
    • Connection limits
    • Congestion control
  5. TCP Buffer Sizes
    net.core.rmem_max
net.core.wmem_max
  6. TCP Window Size
    Controls how much data can be sent before acknowledgment.
  7. Window Scaling
    net.ipv4.tcp_window_scaling = 1
  8. Receive & Send Buffers
    net.ipv4.tcp_rmem
net.ipv4.tcp_wmem
  9. Connection Backlog
    net.core.somaxconn
net.ipv4.tcp_max_syn_backlog
  10. SYN Flood Protection
    net.ipv4.tcp_syncookies = 1
  11. TIME_WAIT Optimization
    net.ipv4.tcp_tw_reuse = 1
  12. Keepalive Settings
    net.ipv4.tcp_keepalive_time = 600
  13. Congestion Control Algorithms
    • cubic (default)
    • bbr (modern, high performance)
  14. Enable BBR
    net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
  15. File Descriptor Limits
    ulimit -n 100000
  16. Ephemeral Ports Range
    net.ipv4.ip_local_port_range = 1024 65535
  17. TCP Fast Open
    net.ipv4.tcp_fastopen = 3
  18. Retransmission Settings
    net.ipv4.tcp_retries2
  19. Apply Settings
    sysctl -p
  20. Check Current Values
    sysctl -a | grep tcp
  21. High Traffic Optimization
    • Increase buffers
    • Increase backlog
  22. Low Latency Optimization
    • Use BBR
    • Tune keepalive
  23. Docker Consideration
    • Uses host kernel TCP settings
  24. Kubernetes Consideration
    • Node-level tuning required
  25. Performance Impact
    • Better throughput
    • Reduced packet loss
  26. Common Issues
    • Too small buffers
    • Connection drops
    • High latency
  27. Troubleshooting Flow
    Check sysctl values
Monitor traffic
Adjust parameters
Test performance
  28. Monitoring Tools
    ss -s
netstat -s
  29. Security Consideration
    • Prevent SYN floods
  30. Best Practices
    • Test before applying
    • Tune based on workload
  31. Real-World Example
    High-traffic web server optimized using BBR and increased buffers
  32. Summary
    TCP tuning optimizes kernel parameters to improve throughput, reduce latency, and handle high network loads efficiently.
Completion check: You should now understand how TCP tuning improves network performance using kernel-level optimizations.

Goal: Understand how connection limits control the number of concurrent connections to ensure performance, stability, and security.

  1. What are Connection Limits
    Connection limits define the maximum number of simultaneous connections a system can handle.
  2. Why Connection Limits
    • Prevent overload
    • Ensure stability
    • Improve performance
  3. Basic Concept
    Clients → Server (Limited connections allowed)
  4. Without Limits
    Too many connections → Server crash / slowdown
  5. With Limits
    Max connections → Controlled traffic → Stable system
  6. Types of Limits
    • System-level limits
    • Application-level limits
    • Network-level limits
  7. File Descriptor Limits
    ulimit -n
    Each connection uses a file descriptor.
  8. Increase FD Limit
    ulimit -n 100000
  9. Kernel Limits
    fs.file-max
  10. Backlog Queue
    net.core.somaxconn
net.ipv4.tcp_max_syn_backlog
  11. TCP States
    • ESTABLISHED
    • TIME_WAIT
    • CLOSE_WAIT
  12. TIME_WAIT Issue
    Too many connections stuck in TIME_WAIT.
  13. Optimize TIME_WAIT
    net.ipv4.tcp_tw_reuse = 1
  14. Application-Level Limits (Nginx)
    worker_connections 1024;
  15. HAProxy Limits
    maxconn 5000
  16. Database Limits
    max_connections = 200
  17. Rate Limiting vs Connection Limits
    • Connection limit → total connections
    • Rate limit → requests per time
  18. Load Balancer Role
    Distributes connections across multiple servers.
  19. Connection Pooling
    Reuse existing connections instead of creating new ones
  20. Keep-Alive Connections
    • Reduce connection overhead
  21. Ephemeral Ports
    net.ipv4.ip_local_port_range
  22. Port Exhaustion
    Too many outgoing connections → no ports available.
  23. Monitoring Connections
    ss -s
netstat -an | wc -l
  24. Docker Consideration
    Containers share host limits.
  25. Kubernetes Consideration
    Node-level limits apply to pods.
  26. Performance Impact
    • Proper limits → stable performance
  27. Security Benefits
    • Prevents connection flooding
    • Mitigates DDoS
  28. Common Issues
    • Too many open files
    • Connection refused
    • Timeout errors
  29. Troubleshooting Flow
    Check FD limits
Check connections
Check logs
Adjust limits
  30. Best Practices
    • Set realistic limits
    • Use load balancing
    • Monitor usage
  31. Real-World Example
    High-traffic API server tuned with increased FD and connection limits
  32. Summary
    Connection limits control concurrent connections to maintain system stability, performance, and security.
Completion check: You should now understand how connection limits manage concurrency and protect system resources.

Goal: Understand how Linux kernel parameters can be tuned to improve networking performance, scalability, and reliability.

  1. What are Kernel Parameters
    Kernel parameters control how the Linux kernel handles networking, memory, and system behavior.
  2. Why Tune Kernel Parameters
    • Improve performance
    • Handle high traffic
    • Optimize resource usage
  3. sysctl Tool
    sysctl -a
    Used to view and modify kernel parameters.
  4. Temporary Change
    sysctl -w net.ipv4.ip_forward=1
  5. Permanent Change
    /etc/sysctl.conf
  6. Apply Changes
    sysctl -p
  7. Categories of Parameters
    • Network (net.*)
    • File system (fs.*)
    • Kernel (kernel.*)
  8. IP Forwarding
    net.ipv4.ip_forward = 1
    Enables routing between networks.
  9. TCP Buffer Sizes
    net.core.rmem_max
net.core.wmem_max
  10. TCP Window Scaling
    net.ipv4.tcp_window_scaling = 1
  11. Connection Backlog
    net.core.somaxconn
net.ipv4.tcp_max_syn_backlog
  12. SYN Flood Protection
    net.ipv4.tcp_syncookies = 1
  13. TIME_WAIT Optimization
    net.ipv4.tcp_tw_reuse = 1
  14. Ephemeral Port Range
    net.ipv4.ip_local_port_range = 1024 65535
  15. File Descriptor Limits
    fs.file-max
  16. Network Queue Length
    net.core.netdev_max_backlog
  17. Congestion Control
    net.ipv4.tcp_congestion_control = bbr
  18. Queue Discipline
    net.core.default_qdisc = fq
  19. ICMP Settings
    net.ipv4.icmp_echo_ignore_broadcasts = 1
  20. Reverse Path Filtering
    net.ipv4.conf.all.rp_filter = 1
  21. Docker Consideration
    • Containers use host kernel settings
  22. Kubernetes Consideration
    • Node-level tuning required
  23. Performance Optimization
    • Increase buffers
    • Enable BBR
    • Adjust backlog
  24. Security Optimization
    • Enable SYN cookies
    • Disable ICMP redirects
  25. Monitoring
    ss -s
netstat -s
  26. Common Issues
    • Wrong values causing instability
    • Performance degradation
  27. Troubleshooting Flow
    Check current values
Modify gradually
Test performance
Monitor system
  28. Best Practices
    • Test before production
    • Document changes
    • Use workload-based tuning
  29. Real-World Example
    High-traffic server optimized using increased buffers and BBR congestion control
  30. Summary
    Kernel parameters allow fine-grained control over networking behavior, enabling optimized performance, scalability, and security.
Completion check: You should now understand how kernel parameters can be tuned for better networking performance.
